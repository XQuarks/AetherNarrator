## 一、现状与设计定位（接入分析结论摘要）

现有"地点"三件套（剧情代码只依赖它们）：
1. `S.gameState.current_location`（字符串）：AI 每轮 `state_changes.current_location` 自由改（game.js:796-803），旧地点自动入 revealed_locations；
2. `S.gameState.revealed_locations`（数组）：引擎记账 + 兜底"前往Y"选项（game.js:1148-1154）；
3. 知识库 `category="地点"` 条目：`inferTriggerFromContent`（prompt.js:890-899）把地点类 lore 标题当地点名单做事件匹配。

→ 新增 `world.locations` 地点图是**可选旁路数据**：只做参考/展示/增强，旧世界无此字段零行为变化、零迁移；不强制 AI 在图中移动（保持自由玩法）。

---

## 二、数据模型

```jsonc
// world.locations（可选顶层字段）
[
  {
    "id": "cafe",                 // ≤50 字符
    "name": "咖啡馆",              // ≤100 字符，必填；与 lore 地点类条目/current_location 尽量同名
    "summary": "白发马尾的镜子小姐经营的老式咖啡馆。",   // ≤500 字符
    "connections": ["集市", "码头后巷"],   // 可达邻居"地点名"数组，≤12 个，去重、不含自身
    "hidden": false,              // 是否隐藏地点（地图默认不展示、不给 AI 提示可达性）
    "npcs_default": ["镜子"]       // 常驻 NPC（可选，≤8 个）
  }
]
```

**为什么不存连接 id 而存名称**：现有机制（current_location / revealed_locations / 事件地点匹配）全部以"地点名"为键，存名称与之一致，AI 生成/编辑更自然。

## 四、兼容与安全

- 旧世界/旧档无 `locations` → sanitize 不产该字段；`buildCompactGameState` 无图时不输出 `connections_from_current`（undefined 键被 JSON.stringify 省略）；地图 tab 显示空态；行为与现在完全一致。
- AI 生成世界不产 locations → 正常（可选字段）。
- 不强制移动规则：AI 仍可自由改 current_location，地点图仅作参考提示。
