# docs/58 · 创建新世界界面合并与「去类型」方案（已落地整理版）

> 状态：**已实施并验证（2026-08-04）**
> 范围：创建向导「基本信息 + 世界观」两模块合并为一屏；移除世界类型概念（角标/编辑弹窗/自动判定）；主角设定改为「叙事视角」显式选项（支持群像剧）
> 关联：docs/52（W2 向导）、docs/34（竞品借鉴）、docs/56（lore 门禁）
> 附注：黎总要求「IP 合规扫描」更名「IP 世界观约束」——`src/modules.js` 模块名已改、创建向导不再暴露该开关（由是否填「参考作品」自动判定）。

---

## 1. 背景与目标

黎总反馈创建新世界流程字段冗余、逻辑割裂（2026-08-04），归纳为 5 点改造目标：

1. 「基本信息」与「世界观」两个 tab 内容分散 → **合并为一屏**
2. 创建界面去掉「世界书（知识库）」提示框（生成后详情页入口保留）
3. 去掉「世界类型」下拉（5 档来源类型概念整体移除，黎总拍板「完全去掉」）
4. 「主角设定」输入框移除，改为「叙事视角」显式选项，支持**无主角群像剧**
5. 界面字段重组为：世界名称 / 参考的世界 / 小说原文本上传 / 世界观知识与描述（上传或填写）/ 关键偏离 / 叙事视角 / 剧情自由度

> 本方案已全部落地，并经 594 项测试 + 浏览器可视化核验通过（见 §7）。

## 4. 移除世界类型（D1）的连锁处理

### 4.1 删除清单（函数 / 元素）
- `src/render.js`：`WORLD_TYPE_META`、`WORLD_TYPE_DEFAULT`、`worldTypeLabel/BadgeClass/Detail`、`needsSourceWork`、`editWorldType`、`onEditWorldTypeChange`、`saveWorldTypeEdit`；世界列表/详情的 `wc-badge-*` 角标渲染逻辑；`resetCreateWorldForm` 中类型相关重置
- `src/app.js`：import 与 action map 删除 `onWorldTypeChange / editWorldType / onEditWorldTypeChange / saveWorldTypeEdit`
- `index.html`：`worldTypeEditModal` 弹窗及其入口按钮；创建向导 `#worldType` 下拉、`#ipNameField` 显隐联动、`#ipNameReqTag` 必填标签；独立的「世界观」导航项与 section
- `src/game.js`：类型收集、类型相关校验、`world.type` 写入、debugLog 的 worldType 字段
- `src/utils.js`：`analyzeWorldTags` / `pickWorldTags` 的 `type` 参数（函数体内未使用，仅签名清理）

### 4.2 修改点（去 type 后行为收敛）
- `src/store.js::ensureWorldCanon`：`mode` 兜底 `(world.ip_name || world.type === "ip")` → `world.ip_name`
- `src/store.js::resolveCanonContext({ ipName, desc, sourceFileContent })`（去 type 参数）：
  - `mode = userIp ? "ip_adaptation" : "original"`
  - **行为收敛**：不再从描述文本自动检测补 `ip_name`（原 `type==="ip" && detected.length===1` 分支删除）；`detected` 仅用于冲突提示
- `src/prompt.js::buildWorldGenerationPrompt(name, desc, hero, ipName, sourceContent, styleRef, customStyle, plotFreedom, worldPrefix, pov, ...)`：
  - 签名**移除 `type`**、**新增 `pov`**（位置 10）
  - `ipNameSection`：`(type === "ip" && ipName)` → `ipName` 非空即注入（顺带修复 fan 不注入的既有遗漏）
  - 「类型」行：改为按 `ipName` 动态描述（「基于参考作品/小说」/「原创世界观」）
  - 游玩禁律「本世界为「original」背景」→ 用世界名称（顺手修枚举码显示瑕疵）
- `src/prompt.js::buildHeroContext()`：新增群像剧分支——`isEnsemble = S.currentWorld.pov === "ensemble"` 时以「参与者」视角推进，无固定单一主人公
- `src/llm.js::mockGenerateWorld` / `callWorldGenerationLLM`：`type` 参数保留兼容（调用处传 `null`），函数体不用 type
- `src/modules.js`：**模块名「IP 合规扫描」→「IP 世界观约束」**（`ip_scan` id 不变），`defaultEnabled` 为函数：世界填了 `ip_name` → 默认开，纯原创未填 → 默认关；创建向导不暴露该开关（`wizard-editor.js` 遇 `ip_scan` 直接 `return`）

### 4.3 兼容性
- 旧世界 `world.type` 字段保留在数据中，**只读不参与逻辑**；角标不再显示
- `world.canon.mode` 对旧世界：有 `ip_name` 的自然保持 ip_adaptation；仅靠 type==="ip" 维持的旧世界 → 读档时 `ensureWorldCanon` 兜底后 mode 变 original（可接受，参考作品未填说明无明确来源）
- 测试同步：`test/29-canon-resolver.test.js` 用例「type=ip 从文本自动填名」删除，改为验证「未填参考的世界不自动认定」

## 5. 叙事视角 / 群像剧（D2）

- 新字段 `world.pov`：`"solo"`（默认）| `"ensemble"`
- **solo（单人主角）**：玩家不再手填主角设定；`generateWorld` 调用 AI 设计主角（身份/背景/能力，≤200 字），回填 `world.hero`（游玩注入链路原样保留）；旧世界有 `world.hero` 照常展示
- **ensemble（群像剧）**：`world.hero` 保持空；prompt 改为「设计戏份均衡的多角色群像，玩家以参与者视角推进」；`buildHeroContext` 不注入单一「你…」开场；玩家身份回退「玩家/参与者」（`save.js` 已有 hero ? "主角" : "玩家" 兜底）
- 完成度清单（`src/utils.js::computeWorldCompletion` 的 hero 维度）：改为可选（hint「主角设定（可选，群像剧可留空）」），未填不扣分
