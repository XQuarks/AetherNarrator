# docs/54 · 规则可视化与结局系统增强方案

> 状态：方案待黎总确认（2026-07-31）
> 目标：把已有的「多类型规则 DSL」从纯表单卡片，升级为**可视化、可追踪、有分类**的规则系统。
> 范围：三件套 —— ① 作者端规则分组+如果→就卡片 ② 游玩时结局追踪器 ③ 结局分类+图鉴。

---

## 0. 现状盘点（重要：能力其实已具备）

经代码核查，规则系统**不是"只有违禁物品"**，引擎、编辑器、游戏结束流程都已支持多类型：

- **`then`（动作）已支持 3 种**：`ban`（禁止概念/禁项）、`tag`（设置标签=限制/解锁）、`ending`（触发结局）
- **`when`（触发）已支持 4 种**：`always`（始终）、`concept`（文本出现某词）、`state`（状态数值比较，如 `金币 < 0`）、`tag`（标签活跃）
- **结局已接到游戏结束**：`src/game.js:1244-1257` 每回合跑 `evaluateRules`，命中 `ending` 即 `showGameOver(reason)`
- **编辑器已暴露全部类型**：`src/lore-editors.js` 的"就"下拉有「禁止概念/设置标签/触发结局」
- **测试已覆盖**：`test/worldview-dsl.test.js` 覆盖 ending/state/tag/概念触发

**真正的缺口（本方案要补的）**：
1. 编辑时规则是一长条混排表单卡片，作者易以为"规则=禁项"（观感问题）。
2. 游玩时玩家看不到"离某个结局还差什么"（无可视化进度）。
3. 结局只有一句 `reason` 文字，无「好/坏/真/隐藏」身份，也无可重复的"结局图鉴"。

> 附带清理项：世界对象上的旧字段 `game_over_conditions`（如 `is_alive === false`）**不被引擎求值、只是历史文案**（见架构文档 Phase2 决策）。本方案不依赖它；建议后续统一走规则 DSL，不在本方案范围内删除（避免动旧存档）。

## 1. 数据模型变更（最小、向后兼容）

### 1.1 `ending` 规则增加两个可选字段
```js
// 现有
{ id, name, enabled, when:{type:"state", field:"gold", op:"<", value:0},
  then:{ type:"ending", reason:"你破产了" } }
// 改为（新增 title / kind，旧规则缺省不报错）
then:{
  type:"ending",
  title:"破产结局",          // 可选：结局标题；缺省回退到 rule.name 或 "结局"
  kind:"bad",                // 枚举见下；缺省 "normal"
  reason:"你欠下巨债，故事在此终结。" // 结束弹窗的详细说明
}
```

- `kind` 枚举：`normal`(普通) | `good`(好/通关) | `bad`(坏) | `true`(真结局) | `secret`(隐藏)
- 旧档无 `title/kind` → 渲染时 `title = name || "结局"`，`kind = "normal"`，**零破坏**。

### 1.2 结局图鉴（游玩时，存于当前存档）
```js
// S.gameState.unlockedEndings: [{ ruleId, title, kind, reason, at }]
// 每次触发 ending 且未记录过该 ruleId 时追加；随存档保存（storage.js 已整体持久化 gameState）
```

## 2. 模块① 作者端规则可视化（`src/lore-editors.js` + `styles.css`）

**改动点**（不改数据结构，只改渲染与少量交互）：
- `renderRuleEditorBody()` 在规则列表上方加**分类标签栏**：`结局(N) / 限制·禁项(N) / 标签(N)`，按 `then.type` 统计。
  - 切换标签 → 过滤显示对应类型规则（草稿 `S._ruleEdit` 不变，仅视图过滤）。
  - "＋ 添加规则" 始终可用；新增规则默认取当前所在标签对应的 `then.type`（`ending`/`ban`/`tag`），减少作者误选。
- 每条 `rule-card` 头部加**类型色点**（金=结局 / 红=禁项 / 蓝=标签），并把现有 `ruleSummary()`（"如果…→就…"）放大为卡片主展示，弱化纯表单感。
- `then.type==="ending"` 的子表单增加 `title`（结局标题）与 `kind`（下拉：普通/好/坏/真/隐藏）两个输入；`syncRuleEditFromDOM` / `selectRuleType` / `saveRuleReview` 同步与校验。
- 空状态提示文案更新，强调"规则不止禁项"。

**不新增文件**，纯渲染+字段扩展。

## 3. 模块② 游玩时结局追踪器（`src/render.js` + `src/game.js` + `index.html` + `styles.css`）

**新增侧边栏面板「结局追踪器」**，每回合刷新：
- 数据来源：在 `src/worldview.js` 新增纯函数
  `evaluateEndingStatus(world, gs)` → `[{ ruleId, name, title, kind, when, met, progress }]`
  - `met`：`evalWhen(when, ctx)` 结果（复用现有 `evalWhen`/`compareState`，需 `export`）。
  - `progress`（仅 `when.type==="state"` 且数值比较时）：计算 `当前值` 距 `阈值` 的比例，0~1；`concept`/`tag`/`always` 无进度，仅显示 满足/未满足。
- 渲染（`render.js`）：每张卡片 = 类型色条 + kind 徽标 + 标题 + 触发条件摘要 + 状态药丸（已满足/进行中/未满足）+（数值类）进度条。
- 刷新时机：`game.js` `processTurn` 末尾（已有 `evaluateRules` 调用处）顺带算 `evaluateEndingStatus` 并 `renderEndingTracker()`；开关由世界是否含 `ending` 规则决定（无则隐藏面板，零噪音）。
- **兼容**：无 `ending` 规则的世界不显示面板；旧 ending 规则 `kind` 缺省 `normal` 正常显示。

## 4. 模块③ 结局分类 + 图鉴（`src/render.js` + `src/game.js`）

### 4.1 结束弹窗升级（`showGameOver`）
- 入参由 `showGameOver(reason)` 扩展为 `showGameOver({ title, kind, reason })`。
- `game.js` 调用处改为传 `evaluated.endings[0]` 的 `title/kind/reason`（旧调用点逐一更新）。
- 弹窗显示：kind 徽标（好/坏/真/隐藏 配色）+ 标题 + 说明；并提示"已解锁结局图鉴 +1"。

### 4.2 结局图鉴
- 触发结局时，`game.js` 向 `S.gameState.unlockedEndings` 追加（去重 ruleId）。
- 在世界详情「规则」页签（或游戏结束弹窗内）加「结局图鉴」区：列出本档已解锁的结局（标题+kind+说明），未解锁的同类世界结局显示「？？？」（保留悬念，仅显示 kind 占位）。
- 旧存档无该字段 → `storage.js`/`store.js` 归一化时补 `unlockedEndings:[]`。

## 7. 风险与取舍

- **低风险**：纯渲染+字段扩展，引擎求值逻辑（`evaluateRules`）不动，旧档零破坏。
- **追踪器进度**只对「数值状态」类条件有意义；文本/标签类条件只能显示布尔满足态——这是合理的，不强行造进度。
- **不做**：不引入新 `when`/`then` 类型（保持 DSL 稳定）；不删除旧 `game_over_conditions` 字段（留待单独清理）；不把限制类再细分为"门槛/冷却"等子类型（现有 `when:state`+`then:ban/tag` 已能表达，先做可视化呈现）。

## 8. 落地顺序（建议）

1. 数据层：`worldview.js` 导出 + `evaluateEndingStatus`；`kind` 解析。

3. 游玩层：模块② 追踪器面板 + 模块③ 弹窗升级 + 图鉴。
4. 测试 + 全量验证。
