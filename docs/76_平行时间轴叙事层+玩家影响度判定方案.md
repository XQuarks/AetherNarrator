# docs/76 · 平行时间轴叙事层 + 玩家影响度判定

> 定位：在既有「时间/分支层并行」（`multiverse` 双界、`triggers.js` 的 S4 时间穿越分支、`timeline-log.js` 的章节回溯分叉）之上，补两块**叙事本体**层面的能力——
> ① **平行时间轴叙事层**：同一主角同时存在于多条「叙事现实」，每条有独立 `story_progress` / `lore` 作用域 / 状态副本，玩家激活一条游玩，跨层抉择经「影响度」投射改写他层基准；
> ② **玩家影响度判定**：确定性累加器，从每回合 `state_changes` 增量加权算出「玩家把世界推离原轨多远」，既驱动状态栏展示，又作为「偏离度越线 → 自动 fork 新叙事层」的蝴蝶效应开关。
> 状态：**✅ 已实现（2026-08-08，Phase A→D 全链路落地，全量 871 测试通过）**。
> 已拍板默认值（2026-08-08）：`max_layers = 4`（主线+3 衍生）/ 每层**全量 deepClone** / **采纳推荐权重表** / 偏离度**单档 `[100]` 自动 fork。

- **叙事层** ≈ 把 `multiverse`/`createBranch` 的「并行 + 独立触发 + 状态副本」范式下沉到**同一世界内的叙事现实**层，复用 `switchTimeline`/`createBranch`/`deepClone`；

## 1. 设计目标与红线

**目标**：让「玩家的每个重大抉择」可被**确定性度量**（影响度），并在偏离足够大时**可视化地分叉出平行叙事层**（蝴蝶效应），且「旧层的抉择」能**投影改写**新层基准——叙事从单线变成「一棵可被玩家亲手掰开的树」。

**红线（与项目价值观一致）**：
1. **引擎管状态、LLM 管叙事**：AI 不直接写 `narrative_layers` 结构；影响度由引擎从**确定性** `state_changes` 增量算出；叙事层 fork/切换由确定性动作或回合结算阈值触发，**不信任 AI 自报**。
2. **复用优先**：状态副本用 `deepClone`；切换仿 `switchTimeline`；每层事件隔离仿 `createBranch`；影响度门控复用 `evalEventConditions`；通知范式照搬 skill-growth banner。**不新写条件基础设施**。
3. **默认关闭**：新增模块 `parallel_narrative`（伞形，管「影响度 + 叙事层」两套能力），`defaultEnabled:false`；不开则完全无副作用、不改变既有 `story_progress` 语义。
4. **不喧宾夺主**：日常小抉择静默累计；仅在「跨档（偏离度越线）」或「手动切换层」时给非阻塞提示；旧档无相关字段不报错。

## 2. 数据模型

### 2.1 世界配置（静态预设，创作者填；全可选，缺省用代码默认）
```js
world.parallel_narrative = {
  max_layers: 4,            // 主线(main) + 最多 3 条衍生叙事层
  // 偏离度（玩家影响度）达到档位 → 自动 fork 一条新叙事层；空数组=不自动派生
  influence_thresholds: [100],
  weights: {                // 各增量维度的默认权重（推荐值，world 可覆盖）
    attr_per_point: 0.5,    // 属性绝对值变化每点
    affinity_per_point: 1,  // 好感 delta 每点
    event_triggered: 10,    // 触发一个预设事件
    quest_completed: 15,    // 完成一个任务
    lore_unlocked: 8,       // 解锁一条 lore
    rel_upgrade: 12,        // 一次关系升阶
    ending_reached: 40,     // 触达一个结局
    random_event: 5         // 触发一次随机事件
  }
}
```

### 2.2 运行时状态（引擎维护，确定性）
- `s.narrative_layers`：字典，key=层 id（`main` 为初始层）。**独立新字段，不复用 `s.timelines`**（避免与 `multiverse` 的「不同世界」语义冲突，降低回归风险）。每层：
  ```js
  {
    id: "main",
    label: "主线",
    story_progress: 1,          // ★ 从全局下沉为「每层独立指针」
    lore_scope: [],             // 本层可见 lore 的 id 集合（缺省=全部可见）
    state_clone: <deepClone>,   // 本层完整状态副本（切换即激活此副本）
    active: true
  }
  ```
- `s.active_narrative_layer`：当前激活层 id（默认 `"main"`，镜像 `active_timeline`）。
- `s.player_influence`：累计偏离度（number，确定性累加，不依赖 AI）。
- `s.influence_baseline`：当前层的**初始状态 deepClone**（层创建时快照），`computeInfluence` 与之比对。
- `s.pendingInfluenceEvents = []`：跨档/分叉事件 `{type:"influence_tier"|"layer_fork", ...}`（镜像 `pendingGrowthEvents`，回溯自然清空）。

### 2.3 向后兼容
- 老存档无 `narrative_layers` → 视为单线（`main` 层，`story_progress` 沿用全局值）；世界无 `parallel_narrative` → 用代码默认 `DEFAULT_*`。
- `story_progress` 全局字段**保留作为兼容回退**：模块关闭时一切照旧；模块开启后，各层改用 `narrative_layers[id].story_progress`，全局字段仅作为 `main` 层的镜像写入（防其他代码读取空值）。

## 8. 风险与权衡

- **与 `multiverse` 语义重叠**：刻意用**独立字段 `narrative_layers`**（不复用 `s.timelines`），把「同一世界内的叙事现实分叉」与「不同世界的双界」分开，降回归风险。
- **`story_progress` 下沉的连锁**：知识库注入（`prompt.js:978`）、RAG（`rag.js:320/392`）、`store.js:857` 等读 `s.story_progress` 处需改读「当前激活层的 `story_progress`」。统一封装 `getActiveStoryProgress(gs)` 收口，避免散改。
- **baseline 存哪**：用 `s.influence_baseline`（层创建时 inline deepClone）而非依赖 `timeline-log.js` 的异步 IndexedDB 快照，保证 `computeInfluence` 同步、可单测、无 IO 依赖。
- **自动 fork 的频率**：`influence_thresholds` 默认单档 `[100]`，且受 `max_layers` 封顶；越线后该档位「已消费」（记录 `last_fork_influence`）避免每回合重复派生。
- **回溯（docs/69）**：`pendingInfluenceEvents` 是运行时队列，回溯重算自然清空；`narrative_layers` 本身随存档快照恢复。
- **AI 不体现层结构**：靠 `promptFragment` 要求叙事贴合「已知世界线变动」；层结构已写入状态，下轮 prompt 自然带出，AI 无从伪造层切换。

## 9. 待用户拍板的默认值（已确认 ✅ 2026-08-08）

1. **叙事层默认规模**：✅ `max_layers = 4`（主线 + 最多 3 条衍生线）。默认只开主线、影响度越线才派生。
2. **每层状态副本范围**：✅ **全量 `deepClone`**（像章节回溯快照，简单可靠，不漏边角）。
3. **影响度权重表**：✅ **采纳推荐权重**（属性0.5 / 好感1 / 事件10 / 任务15 / lore8 / 关系升阶12 / 结局40 / 随机事件5）。
4. **偏离度阈值**：✅ **单档 `[100]`** —— `player_influence ≥ 100` 即自动 `forkNarrativeLayer`（受 `max_layers` 封顶，越线档位消费一次防重复派生）。
