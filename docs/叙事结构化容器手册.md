# 叙事结构化容器手册

> 本手册是 AetherNarrator「**叙事结构化容器**」的唯一年威参考，整合自：`30_B1人物卡方案`、`31_B2玩家变量方案`、`32_B3背包物品方案`、`33_B4羁绊好感度方案`、`B6记忆晋升方案`、`知识晋升确认开关`。原始方案已移入 `docs/_archive/叙事容器/` 留底。
>
> **适用读者**：创作文字游戏的作者。这里的「容器」指一组**字段固定、可编辑、每轮强制注入 AI** 的结构，目的是让 AI 不再从散文中「回忆」角色/物品/关系，提升叙事一致性。

---

## 1. 总原则（四个容器共通）

- **结构是容器，不是替代**：每个容器都保留「自由文本备注」字段，AI 仍有发挥空间，避免「填表式」叙事。
- **开箱即用、不强制**：容器都是可选的；没配时世界照常运行（注入段为空就不输出）。
- **主角身份恒定**：玩家始终扮演主角，不可被替换（与身份锚点一致）。
- **注入走缓存友好静态段**：容器定义（schema）放进 system 静态段，命中前缀缓存；运行时值走每轮动态段，不破缓存。
- **旧世界零破坏**：未配容器的世界相关数据为空，注入自动跳过；读档有兜底回填。

> 四大容器（B1~B4）均已落地，全量测试通过。

---

## 2. B1 人物卡（主角 + NPC）

让「主角 + NPC」从散落 lore 的自由文本，变成**固定字段、可编辑、每轮注入**的卡。

**数据模型** `world.characters[]`，每张卡字段：
`role`(主角/NPC)、`name`、`identity`(身份)、`gender_age`、`appearance`、`personality`、`motivation`、`relationship`(NPC 与主角关系标签)、`attitude`(NPC 态度)、`current_state`、`voice`(声音标签)、`untouchable`(**不可触碰设定/红线**，AI 不得违背)、`notes`(自由备注)。

**作者怎么用**：
- 世界详情页有「角色」页签 → 「编辑角色」弹窗，列表式增删改。
- 右上「🤖 AI 生成」可依据世界描述自动产出 3–6 张角色卡（无 API/失败时安全跳过）。
- 保存时自动重建 system 提示缓存。

**AI 怎么用**：`buildCharactersContext` 把非空字段格式化进 system 静态段（主角排前、NPC 在后），AI 不再从文本里猜角色。

## 3. B2 玩家变量（数值 / 文本 / 开关）

把「状态压力」变成创作者可配的变量（理智、污染、声望…），不喧宾夺主。

**数据模型**：
- 世界级定义 `world.variable_schema[]`：每项 `{ id, name, type:"number"|"text"|"toggle", default, min?, max?, unit?, desc?, enabled }`。**默认空数组**——绝大多数世界无任何数字压力。
- 运行时值 `S.gameState.variables`，开局/读档由 `syncVariablesToSchema` 按 schema 初始化并修剪（新增补默认、已删清除）。

**作者怎么用**：世界详情「变量」页签编辑 schema（如克苏鲁配「理智 80/知识污染 5」）。编辑保存即时生效。
**玩家怎么看**：状态面板「变量」页签（数值带进度条）；每条日志下方的「本回合变化」面板显示 `理智 80 → 75（-5）`。
**AI 怎么用**：schema 非空时注入 system 静态段，指令 AI 在 `state_changes.variables` 返回**变化后的完整值**（不是增量）；`applyStateChanges` 做夹取/类型转换/忽略非法。

> 完全复用现有 `state_changes` 通道，老存档零破坏。

---

## 4. B3 背包 / 物品（分类 + 关键标记 + 驱动选项）

让物品成为**可反复触发的叙事道具**，而非背景摆设。背包底层早已能跑，B3 补三件事：分类、关键高亮、驱动「使用 X」选项。

**数据模型** `S.gameState.inventory[]`（运行时）+ `world.initial_state.inventory[]`（创作者配的初始物品）：每件 `{ item_id, name, count, world?, category, is_key, tags }`。
- `category` 枚举：`武器/装备/消耗品/线索/书籍/货币/其他`。
- `is_key`：独立布尔，与分类解耦——关键物品**金色高亮 + 置顶**，获得时进手记强调（importance 高）。

**作者怎么用**：世界详情「物品」页签 + 弹窗，配初始物品（名称/数量/分类/关键/解锁标签）。保存只改世界定义，不影响当前存档。
**AI 怎么用**：每轮可见背包；system 静态段加轻量指令「优先给『使用 X / 检查 X / 交给 X』选项，让物品反复触发剧情」。AI 授予物品时鼓励返回 `category`/`is_key`。

> B3 不做独立「世界物品图鉴」——物品主要靠 AI 在剧情中动态授予，创作者只配开局带什么。

## 5. B4 羁绊 / 好感度（数值关系层叠加在文字关系层之上）

给 NPC 关系加**数值好感度 + 关系标签**，让玩家在状态面板看到关系进度条，AI 据此生成更贴关系的选项。

**数据模型** `S.gameState.bonds[npcId]`：`affinity`(-100~100)、`label`(盟友/宿敌/合作者…)、`trend` 等。它**叠加**在 B1 的 `relationship` 文字标签层之上，不替换、不破坏你原来写的人物关系文字。

**作者怎么用**：
- 人物卡编辑器可手动填**初始好感 / 标签**（世界详情「角色」页签）。
- 状态面板「关系」页签展示进度条 + 标签。
**AI 怎么用**：好感度驱动选项生成——高好感能解锁「倾诉/委托」，宿敌能「对峙/回避」。

### ⚠️ 老档兼容决策（已拍板 2026-07-29）
**老存档 / 老世界维持不兼容现状（读档只兜底、不回填老档）**。原因：你打算重新生成世界，旧档兼容没意义。因此：
- **新世界**：人物卡编辑器可填初始好感，关系页签有数值条。
- **老存档**：关系页签只有 B1 文字层、没有数值条。
> 这与 B3「不考虑旧存档兼容」取向一致。A 全量功能（编辑器+数值+选项驱动+展示+测试）已做齐，仅旧档兼容走了「不兼容」分支。

## 6. B5/B6 记忆晋升（行为记忆 → 长期知识库）

B5（已落地）：每 20 轮 AI 审查知识库，把最近行为记录当「最近事实」软上下文，并可在确认台把 AI 建议**应用**为正式知识库条目（玩家确认才生效，绝不静默写）。

B6（已落地，2026-07-20）：补「硬晋升机制」——把高价值记忆**自动作为晋升候选**交给 AI：
- 候选阈值：`importance >= 4` 或 `pinned === true`（常量在 `src/promotion.js`，可调）。
- 原记忆**保留并标记 `promoted=true`**（不删，可追溯、防重复建议）。
- 完全复用 B5 确认台，不新建 UI。

**知识晋升确认开关**（已落地，2026-07-20）：游戏内 ⚙ → 选项面板有复选框「**知识库修订需我手动确认**」：
- **默认关闭** = AI 回写自动同意，只弹小提示「知识库已更新 ✅」，不打断。
- **开启** = 弹轻量确认窗（应用/忽略），玩家有完全否决权。
- 持久化到 `localStorage`，下次记住。

> 红线：晋升/回写**绝不静默无提示**；开启模式玩家可「忽略」拒绝写入。
