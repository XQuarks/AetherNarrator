## 1. 设计目标与红线约束

**目标**：让世界里的技能随剧情"被成功运用"而自然成长，升星时给玩家一个**确定性、不依赖 AI 临场发挥**的剧情通知。

**红线（与项目价值观一致，落地硬约束）**：
1. **引擎管状态、LLM 管叙事**（老范式）：AI 不直接改 `stars`，只通过结构化 `state_changes` 信封上报"本次运用结果"，引擎确定性累加并判定升星。
2. **三层防泄漏复用**：引擎渲染 banner/状态栏（P0）、`sanitizeLLMText` 净化（P1）、结构化信封（P2），不退回"AI 自己写数据"。
3. **默认关闭**：`skills` 模块 `defaultEnabled:false`，创作者想用才开。
4. **不喧宾夺主**：
   - `successCount` 是引擎**隐藏数**，界面不摆进度条；
   - 日常成功**静默累加**，只有"跨阈值升星"那一刻才有通知；
   - 升星是**叙事节拍**而非属性面板堆砌。

## 2. 数据模型

### 2.1 世界配置（静态预设，创作者填）
沿用既有 `world.initial_state.skills`（docs/60 玩家预设技能容器），新增可选成长参：
```js
world.initial_state.skills = {
  "火焰咒":   { desc: "基础攻击法术", thresholds: [3, 8, 15], maxStars: 3 },
  "魔药调制": { desc: "熬制药剂",                              }  // 缺省用全局默认
}
```
- `thresholds`：升星所需累计成功次数（逐技能覆盖）；缺省回退全局 `[3, 8, 15]`。
- `maxStars`：星级上限，缺省 `3`（与 docs/70 约定一致）。

### 2.2 运行时状态（引擎维护，确定性）
`defaultInitialState.skills` 从 `{}` 改为**对象结构**（初始化时由预设归一）：
```js
S.gameState.skills = {
  "火焰咒": { stars: 0, successCount: 0, thresholds: [3,8,15], maxStars: 3, lastNotifiedRound: null }
}
```
- `successCount`：引擎从信封 `result:"success"` 累加的**隐藏数**。
- `stars`：由 `successCount >= thresholds[stars]` 确定性重算，**不信任 AI 声明的 stars**。

### 2.3 向后兼容
旧档 `skills:{}` 或 `skills:{name:"描述字符串"}` 形式，初始化时统一归一为 2.2 的对象结构（`ensureGameState`/`normalizeSkills`）。缺省 `thresholds`/`maxStars` 补全局默认。

## 3. "成功"怎么定义（混合策略，确定性优先）

**信封上报约定**（`state_changes.skills[name]`）：
```js
state_changes.skills = {
  "火焰咒": { delta: +1, result: "success" }   // delta 可选（熟练度增减），result 必填
}
```
`result` 取值：`"success"`（成功运用）/ `"fail"`（失败）/ `"use"`（普通使用，不计成功）。

**引擎规则（不信任 AI 自报星级）**：
- 仅 `result === "success"` 才 `successCount += 1`；
- `stars` 由引擎按 `thresholds` **重算**，AI 若顺带报了 `stars` 字段，引擎忽略；
- 这比"完全依赖 AI 诚实"稳（确定性累加），也比"引擎纯反推"灵活（AI 自然决定某次行动算不算成功）。

> **为什么不直接让 AI 标 `stars`**：违反三层防泄漏 P0，且 AI 可能为了"让玩家爽"虚标星级，破坏成长感。

## 4. 判定引擎（纯函数，可单测）

新增 `src/prompt.js` 或独立 `src/skill-growth.js`（推荐独立，便于单测与复用）：

```js
// 由累计成功次数确定性算出当前星数
export function computeStars(successCount, thresholds, maxStars) {
  let s = 0;
  for (const t of thresholds) { if (successCount >= t) s++; else break; }
  return Math.min(s, maxStars || 3);
}

// 处理一次运用结果，返回是否升星（纯函数，不碰 DOM/S）
export function applySkillResult(skillState, result, cfg) {
  const next = { ...skillState };
  if (result === "success") next.successCount = (next.successCount || 0) + 1;
  const oldStars = next.stars || 0;
  next.stars = computeStars(next.successCount, cfg.thresholds, cfg.maxStars);
  return { state: next, leveledUp: next.stars > oldStars, oldStars, newStars: next.stars };
}
```

- `game.js` 的回合结算（`applyStateChanges`，docs/70 已抽出纯函数 `applyTagOpTo`）里，解析完 `state_changes.skills` 后调用 `applySkillResult`；若 `leveledUp` 为真，把 `{type:"skill_up", name, oldStars, newStars, atRound: round}` 推入 `S.gameState.pendingGrowthEvents`（新增队列）。
- **空转保护**：条件不满足（无 `result` / 非 success）不累加、不升星、不通知。

## 9. 风险与权衡

- **AI 不报 `result`**：则永不累加（安全默认，不会虚假升星）；可在 system 指令强调回报义务。
- **首星太易/太难**：默认 `[3,8,15]` 可调；创作者逐技能覆盖。
- **回溯（docs/69）改写历史**：`pendingGrowthEvents` 是运行时队列，回溯后重算自然清空，不污染旧存档（同 `random_event_state` 处理思路）。
- **多技能同时升星**：banner 队列依次浮现，不阻塞。
