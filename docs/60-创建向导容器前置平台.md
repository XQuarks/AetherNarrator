# docs/60 · 创建向导「叙事结构化容器」前置平台（三模式填充）

> 配套 docs/59（时间系统前置）。本文档覆盖用户要求前置的其余叙事结构化容器：
> NPC 角色卡(B1) / 玩家变量(B2) / 背包(B3) / 羁绊好感度(B4) / 支线事件 / 技能 / 目标。
> 核心目标：让玩家在**创建世界时**就把这些结构化内容配好，且每个都能「自填 / AI完善 / AI生成」三选一。

---

## 1. 现状缺口（基于代码调研，2026-08-04）

| # | 容器 | 创作层存储 | 建世界时行为 | 主要缺口 |
|---|------|-----------|-------------|---------|
| 1 | B1 人物卡 | `world.characters[]` | **硬编码空数组**，`generated.characters` 被丢弃 | AI 生成需手动点按钮，建世界不自动跑 |

## 2. 统一架构：容器前置平台 + 三模式填充

### 2.1 核心原则

**「玩家显式配置的容器 = 锁定（权威）；未配置的容器 = AI 建世界时自动生成（兜底）」**

- 玩家在向导里配过的容器 → 直接进 `world` 创作层，生成时**不被 AI 输出覆盖**。
- 玩家没配的容器 → 走现有建世界逻辑，AI 正常生成（如 `initial_state` 里的 skills/inventory/goals）。
- 这与 docs/59 时间系统「玩家配置是权威」完全一致，只是把"没配的"交给 AI 兜底，而非强制全配。

### 2.2 三模式 = 填充手段（不影响锁定语义）

每个容器在向导里是一个卡片，顶部有统一工具栏：

```
[＋ 添加]  [🤖 AI 从零生成]  [✨ AI 完善（保留已填、补空白）]  [🗑 清空]
```

- **自填**：玩家手动增删改条目。
- **🤖 AI 从零生成（创建世界前 · 向导内按需点）**：玩家在向导里点按钮，AI **基于玩家已填的向导上下文**（世界观描述 / 风格预设 / IP / 本容器里玩家已写的骨架）生成一套填进卡片。此时上下文已足够（向导里世界观描述、风格都已填），无需等建世界。
- **✨ AI 完善（两种时机）**：
  1. *向导内点「AI 完善」*：把"玩家已填骨架 + 世界观"发给 LLM，返回补全版，保留已填字段只补空白；
  2. *建世界时自动完善*：点「确认生成」后，AI 在生成**整个世界**的同一轮里，把玩家在向导里已填的容器作为**硬约束**注入 prompt，AI 据此生成完整世界并顺带完善这些容器骨架（此时 AI 上下文最全：世界观 + 风格 + 已抽 lore + 玩家已填容器）。
- 三种模式只是"怎么把数据弄进卡片"，最终都汇成 `world` 创作层数据。

### 2.3 向导布局（扩展现有左侧导航）

现有创建向导是「基本信息 / 叙事风格 / 玩法模块 / 时间系统 / 生成设置」左侧导航。
新增两个模块，把容器分组：

- **角色与关系**（B1 人物卡 + B4 羁绊好感度，因二者数据耦合：好感按 NPC 名索引）
- **物品 · 技能 · 目标 · 事件**（B3 背包 + 技能 + 目标 + 支线事件，均为 `initial_state` 派生的清单型容器）

> 时间系统（docs/59）仍是独立模块。

## 4. 关键逻辑改动

### 4.1 建世界管线（src/game.js `generateWorld`）
- **现状**：`characters: []` 硬编码空；`initial_state: generated.initial_state`（AI 全权生成）；`variable_schema` 不读 AI。
- **改后（三路合并）**：
  1. 玩家在向导**自填/AI从零生成**的容器数据（characters / variable_schema / inventory / skills / goals / bonds 锚点）→ 直接成为 world 创作层（锁定）。
  2. 玩家**已填骨架但未补全**的容器 → 作为**硬约束注入 callWorldGenerationLLM 的 prompt**（"以下为玩家已设定的容器，请尊重并补全空白字段/缺失条目"），AI 在生成整个世界的同时完善它们。
  3. 玩家**完全没配**的容器 → 走现有逻辑，AI 正常生成（`initial_state` 等）兜底。
  4. 生成后合并：`mergePlayerFirst(playerFilled, generated)` —— 玩家已填字段优先，AI 补全的只填玩家空白，绝不覆盖玩家显式设定（修复"AI 生成覆盖玩家配置"风险）。
  - 角色卡：玩家没配且未触发 AI 完善时，可选「建世界后自动跑 generateCharacters」（保持现状体验）。

### 4.2 模块门禁联动（src/modules.js）
- 玩家在向导里填了某容器 → 自动开启对应模块开关（如填了技能 → `modules.skills.enabled=true`）。
- 沿用现有 `ensureEventsWorldReady` 逻辑（events 开 → 连带开 variables 体力）。

### 4.3 AI 生成器新增（src/llm.js）
- 新增 `generateVariables / generateInventory / generateSkills / generateGoals / generateSideEvents`，模仿已有 `generateCharacters` 的纯函数 + 降级（无 API/mock 返回空/示例，不阻断）。
- 统一尊重：`world.canon`（IP 一致性包）、`style_preset`（风格预设）、世界观描述。

### 4.4 解析修复（src/llm.js `parseCharacters`）
- 补解析 `affinity` / `rel_tags`，让 AI 生成的角色卡能带初值好感（B4 创作层）。

## 5. 可完善点（帮用户想的扩展方向）

1. **容器间关联校验**：羁绊的 NPC 名必须在角色卡里存在；目标/支线提到的 NPC 应能在角色卡定位；背包关键物品 ↔ 知识库 lore 触发词一致性。提供「校验」按钮或即时提示。
2. **AI 生成尊重一致性包**：AI 从零生成角色/技能时，必须吃 `world.canon`（IP 红线）和 `style_preset`，避免生成出违背 IP 的内容。
3. **建世界性能/成本**：每个容器一次 LLM 调用，7+ 容器若全自动跑会很慢很贵。建议「AI 生成」为向导内**按需点击**，建世界时只把玩家已填的作为权威，未填的才走 AI 兜底（单次建世界最多 1 次 AI 生成）。
4. **无 API / 断网降级**：所有「AI 生成」按钮在无 API 时返回空或示例数据，绝不阻断建世界。
5. **旧世界兼容**：B4 旧档不兼容（save.js:132）的坑别扩大；新容器前置不影响读老存档。
6. **字段合法性校验**：变量 id 唯一且合法（不能含空格/中文 id）、角色卡 name 必填、目标 deadline 依赖时间系统（需时间已配）。
7. **创作者预置支线**：现在支线只能 AI 每轮即时生成、不进存档。前置后支持玩家预置初始支线池（`preset_side_events`），让世界一开局就有可选支线。
8. **向导复杂度控制**：7+ 容器放进向导会很长，用折叠/分区/「收起已配」降低认知负担。
9. **「AI 完善」的保留语义**：完善时必须保留玩家已填字段（如玩家填了角色名，AI 不能改掉），只补空白——需明确 prompt 约束。
10. **与知识库(B1 知识库)分工**：知识库是 AI 抽书的碎片段落（非结构化），容器是结构化设定。二者不替代；前置的是结构化容器，知识库仍由 AI 抽书生成。

## 7. 实施阶段（建议）

- 阶段 1：向导骨架（两个新模块 + 容器卡片 + 三模式工具栏 UI），先接入**已有**编辑器（角色卡/变量/物品）。
- 阶段 2：新增**缺失**编辑器（技能/目标/事件预置）+ 对应 LLM 生成器。
- 阶段 3：建世界管线改造（玩家锁定容器优先于 AI）+ 模块门禁联动 + parseCharacters 修复。
- 阶段 4：容器间关联校验 + 降级 + 测试。

## 8. 已确认决策点（2026-08-04 用户拍板）

- **A. 范围**：✅ 一次性全做（7 个容器）。分 4 阶段交付。
- **B. AI 生成时机**：✅ **并存双时机**（用户 2026-08-04 澄清，比原二选一更优）：
  - （1）向导内「🤖 AI 从零生成」按钮：创建世界前，基于玩家已填的向导上下文（世界观描述 / 风格预设 / IP / 本容器已写骨架）按需点击生成；
  - （2）建世界时「✨ AI 完善」自动发生：AI 在生成整个世界的同时，把玩家在向导里已填的容器骨架作为硬约束注入 prompt，一并完善（此时 AI 上下文最全：世界观+风格+已抽 lore+玩家已填容器）。
  - 用户原话要点：创建世界前 AI 信息量其实够（向导里世界观已填）；建世界时信息更全，应让 AI 顺便完善玩家已填内容。两者不矛盾，都要。
- **C. 未配兜底**：✅ AI 自动兜底（玩家没配的容器，建世界时让 AI 自动生成，保持现有体验）。
