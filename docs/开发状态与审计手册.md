### 3.2 ANN 索引持久化（2026-07-28，路径 A 真持久化）
- **痛点**：每次刷新重建 HNSW 向量索引（同步 wasm `addPoint`），大世界会"冻界面一下"。
- **方案**：用 hnswlib 自带 **IDBFS（IndexedDB 虚拟文件系统）** 落盘。文件名含**内容指纹** `ann_<worldId>_<dim>_<fp>_v1.idx`（`fp=FNV-1a(snippets 的 id+category+title+content+keywords)`）——编辑任一片段文本 → fp 变 → 旧文件失配 → 自动重建，无需显式删。
- **读回顺序**：`loadHnswlib` 后 `syncFileSystem("read")` 恢复虚拟 FS → `loadIndex` 读回跳过重建。
- **优雅降级**：库未暴露 `loadIndex` / sync 任一步抛错 → `catch` 静默忽略，内存索引仍可用，最终由 `rag.js` O(n) 兜底。
- **配套**：设置界面「选项」页新增**「清除索引缓存」**入口（`clearLoreAnnCache`，利用 hnswlib 暴露的 `FS` `readdir`+`unlink` 删全部 `ann_*.idx`，两次点击确认、禁用原生 confirm，失败静默降级）。
- **测试** `test/41-ann-persist.test.js`（3 项）+ `test/42-ann-clear-cache.test.js`（2 项），全量 414/414 通过（409→414）。
- 仅改 `src/ann-index.js`；`rag.js`/`lore-ui.js`/`save.js` 失效钩子无需改（fp 自动处理）。

### 3.3 错误处理三档统一（2026-07-28 落地，零回归）
- 入口（`utils.js`）：
  - `logError(scope, err)` — 静默 `console.warn` + 写入 `S.debugLog.chunkErrors`，**绝不弹 toast**；
  - `notifyError(scope, err, userMsg)` — 内部调 `logError` + `showToast(userMsg, "error")`；
  - `fatalError(scope, err, userMsg)` — 内部调 `logError` + `showModal` + 导出诊断。
- **三档判定**：Tier 1 静默降级（向量/分词/Worker 降级、JSON 修复、索引同步失败、配置加载）→ `logError`；Tier 2 用户主动操作/关键持久化失败 → `notifyError`（toast）；Tier 3 致命（IndexedDB 不可用 / 全局未捕获异常）→ `fatalError`（modal）。
- **Phase 1 安全网**：`app.js` `init()` 挂 `installGlobalErrorGuard()`（监听 `unhandledrejection`/`error`，去抖 5s 只弹一次）；`idbSet/idbSetMulti/idbDel` 改返回 boolean，关键保存失败 `notifyError`。
- **Phase 2 日志统一**：剩余 `console.error/warn` 收口到 `logError`；空 `catch` 补 `logError`。**排除** `ann-index.js` 与 `embedding-worker.js`（无主线程 S 单例/DOM，不能安全调用）。
- **Phase 3 防回归**：`test/43-error-handling.test.js`（6 项，含进 414→420），核心不变量——静默档 `logError` **绝不**触发 `showToast`。`app.js` 的 `installGlobalErrorGuard` 抽离到 `src/error-guard.js` 以便测试。
- **明确不做**：不把 Tier 1 静默降级改 toast（防回归雷区）；不为每错加 modal，仅 Tier 3 用 modal；不动 `migrations.js`/`files.js`。
