## 1. 你能用时间系统做什么

一句话：**让每个世界的时间「像那个世界该有的样子」**，并且支持四类进阶玩法：

| 能力 | 说明 | 典型例子 |
|---|---|---|
| **真实日历** | 公历/农历/自定义历法，支持真实年、月、闰年、跨年 | 克苏鲁开局 `1926年2月2日`；都市题材从 `1999年1月22日`（英伟达上市日）起 |
| **大段时间跳跃** | 闭关、沉睡、远行，时间一键往前跳 | 修仙「闭关三月」→ 直接到 `5月3日`；车祸变植物人，苏醒跳到 `2004年`（腾讯上市） |
| **虚构历法** | 各世界用自己的月份表（魔法历/星际历），引擎不内置任何历法假设 | 星历3024年·熔火月初3 |
| **双世界穿梭** | 现实/异界各自时间独立流逝（道诡异仙效果） | 现实过 1 天，异界可能过 1 年 |
| **时间穿越 + 已触发事件四策略** | 回到过去、重走、或分叉，全程不崩 | 普通逆跳不重播 / 重置重走 / 分支平行世界 |

## 2. 核心概念（作者必须懂的三个量）

时间系统由三个互相独立的东西组成，**不要混为一谈**：

1. **`era_label`（纪元/年份文字）** —— 你写给玩家看的「年代感」文字。例：`1920年代`、`大清乾隆年间`、`星历3024`。
   - ⚠️ **它是唯一的「年/纪元」载体**（方案 22 拍板）。不要再单独填「起始年份」数字——年份请写进 `era_label`。
2. **`calendar_start`（起始日期）** —— 世界的「月·日」起点，**年可以不填**（年无关模式由 `era_label` 推算）。例：克苏鲁 `{month:2, date:2}`（无 year）。
3. **`current_date`（当前日期）** —— 游戏进行到哪一天。引擎按历法原生推进，**没有隐藏的「第几天序数」**（方案 20 方案 B 拍板：彻底解耦）。

> **作者视角的好处**：你写的是「1920年代·2月2日·深冬」这种自然语言，引擎背后算的是真实日期；AI 拿真实日期生成剧情，玩家看真实日期，三层一致。

### 历法模式（5 种）
| 模式 | 显示样例 | 适用 |
|---|---|---|
| `day`（第 N 天） | 第 53 天 | 不强调具体日期的通用世界 |
| `gregorian`（公历） | 1926年2月2日 · 周二 · 深夜 | 真实/半真实历史、现代 |
| `lunar`（农历） | 农历正月初九 | 古风、民俗 |
| `custom_calendar`（自定义历法） | 星历3024·熔火月初3 | 科幻/奇幻自有历法（用 UI-1 可视化配） |
| `none`（不显示时间） | 相对标签「第五十三天」 | 后室类「时间模糊」世界（**后室强制用 none**，强加日期反而违和） |

## 3. 配置时间：一步步来

在「创建/编辑世界」里有 **🌐 世界时间体系** 卡片（创建当次可编辑，进游戏后锁定，防篡改）。你需要配的：

1. **纪元文字**（`era_label`）：填 `1920年代` 这类，别填裸年份数字。
2. **历法模式**：下拉选上面 5 种之一。
3. **起始日期**（仅 dated 历法显示年/月/日输入框）：
   - 年输入框**已移除**（方案 22）。年份靠 `era_label` 表达。
   - 月/日**各自可空**：填 `月+日` / 只 `月` / 全空 都行，缺失部分不显示、按纪元推算。
4. **自定义历法**（选 custom 时出现）：点开 UI-1 编辑器增删月份、设月长（见 §7）。
5. **多时间线**（选 multiverse 时出现）：点开 UI-2 配置器增删世界线（见 §6）。

> **克苏鲁预设已适配**：`era_label="1920年代"` + 起始 `{month:2,date:2}`，无 year。顶栏显示 `1920年代 · 2月2日 · 深冬`。

### 日期合法性校验（自动）
填了非法日期（平年 2月29、月份/日期超范围、农历月份超表），编辑卡会**红字提示**；明显错误（如平年2月29）**自动纠正为 28** 并提示。农历闰月只做基础范围校验，正确性靠 AI 保证。

## 4. 大段时间跳跃（进阶玩法）

AI 在生成剧情时可以直接让时间跳。你作为作者**不需要手动改日期**，AI 会按世界设定推进。引擎支持三种指令：

| AI 指令 | 含义 | 例子 |
|---|---|---|
| 仅切时段 | 常规推进 | `period:"night"` |
| 相对 +N 天 | 远行/沉睡 | `addDays:90` |
| 相对 +N 月 | 闭关 | `addMonths:3`（月末自动夹紧：1/31+1月→2/28或29） |
| 绝对跳转 | 跳到具体历史/未来日期 | `{year:2004,month:6,date:16}` |

**向前跳（时间变大）一律放行；向后倒退（时间倒流）默认也放行**（黎总拍板允许时间倒流），倒退时的事件行为由 §5 四策略决定。

## 5. 时间穿越与「已触发事件」四策略（UI-3 / UI-4 / UI-5）

这是时间系统最复杂也最强大的部分。核心原则：**不再用「日期大小」判断事件该不该触发，改用「触发记录 + 每事件策略 + 穿越指令」三者组合**。这样四种玩法能并存、互不打架。

### 四个策略
| 策略 | 行为 | 典型玩法 |
|---|---|---|
| **S1 不重触发（once，默认）** | 已触发事件永久进触发记录，穿回去也不重播 | 生日、历史性节点、一次性剧情 |
| **S2 可重复（repeatable）** | 带 `max_repeats` + `cooldown_steps`，到窗口且未超次数就再触发 | 每日商情、周期怪潮 |
| **S3 时间线重置（reset）** | 穿越指令带 `reset_triggers`，回滚触发记录，重走该段可重新触发 | 轮回/重开、roguelike 时间循环 |
| **S4 分支隔离（branch）** | 穿回去时新建一条分支时间线，原未来保留；各分支独立触发记录 | 量子分叉、平行世界（与多世界同构） |

### 三层策略优先级（从高到低）
1. **穿越指令显式指定**（如 `reset_triggers:["ev_a"]` 或 `branch:true`）—— 最高优先级
2. **单时间线覆盖**（`timelines[id].timetravel_strategy`，`null`=继承世界级）
3. **世界级默认**（`time_config.default_timetravel_strategy`：`keep` 默认 / `reset` / `branch`）
4. 回落 `keep`（保留触发记录，不重触发）

> 仅在「时间逆跳（日历变小）」时套用默认/覆盖层；**向前跳一律放行，不触发重置/分支**。

### 截止事件（deadlines）编辑器（UI-5）
在「🌐 世界时间体系」卡里可可视化配置 `time_config.deadlines[]`，每条设：
- 触发时间（月/日/时段）
- 重触发策略 `retrigger_policy`：`once`（一次性）/ `repeatable`（可重复 + `max_repeats` + `cooldown_steps`，0=无限）

> 截止事件由 AI 在时间到达时自动触发；编辑器只负责你写入与归一化。

## 6. 双世界 / 多时间线（multiverse，UI-2）

当世界选 **多时间线** 结构时，用 UI-2 配置器图形化操作：

- 切换世界结构：单一时间线 ↔ 多时间线（切到多线会自动 seed 一条默认线继承你已填的单线配置，不丢数据）。
- **增删时间线**：每条线一个独立身份（如「现实 / 异界」）。
- 每条线设：名称、历法、纪元文字、初始日期、是否活动线（单选）、删除。
- **「双界穿梭」一键模板**：直接载入 earth/xianxia 两线预设。
- 每条线内可内嵌自定义历法编辑器（UI-1）、时钟/天气、拖拽排序。

**玩法效果**：切换世界 = 切 `active_timeline`，每条线时间独立推进。时间流速可不同（如异界 1 天 = 现实 1 年），用 `sync_rules` 配置（见下）。

### 时间流速比（sync_rules，UI-3）
每条时间线可带 `sync_rules:[{ref, ratio}]`：
- `ref` 指向 `timelines` 内另一条线
- `ratio` 语义：「本线推进 1 个日历日 ⇒ ref 线推进 ratio 个日历日」（可为小数，如 0.0027 反向慢流速）
- 道诡异仙类各自独立无需同步；想做流速差就配。

## 7. 自定义历法编辑器（UI-1，自定义历法模式）

选 `custom_calendar` 时出现的可视化编辑器，让你**不用手写 JSON** 就能：
- 给历法起名（如「艾欧历」「星历」）
- 可视化增删月份、改名、改每月天数
- 一键插入「闰 X 月」（本质是在对应月后插一个普通月份条目）
- 上移/下移排序、拖拽排序
- 模板预设：农历 / 科幻历 一键载入
- 实时看「共 N 个月 · 一年约 M 天 · 示例日期」+ 边界校验

> 引擎早已支持该结构，UI-1 纯前端补全，与引擎解耦（只读写 `schema.time_config.custom_calendar`）。

## 8. 季节机制已彻底移除（方案 23）

**重要**：时间系统**不再有「季节」概念**（黎总拍板移除）。原因：季节最容易和「具体日期」打架，移除后从源头消除一类时间冲突，作者也少一个要对齐的字段。

影响：
- 数据模型无 `time_config.season`；编辑卡无季节输入框；顶栏不显示季节；AI 提示词不含季节。
- 开场白占位符 `{season}` 不再支持（旧档残留 `{season}` 静默清空，不显示怪字符）。
- 冲突检测只剩「年份 + 现代措辞」两维。
- 氛围（深冬/盛夏）改由开场白/系统提示的措辞自带，不强依赖系统字段。

## 9. 时间冲突检测与修复（编辑期 + 运行期）

如果你改了 `era_label`/起始日期，但开场白、系统提示里写死了旧年份，会「自相矛盾」。系统有四道机制兜底，**绝不静默改你的文本**：

| 机制 | 时机 | 做什么 |
|---|---|---|
| **一·占位符（推荐）** | 写开场白时 | 用 `{era_label}` `{calendar_date}` `{calendar_year}` `{calendar_month}` 占位，时间跳跃后自动跟随。例：`现在是{era_label}。{calendar_date}，波士顿…` |
| **二·轻量 Lint + 一键修复** | 编辑改日期时 / 开局 `loadSave` | 扫硬年份/现代措辞与锚点不符 → 打「⚠ 时间可能冲突」徽章（非阻塞）。提供「重新生成开场」/「改成占位符版」两按钮，均走「预览 diff → 确认才改」 |
| **三·Critic 审稿** | 世界生成后 / 手动「重新审稿」 | 复用现有 AI 审稿人，新增「时间一致性」维度，专审知识库条目 |
| **四·权威时间兜底（运行期）** | 每轮生成 | 把「当前权威时间」显式注入 prompt，AI 以它为真相，不被写死文本误导 |

> 冲突检查锚点读取 `era_label`（方案 22 后），同 decade 容错（1920 与 1926 不算冲突），消除克苏鲁式误报。
