## 一、目标

在「创建/编辑世界」的时间体系卡里，当历法模式选 **自定义历法（custom_calendar）** 时，提供**可视化编辑器**让用户：

- 给历法起名（如「艾欧历」「星历」）；
- 可视化**增删月份、改名、改每月天数**；
- （可选）一键插入「闰 X 月」；
- 实时看到**一年总月数 / 总天数 / 示例日期**；
- 校验非法输入（月份数、天数边界）。

**替代**当前"手写 JSON 月历表"的高门槛写法（引擎早已支持该结构，仅缺 UI）。

## 三、设计

### 3.1 编辑区（custom_calendar 模式显示）

在时间体系卡 `renderTimeConfigSection` 的 custom_calendar 分支内插入：

1. **历法名称**：文本输入 `data-cal="cc-label"`（≤20 字，对应 normalize 截断）。
2. **月份列表**：每行一个条目
   - 月名输入 `data-cal="cc-month-name"`（空则回退「月 N」）
   - 天数数字输入 `data-cal="cc-month-days"`（1–400，失焦夹取）
   - 操作：`↑ 上移` `↓ 下移` `🗑 删除`（各带 `data-action`，走 app.js 事件委托，**禁用原生 confirm**）
3. **添加月份** 按钮（`data-action="ccAddMonth"`）：追加一行默认 `{name:"新月", days:30}`。
4. **实时统计条**：「共 N 个月 · 一年约 M 天 · 示例：第1年 月1 日1」（纯函数 `summarizeCustomCalendar` 计算）。
5. **校验徽章**（可选，复用 `lore-ui.js:281` `setBadge`）：月份数越界 / 天数越界时提示。

### 3.2 闰月处理

引擎把月份当成普通 `{name, days}` 数组，无独立「闰月」字段。故**闰月 = 在对应月后插入一个名为「闰X月」的普通月份条目**即可（如「闰二月」插在二月之后）。可选提供「插入闰月」快捷按钮（B 方案）。

### 3.3 只读模式

`renderTimeConfigSection("save")` 时，编辑器渲染但输入框 `disabled`、隐藏增删按钮（与现有 world/save 区分一致）。

### 3.4 回读

`readCalendarStartFromDOM` 的 custom_calendar 分支：遍历月份行 DOM → 组装 `tc.custom_calendar = { label, months:[{name,days}] }`。保存时由 `normalizeTimeConfig` 兜底夹紧。
