## 1. 设计目标与红线

**目标**：让 NPC 关系从「只有好感数字」升级为有「等级阶梯」（陌生人→…→恋人），且每次升级被**明确的门控**约束；升级通知**确定性、不依赖 AI 临场发挥**。

**红线（与项目价值观一致）**：
1. **引擎管状态、LLM 管叙事**：AI 不直接写 `tier`，只通过 `state_changes.bonds` 报好感/标签变化；**等级提升由引擎在条件满足时确定性执行**（主动触发走确定性动作，自动触发走回合结算）。
2. **复用优先**：阈值用 `evalCondition` bond 分支；节点用 `evalEventConditions`；**不新写条件代码**。
3. **默认关闭**：挂在 `affinity` 之上，新增模块 `relationship_upgrade`，`defaultEnabled:false`；不开则完全无副作用。
4. **不喧宾夺主**：日常好感浮动静默；仅在「跨级」时弹非阻塞 banner（方案 B）。

## 2. 数据模型

### 2.1 世界配置（静态预设，创作者填；全可选，缺省用代码默认）
```js
world.relationship_upgrade = {
  // 等级阶梯（有序）。缺省用全局 DEFAULT_TIERS
  tiers: ["陌生人", "相识", "朋友", "挚友", "恋人"],
  // 每级「升入」的门控，index = 升入的 tier 下标（即 gates[0] 是升入 tiers[1] 的门槛）
  // 某字段缺失 = 该门控类型「不要求」
  gates: [
    { threshold: 20, active: true },                                  // → 相识
    { threshold: 40, active: true },                                  // → 朋友
    { threshold: 60, node: { conditions: [{type:"location", value:"老家"}], condition_mode:"all" }, active: true }, // → 挚友（需到过老家）
    { threshold: 80, active: true }                                   // → 恋人
  ]
}
```
- `threshold`：好感下限（复用 `evalCondition` bond：`affinity ≥ threshold`）。
- `node`：节点条件（复用 `evalEventConditions`，支持 location/story_progress/bond/events/lore/season/era + all/any）。
- `active`：`true`=需玩家在 UI 主动选择触发；`false`=条件满足即自动升级（回合结算时执行）。

### 2.2 运行时状态（引擎维护，确定性）
- `s.bonds[npc].tier`：整数，指向 `tiers` 下标；**读取时缺省 0**（老存档无此字段不报错）。
- 新增队列 `s.pendingRelationshipEvents = []`：跨级事件 `{type:"rel_upgrade", npc, fromTier, toTier, atRound}`（同 `pendingGrowthEvents` 思路，回溯自然清空）。

### 2.3 向后兼容
老存档 `bonds[npc]` 无 `tier` → 默认 0；世界无 `relationship_upgrade` → 用代码默认 `DEFAULT_TIERS` + `DEFAULT_GATES`。

## 3. 门控判定（纯函数，可单测）

新增 `src/relationship-gating.js`（独立模块，便于单测与复用）：

```js
export const DEFAULT_TIERS = ["陌生人", "相识", "朋友", "挚友", "恋人"];
export const DEFAULT_GATES = [
  { threshold: 20, active: true },
  { threshold: 40, active: true },
  { threshold: 60, active: true },
  { threshold: 80, active: true },
];

// 取某 NPC 的「下一步门控」
function nextGate(world, npc) { ... } // 按当前 tier 取 gates[tier]

// 阈值是否满足（复用 evalCondition bond 分支）
export function thresholdMet(gs, npc, threshold) {
  return evalCondition({ type:"bond", npc, op:">=", value: threshold }, { gameState: gs, world: {} });
}
// 节点是否满足（复用 evalEventConditions）
export function nodeMet(world, gs, node) {
  if (!node) return true;                       // 无节点要求 = 满足
  return evalEventConditions(node, { gameState: gs, world });
}
// 综合：是否「已具备升级资格」（忽略 active 与否）
export function isEligible(gs, world, npc) {
  const gate = nextGate(world, npc);
  if (!gate) return false;                      // 已在最高级
  return thresholdMet(gs, npc, gate.threshold) && nodeMet(world, gs, gate.node);
}
// 确定性升级（主动 / 自动 共用）。返回是否成功 + from/to。
export function applyRelationshipUpgrade(gs, world, npc) {
  const gate = nextGate(world, npc);
  if (!gate) return { ok:false };
  if (!isEligible(gs, world, npc)) return { ok:false };   // 双保险，不信任 UI
  const bond = gs.bonds[npc] || (gs.bonds[npc] = { affinity:0, tags:[] });
  const from = bond.tier || 0;
  const to = from + 1;
  bond.tier = to;
  gs.pendingRelationshipEvents = gs.pendingRelationshipEvents || [];
  gs.pendingRelationshipEvents.push({ type:"rel_upgrade", npc, fromTier:from, toTier:to, atRound: gs._round });
  return { ok:true, fromTier:from, toTier:to };
}
```

## 4. 三类门控如何落地

| 门控 | 复用 | 触发方式 |
|---|---|---|
| **① 阈值** | `evalCondition` 的 `bond` 分支（`prompt.js:1353`） | 被动（好感累计自然达线） |
| **② 节点** | `evalEventConditions`（`prompt.js:1390`） | 被动（完成事件/到访/解锁 lore） |
| **③ 主动** | 新增：UI 按钮 → 确定性动作 | **玩家主动选择**（表白/结义/深交） |

- **自动升级**（`active:false`）：在 `game.js` 的 `applyStateChanges` 处理完 `state_changes.bonds` 后，遍历各 bond，若 `isEligible` 且 `!gate.active`，调 `applyRelationshipUpgrade` 推事件。
- **主动升级**（`active:true`）：关系页签对「已具备资格」的 NPC 显示升级按钮（见 §5）；玩家点击 → 确定性 `applyRelationshipUpgrade`，不依赖 AI。

## 5. UI：主动升级按钮 + 等级展示

- **主动按钮**（仅当 `isEligible(npc)` 且 `gate.active===true` 且未达顶级时显示）：
  ```html

          data-action="upgradeRelationship" data-npc="${name}">${upgradeLabel(nextTier)}</button>
  ```

## 7. 验收标准

| 项 | 标准 |
|---|---|
| 默认关闭 | 不开 `relationship_upgrade`（或 affinity）则完全无副作用 |
| 复用 | 阈值走 `evalCondition` bond；节点走 `evalEventConditions`；无新条件代码 |
| 确定性 | 同 `bonds`/`completed_events` 状态 → 同升级结果，可单测 |
| 防泄漏 | AI 即使谎报等级，引擎以 `isEligible` 双保险为准 |
| 主动可控 | 仅 `active:true` 且资格就绪时显示按钮；点击确定性升级 |
| 不喧宾夺主 | 日常好感静默；仅跨级弹 banner |
| 向后兼容 | 老档无 `tier` 默认 0；世界无配置用代码默认 |
| 无回归 | 全量测试通过 |

## 8. 风险与权衡

- **AI 不体现等级**：靠 `promptFragment` 要求叙事贴合关系阶段；等级已写入 `bonds[npc].tier`，下轮 prompt 自然带出。
- **按钮诱导 AI 自编升级**：按钮只在 `isEligible` 真时渲染，且升级走确定性动作，AI 无从伪造。
- **回溯（docs/69）**：`pendingRelationshipEvents` 是运行时队列，回溯重算自然清空，不污染旧档。
- **跨级跳级**：每次只升 1 级（to=from+1），资格者下回合继续升，符合阶梯语义。
- **门槛松紧**：默认 `[20,40,60,80]`，创作者可逐阶覆盖；节点默认不要求（world 按需加）。
