# 70 · 每回合状态栏与变动日志 · 字段设计 + 呈现格式方案

> 目标：给玩家每回合一个清晰的"本回合发生了什么变化"视图，同时**从架构上杜绝 LLM 把代码/格式原样吐到界面**（JSON、Markdown 围栏、`【状态栏】` 占位、模板残留等）。
> 状态：**方案文档（待确认范围后再落代码）**。

---

## 1. 防泄漏总纲（先定死，再谈字段）

| 原则 | 内容 | 解决的问题 |
|------|------|-----------|
| **P0 引擎渲染，LLM 不写状态栏** | 状态栏/变动日志由代码从"权威状态对象"渲染，LLM 只产出叙事正文 | 根上消除"LLM 写出 JSON/Markdown 代码块" |
| **P1 输出净化器** | 所有 LLM 文本进 DOM 前过 `sanitizeLLMText()`，剥离代码围栏/模板残留 | 即便 LLM 误吐标记，玩家也看不到 |
| **P2 结构化信号走受控信封** | 若 LLM 需上报状态变化，用唯一信封 `<state-delta>…</state-delta>`，解析失败有兜底 | 不当信封原文显示给玩家 |
| **P3 diff 不 dump** | 只渲染"变化项"，无变化不显示该行 | 避免噪声与空项 |

> 关键认知：**状态栏不是 LLM 的"作业"，而是引擎的"渲染结果"。** prompt 里应**删除**"每轮必须输出状态栏 / 每轮必须输出【状态栏】"这类指令，改为由 `renderChangeLog(state.prev, state.curr)` 在每回合渲染后自动追加。

## 2. 权威状态对象（State Schema）

引擎维护一个唯一可信状态对象 `S`。状态栏与变动日志都从它派生。

| 分类 | 字段 | 类型 | 说明 / 枚举 |
|------|------|------|------------|
| 时间 | `time.year` | int | 学年（自定义历法下为 era_label 载体） |
| 时间 | `time.season` | enum | 春/夏/秋/冬（或世界自定义季节） |
| 时间 | `time.dateLabel` | string | 当前日期展示文案 |
| 玩家 | `player.name` | string | |
| 玩家 | `player.house` | string | 学院（待分院时为"待分院"） |
| 玩家 | `player.bloodline` | string | 纯血/混血/麻瓜出身 |
| 玩家 | `player.wand` | string | 木材+杖芯 |
| 玩家 | `player.patronus` | string | 守护神 |
| 玩家 | `player.status` | string[] | 特殊状态：受伤/禁足/中毒…默认 `['无']` |
| 资源 | `player.resources.stamina` | int | 体力（跨天恢复，事件消耗） |
| 资源 | `player.resources.gold` | int | 金币（可选） |
| 技能 | `skills[]` | obj[] | `{id,name,track:'major'|'minor'|'custom',stars:0-3,uses:int}` |
| 魔咒 | `spells[]` | obj[] | `{id,name}`，**上限 5**，学新需主动遗忘旧 |
| 好感 | `affinity` | map | `charId -> {name, value:int, tier:enum}` |
| 背包 | `inventory[]` | obj[] | `{id,name,qty:int}` |
| 地点 | `location.current` | string | 当前地点 |
| 地点 | `location.discovered[]` | string[] | 已发现地点 |
| 地点 | `location.connections[]` | string[] | 已解锁连接 |
| 任务 | `quests[]` | obj[] | `{id,title,status:'active'|'done'|'failed',stage:int}` |
| 记忆 | `memory.newThisTurn[]` | string[] | 本回合新沉淀（emotional/important_event/learned_fact） |
| 世界 | `worldFlags.triggeredEvents[]` | string[] | 已触发事件 |
| 世界 | `worldFlags.factionStates` | map | 势力态度 |
| 关系 | `relationshipQual` | map | `charId -> {tierLabel}` 质性等级（朋友/盟友/恋人…） |
| 延迟 | `delayedConsequences[]` | obj[] | `{id,hint,trigger}` 未来才兑现的后果 |

> 兜底：任何字段缺失，渲染器用默认值（如 `status:['无']`、`affinity:{}`），**不抛错、不显示 `undefined`**。

## 3. 变动日志条目 Schema（ChangeEntry）

引擎对比 `S.prev` 与 `S.curr`，产出 `ChangeEntry[]`。**LLM 不提供原始符号**，图标/标签由代码映射。

| 字段 | 类型 | 说明 |
|------|------|------|
| `category` | enum | time / affinity / item / status / skill / spell / location / quest / memory / world / relationship / resource / delayed |
| `changeType` | enum | added / removed / increased / decreased / upgraded / downgraded / changed / new_state / discovered / unlocked |
| `target` | string | 展示名（如"赫敏""魔杖"） |
| `detail` | string? | 可选补充 |
| `from` / `to` | any? | 数值或状态的前后值（用于 `+N`、箭头展示） |
| `icon` | **代码派生** | 由 `category+changeType` 映射，LLM 不碰 |

> 校验：所有 enum 必须命中白名单；`value` 非数字→忽略该条；`category` 未知→静默丢弃。

## 4. 呈现格式模板

固定区块顺序（仅显示有变化的分类），用中文标签 + 安全符号，不依赖 emoji：

```
📊 本回合变动（第 N 轮）
【时间】<from> → <to>
【好感】<name> <+/-><n>（现 <v>）｜ <name2> …
【物品】+ <name>×<qty> ｜ - <name>×<qty>
【状态】<status> <(新增/解除)>
【技能】★ <name> 升星（<old>→<new>）｜ + <name>（新获得）
【魔咒】+ <name>（掌握 <k>/5）｜ 遗忘 <name> → 习得 <name>
【地点】<from> → <to> ｜ 🔍 发现 <name>
【任务】◆ <title> <推进至阶段X / 完成 / 失败>
【记忆】新沉淀「<text>」
【世界】<event>（已触发 / 已解锁）
【关系】<name>：<oldTier> → <newTier>
【资源】体力 -<n> ｜ 金币 -<n>
【延迟】⏳ <hint>（后续影响已埋下）
```

**渲染示例（真实玩家视角）：**
```
📊 本回合变动（第 12 轮）
【时间】第1学年·秋 → 冬
【好感】赫敏 +5（现 32）｜ 斯内普 -2（现 18）
【物品】+ 魔杖（冬青木+凤凰羽）｜ - 2 金币
【状态】轻微擦伤（新增）
【地点】大堂 → 魔药课教室
【任务】◆ 主线「密室疑云」推进至阶段2
【记忆】新沉淀「斯内普偏袒斯莱特林」
【世界】霍格莫德周末开放（已解锁）
```

**绝不允许出现在界面上的（净化器会拦）：**
```
[RAG 命中 lore_kb 相似度 0.34]      ← 引擎内部
你将在第3学年知晓身世              ← 剧透（防剧透门禁拦截）
S.affinity.harry = 32               ← 内部字段
GM真相：魂器尚未销毁               ← 玩家不可见（GM 真相层）
```状态栏``` 或 ```json {...}        ← Markdown 围栏（净化器剥离）
```

## 5. 兜底 / 守卫设计（代码层，重点）

### G1 · 状态栏永远引擎渲染
- prompt 删除"每轮必须输出状态栏"类指令。
- 渲染器从 `S` 读字段；缺字段用默认值，不显示 `undefined`/`[object Object]`。

### G2 · LLM 文本净化器 `sanitizeLLMText(raw)`
进 DOM 前必过。伪代码（实际用 `textContent` 插入，不用 `innerHTML`）：

```js
function sanitizeLLMText(raw) {
  if (typeof raw !== 'string') return '';
  let t = raw;
  t = t.replace(/```[\s\S]*?```/g, '');     // 剥离代码围栏 + 语言标签
  t = t.replace(/`([^`]*)`/g, '$1');         // 剥离行内 code
  t = t.replace(/\{\{.*?\}\}/g, '');         // 剥离 {{ }} 模板残留
  t = t.replace(/<%[\s\S]*?%>/g, '');        // 剥离 <% %> 
  t = t.replace(/【状态栏】|【状态】/g, ''); // 剥离旧式标记
  // 疑似 JSON 行（以 { 开头且含 "key":）整体丢弃，绝不当代码渲染
  t = t.split('\n')
       .filter(line => !/^\s*\{[\s\S]*"[\w-]+"\s*:/.test(line))
       .join('\n');
  t = t.replace(/\n{3,}/g, '\n\n').trim();   // 压缩多余空行
  return t;
}
```

### G3 · 结构化信号信封 + 严格解析 `parseStateDelta(raw, prev)`
若让 LLM 上报变化，只允许信封包裹的 JSON；**任何异常返回 `null`，绝不显示原始信封**：

```js
const CATEGORIES = new Set(['time','affinity','item','status','skill',
  'spell','location','quest','memory','world','relationship','resource','delayed']);
const CHANGE_TYPES = new Set(['added','removed','increased','decreased',
  'upgraded','downgraded','changed','new_state','discovered','unlocked']);

function parseStateDelta(raw, prev) {
  try {
    const m = raw.match(/<state-delta>([\s\S]*?)<\/state-delta>/);
    if (!m) return null;                       // 无信封 → 不当状态信号处理
    const obj = JSON.parse(m[1]);
    return validateDelta(obj, prev);           // 逐字段校验 + 兜底
  } catch (e) {
    return null;                               // 解析失败 → 本回合无状态变动
  }
}

function validateDelta(obj, prev) {
  if (!obj || !Array.isArray(obj.entries)) return null;
  const out = [];
  for (const e of obj.entries) {
    if (!e || !CATEGORIES.has(e.category)) continue;        // 未知分类丢弃
    if (!CHANGE_TYPES.has(e.changeType)) continue;          // 非法变动类型丢弃
    if (typeof e.target !== 'string') continue;             // 无目标名丢弃
    // 数值类兜底
    if (['increased','decreased'].includes(e.changeType)) {
      const n = Number(e.amount);
      if (!Number.isFinite(n)) continue;                    // 非数字忽略
      e.amount = Math.trunc(n);
    }
    out.push(e);
  }
  return out.length ? out : null;
}
```

### G4 · 数值 / 枚举校验
- 好感 `value`：必须 int，`clamp` 到设计范围（如 [-100,100]）；非数字→忽略。
- 星级 `stars`：0–3 int，越界 clamp。
- `category` / `changeType`：必须是白名单枚举，否则丢弃该 entry（G3 已做）。

### G5 · 列表长度上限 + 截断
- 单分类最多显示 `K=6` 条；超出显示"+N 项未列出"或折叠。
- 单条文本 ≤ 40 字，超出加"…"。

### G6 · HTML 转义
- 动态文本一律 `textContent` 插入（或转义后拼），**绝不用 `innerHTML` 拼 LLM 内容**——既防 XSS 也防 markup 泄漏。

### G7 · 空集合不渲染
- 某分类本回合无变化 → 不输出该行（不显示"无变化"）。
- 整轮无任何变化 → 不显示变动日志区块（或显示极简"本回合无状态变动"，可选，见待确认）。

### G8 · 渲染层再卡一道防剧透 / 信息边界
- 渲染前再过 `unlock_stage`（docs/56）与 A1 信息边界（secrecy）：
  即便 LLM 误把未解锁真相写进 delta，渲染器按 `story_progress` 过滤，未达阶段不显示。
- `worldFlags` / `memory` 若标记 `locked` 且未解锁 → 不渲染。

### G9 · 轮次计数由引擎维护
- `turn` 在 `S` 中，引擎自增；**不依赖 LLM 数数**，prompt 不要求"每 3 轮随机"。

### G10 · 随机事件由引擎调度
- 在 `modules.js` 注册 `random_event`（可配 `defaultEnabled`），引擎按 turn/event 计数触发，把事件注入叙事上下文；LLM 只负责把给定事件写成故事，**不自己决定"现在随机"**（避免无真随机源导致漏触发/乱触发）。

## 8. 一句话总结

状态栏 = 引擎从权威状态对象渲染的 **diff 视图**；LLM 只写故事、不写状态。靠 **P0 引擎渲染 + P1 净化器 + P2 信封解析兜底 + G1–G10 守卫**，任意一层失效都不会让玩家看到代码/格式泄漏。
