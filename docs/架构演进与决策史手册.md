## 一、整体架构定位

| 维度 | 结论 |
|---|---|
| 形态 | **纯前端、零后端、可离线**运行的 AI 文字冒险/叙事模拟器 |
| 技术栈 | 原生 HTML + ES Module（无框架）+ IndexedDB + 本地内嵌中文向量模型（Xenova/bge-small-zh-v1.5，512 维） |
| 部署 | 零构建，`deploy.yml` `upload-pages-artifact path: .` 直接上线（曾用 GitHub Pages，现迁移 EdgeOne Makers 国内边缘节点）；`vendor/`+`models/` 本地内置，彻底脱离 CDN |
| 模块数 | 当前 `src/` 约 **32 个 ES Module**（21 个基础上新增 `ann-index`/`calendar`/`critic`/`kg-graph`/`embedding-worker`/`lore-revision`/`memory-transfer`/`migrations`/`simulation`/`time-engine`/`turn-lifecycle`/`providers`/`worldview` 等） |
| 强项 | 模块化与工程门禁强（verify-modules 三查 + JSON 4 级兜底 + 会话 epoch 失效 + applyStateChanges 事务回滚）；RAG 设计成熟；system 前缀缓存优化到位；零后端可离线 + 多世界 + UGC 便携；世界观守卫 + 防注入双层 |
| 弱点 | 无向量索引时大世界检索扩展性存疑（Phase 1 已解）；平台化（后端/账号/同步）完全缺失（Phase 6 独立立项）；少数巨型模块（已部分拆） |

### 1.1 核心架构决策：全局状态收进 `S` 容器
36 个可变全局状态**全部收进 `store.js` 的单一容器对象 `S`**，跨模块读写统一 `S.xxx`：
```js
export const S = { gameState: null, currentWorld: null, /* … */ };
```
放弃 `export let x` live binding（跨模块重赋值会 TypeError），容器对象只需机械加 `S.` 前缀，赋值天然可写，且与循环依赖无关。

### 1.2 ESM 多文件红线
- 所有 `import` 必须用 `./xxx.js` 相对路径；**禁用前导斜杠绝对路径**（`/src/x.js`），否则部署到 `user.github.io/<repo>/` 子路径会 404。
- 与现有 CSP / SRI 兼容，无需打包器。

### 1.3 模块化拆分方法（acorn 真解析器）
放弃正则/括号计数切分（模板字符串、正则字面量、转义会导致边界静默错误），改用 **acorn 解析 AST**：精确按函数边界切分、精确改写状态引用为 `S.xxx`（跳过变量声明/属性访问/对象键/对象简写）、基于符号引用自动生成相对 `import`。

**踩过的三个致命坑**（教训）：
1. ESM 严格模式下顶层重复函数声明是 SyntaxError（经典脚本模式只是后者覆盖前者不报错，`node --check` 按 CJS 解析曾漏过）→ 删残留旧定义。
2. `acorn-walk` 的 `simple`/`ancestor` 不访问 Pattern 位置的标识符 → 赋值左值漏改 96 处；必须改用 `walk.fullAncestor`。
3. import 清理副作用：某模块原本只从 `store.js` import 裸状态名，清理后整行删除导致 `S` 也丢了 → 需补 `import { S }`。

### 1.4 校验体系（无浏览器环境的唯一保障）
`npm run verify` 依次跑：内联脚本语法 → ES Module import/export 静态三查（`tools/verify-modules.cjs`：自引用+link 完整 / 裸状态引用必须以 `S.xxx` / 缺失 import 报错）→ 真实模块加载（`tools/load-check.mjs` 宽容浏览器全局 stub 下 import 全部约 32 模块，验证 node ESM link 无 "does not provide an export"）→ node 单元/集成测试 → 本机 Edge/Chrome 无头浏览器烟雾测试。
> 教训：`node --check` 只做单文件语法，**不做跨模块 link**，无法发现"import 了不存在的 export"。必须叠加静态 link 校验 + 真实 ESM 加载。

## 二、Phase 演进总览（决策史）

> 前提（2026-07-20 规划）：**后续优化不兼容旧存档/世界**，可自由做破坏性 schema 变更。后续时间系统重构（方案 B，2026-07-22）反而**加强了旧档兼容**（`normalizeCurrentDate`/`backfillCurrentDate` 自动补算回原生年月日），"不兼容旧档"前提在时间维度上不再成立，但其他 schema 破坏性变更仍可自由进行。

### Phase 0 — 清理与一致性（✅ 2026-07-20，低风险）
- **目标**：删 `migrations.js` 里的向后兼容迁移函数（`migrateWorldRecord`/`migrateSaveRecord`），未来改 schema 不受旧数据牵制；只删兼容层，不动业务。
- **关键事实**：`parseStoredArray`/`parseStoredObject` 是纯安全解析、必须保留；`store.js`/`theme.js` 里的 `localStorage` 是 UI 偏好（主题/字号/温度），刻意保留、不在清理范围。
- **附带**：统一删除存档/世界处原生 `confirm()` 为自定义弹窗；删死脚本 `tools/generate_embeddings.py`；重算 `data/lore_kb_with_embeddings.json` 覆盖真实默认世界。
- **验证**：`npm run verify` 全过；浏览器冒烟无 pageerror。

### Phase 1 — 向量 ANN 索引（✅ 2026-07-20，治卡顿）
- **痛点**：`embeddingRetrieve()` 每回合对全部 snippet 做 O(n) 全扫描余弦，2000+ 条世界卡顿；`selectTimelineSlice` 还逐段时间线段再调一次 embedding，雪上加霜。
- **方案**：引入 `hnswlib-wasm`（v0.8.2，浏览器 wasm，wasm 内联进 js 无需 fetch）在浏览器构建向量索引；保留关键词+向量融合与现有触发门禁/预算裁剪。
- **落地细节**：`src/ann-index.js` `loadHNSWLib()` 动态 `import("../vendor/ann/hnswlib.js")`；`index.html` CSP 补 `wasm-unsafe-eval`/`unsafe-eval`；`new lib.HierarchicalNSW("cosine", dim)`；按 worldId 缓存、模型维度变化自动重建；`invalidateLoreAnn`/`invalidateAllLoreAnn` 接 `lore-ui.js`（词条增删改）与 `save.js`（切世界/读档）；**仅内存构建**（向量本身已持久化在 snippet，2000×512 建索引约 2s 可接受），不持久化 IndexedDB（持久化留待后续，见《开发状态与审计手册》3.2 路径 A，2026-07-28 已落地）。
- **风险缓解**：O(n) fallback 永远在，ann 失败 = 原行为；零存档/世界数据风险。
- **验证**：浏览器实测 2000 条——构建 ~1976ms（一次性）、单查 2.35ms、ANN vs 暴力 topK 重合度 avgRecall=0.992 / minRecall=0.917（合格线 0.95/0.85）；`npm run verify` 全过（39 测试 + 浏览器烟雾）。

### Phase 2 — 规则 DSL 引擎（✅ 2026-07-20，让你自己配世界）
- **目标**：把写死在 `worldview.js` + `bannedConcepts` 里的世界硬规则，升级成**普通人能在界面上配置的规则 DSL**（"如果…就…"），创作者不碰代码。
- **DSL 设计**：一条规则 = `when`（条件）+ `then`（动作）+ 开关/强度。
  - 条件 `when`：`concept`（文本出现某词）/ `state`（状态数值比较，如 `gold < 0`）/ `tag`（某标签活跃，如 `char:王二` 在场）。
  - 动作 `then`：`ban`（禁词）/ `tag`（设/解锁标签）/ `ending`（触发 `showGameOver`）。
  - **不在 v1**：`then: deny`（阻止动作，需先建动作总线）、`when: event`（叙事事件匹配）——避免画饼。
- **解释器**：`worldview.js` 新增 `evaluateRules(world, gameState)`，输出 `{bannedConcepts, tagOps, endings}`；`getBannedConceptRules` 优先 DSL、回退 `bannedConcepts`（默认世界继续工作，零破坏）；`processTurn` 应用状态变更后调 `evaluateRules`，`endings` 非空则 `showGameOver`。
- **UI**：世界详情弹窗加「世界规则」按钮 → `openRuleEditor` 纯下拉+填空表单；老世界「一键把禁用词表转规则」按钮（非自动、可取消）。
- **验证**：`npm run verify` 全过（测试 **50/50** 含新增 11 项 DSL 单测 + 浏览器烟雾 3 连跑绿）；默认世界（仅 `bannedConcepts`）现代科技词仍被正确拦截。

### Phase 3 — IP 抽取 NER 增强 + Critic 审稿人（✅ 2026-07-20）
- **现状修正**：核对磁盘发现"NER 建知识库"在 Plan A 已大半落地（`generateWorld` 分块 LLM 抽取已存在），故 Phase 3 实际补两块：
  1. **Critic 审稿人（全新，`src/critic.js`）**：世界生成后自动（及手动「🤖 审稿检查」）用第二个 LLM 通读整库，查矛盾/冲突/悬空链接/违反 Phase 2 硬规则/重复条目，产出 diff，直接复用 `lore-revision.js` 的确认台（采纳/忽略）。
  2. **NER 增强（加法）**：抽取提示词追加实体关系三元组 `relations:[{from,relation,to}]`（图谱地基，Phase 4 用）；给已有世界加「📥 从源文档补抽」按钮（`extractLoreFromSource` 公共函数 + `mergeLoreSnippets` 并入，只 enrich `lore_kb`）。
- **验证**：`npm run verify` 全过（**56/56** 含新增 `test/critic.test.js` 6 项）；relations 合并与矛盾修订单测覆盖。

### Phase 4 — 知识库升级为 KG（✅ 2026-07-20，UI 增强 v1 + RAG 图遍历 v2）

## 四、架构演进经验教训（给黎总看）

1. **大改动先出方案文档 → 确认范围 → 才动代码**：Phase 0-7、UI-1~5、A3、ANN 持久化、错误处理、STYLE_GUIDE 全部遵守（docs/21 第 56 行）。任何未授权文件不动。
2. **循环依赖是隐性雷**：2026-07-27 清零 4 组（utils↔game / game↔render / llm↔game / rag↔prompt）——死导入直接删；`getWorldLoreKB` 移入 store；`abortCurrentRequest` 移入 turn-lifecycle 依赖注入。
3. **验证必须分层**：`node --check`（单文件语法）≠ 跨模块 link；静态三查 + 真实 ESM 加载 + 浏览器烟雾缺一不可。
4. **巨型模块要拆**：`lore-ui.js` 2039 行按机械搬移三分（核心面板/lore-graph-ui/lore-editors），`processTurn` 306 行拆 6 阶段函数——拆时顺带抓出 2 个生产 bug。
5. **持久化要"内容指纹"而非"版本号"**：ANN 索引用 `fp=FNV-1a(snippets…)` 命名，编辑即自动失效重建，省去显式删文件逻辑（见《开发状态与审计手册》3.2）。
6. **降级永远在**：ANN 失败→O(n) 暴力；索引同步失败→内存索引仍可用 + rag O(n) 兜底；工具调用失败→`parseResponse` 兜底。任何新依赖必须有 fallback，零数据风险。
7. **不兼容旧档前提要动态修正**：原"不兼容旧存档"规划，在时间系统重构后反加强旧档兼容——文档与代码冲突时以代码为准（见《开发状态与审计手册》第五节）。
