# 23 · 彻底移除「季节」机制

## 背景与决策

用户（黎总）拍板：**彻底移除时间设定里的「季节」概念**。
动机：季节是最容易和"具体时间（起始日期月日 / 历法）"打架的维度，移除后从源头消除一类时间冲突，且作者设定时少一个要对齐的字段。

本方案属于时间系统相关改动，遵循项目规矩：**先出方案文档 → 用户确认范围 → 才动代码**。本文即方案文档，待用户亲口说"做"后执行。

## 移除目标

- 数据模型不再有 `time_config.season` 字段
- 编辑卡不再有"季节"输入框
- 顶栏"纪元·季节·日期·时刻"不再显示季节
- 喂给 AI 的提示词不再含"当前季节"
- 开场白占位符 `{season}` 不再支持
- 冲突检测 `detectTimeConflict` 不再含季节维度（仅保留年份 + 现代措辞）

## 旧档兼容策略（按用户要求：不做专门兼容）

- **不在加载/迁移流程写任何为旧档服务的兼容或清洗代码。**
- `normalizeTimeConfig` 改为不再读取 `season` → 旧档 `time_config` 里残留的 `season` 字段被自然忽略，加载不崩，旧世界照常运行，只是不再显示/使用该字段。
- 旧存档若开场白文本里写死含 `{season}` 占位符，按下方「占位符处理」静默清空（属占位符函数的通用默认行为，非专门迁移代码）。

## `{season}` 占位符处理

- `resolveOpeningTokens` 从 `OPENING_TOKENS_RE` 和 switch 中彻底移除 `season`。
- 占位符展开的 `default` 分支由 `return m`（原样保留未知 token）改为 `return ""`（静默清空未知/已移除 token）。已知 token（`era_label`/`calendar_date` 等）各自 case 已显式 return，不受影响；非 dated 模式下 `calendar_date` 等仍按原 case 保留原文。
- 效果：旧档开场白残留的 `{season}` 静默消失、不显示怪字符；这是占位符函数的通用行为，不是为旧档写的专门迁移代码（符合"不兼容旧档"要求）。

## 影响评估 / 风险

- **正向**：设定更简单（少一个字段），消除一类时间冲突，编辑卡更清爽。
- **负向**：失去"当前季节"的氛围提示（如"深冬""盛夏"）。文字游戏的氛围可由开场白/系统提示的措辞自带，不强依赖系统字段。
- **风险**：`llm.js` 多处 AI 开场白/审稿模板含 `{season}`，须逐一改干净，否则生成的开场白会残留 `{season}` 字样——已列入清单，验证时重点查。
- **可逆性**：纯删除，git 提交后可回退（SourceTree 里 revert 该提交即可）。
