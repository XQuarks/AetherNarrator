## 三、数据结构（落点）

### UI-3 `sync_rules`（每条时间线可选）
```js
// time_config.timelines[id]
{
  ...,
  sync_rules: [                 // 可选；本线推进 N 日 → 按 ratio 同步 ref 线
    { ref: "earth", ratio: 365 } // 例：异界(xianxia) 1 天 = 现实(earth) 365 天
  ]
}
```
- `ratio` 语义：本线推进 **1 个日历日** ⇒ `ref` 线推进 `ratio` 个日历日（ratio 可为小数，如 0.0027 表示反向慢流速）。
- 归一化：`clampTimelineLine` 增加 `sync_rules` 夹紧（ref 必须存在于 `timelines`、ratio 为有限正数、去重）。

### UI-4 默认穿越策略
```js
// 世界级（放 time_config）
time_config.default_timetravel_strategy: "keep" | "reset" | "branch"   // 默认 "keep"
// 可选：每条线覆盖（放 timelines[id]）
timelines[id].timetravel_strategy: "keep" | "reset" | "branch"
```
- `keep` = S1（默认，保留触发记录，不重放）；`reset` = S3（重置回放，等同 `reset_triggers:"all"`）；`branch` = S4（分支隔离）。

### UI-5 `retrigger_policy`（每个事件/截止）
```js
deadline.retrigger_policy = "once"
  | { mode:"repeatable", max_repeats:N, cooldown_steps:M }   // N=0 表示无限
```
- 引擎已支持；UI 只负责写入 + 归一化（复用 `store.js` 现有逻辑）。

### UI-6 分支（引擎已存在，仅 UI 暴露）
```js
gameState.branches = { branch_1: { label, current_date }, ... }
gameState.active_timeline   // 当前所在线/分支
```
- 合并（E-1，可选）：把某分支的 `triggered_event_ids` / `retrigger_state` 并入主线后删除该分支（仅 C 档做）。

## 四、设计

### 4.1 UI-3 流速比同步
- **引擎**：`src/calendar.js` 新增纯函数 `applySyncRules(timelines, sourceId, deltaDays)`：取 `timelines[sourceId].sync_rules`，对每条 `{ref,ratio}` 用 `addCalendar` 推进 `timelines[ref].current_date` 共 `ratio*deltaDays` 日（按 ref 线自身 mode 分派）。新增 `clampSyncRules(tc)` 夹紧。**集成点**：游戏主循环里"活动线推进"之后调用（具体行号实现时定位 multiverse 推进点，预计在 `game.js` 时间推进 / `advanceWorldTime` 调用处）。
- **UI**：在 UI-2 多时间线卡片内，每条线底部加「流速同步」区：下拉选 ref 线 + 数字输入 ratio + "✕"删除；多规则可叠加；卡片内实时显示「本线 1 天 = 参照线 N 天」摘要。纯读写 `schema`，与引擎解耦。

### 4.2 UI-4 默认穿越策略
- **引擎**：`src/triggers.js`（或 `game.js` 时间变更应用处）新增 `resolveTimeTravelStrategy(change, tc, lineId)`：若 `change` 已显式带 `reset_triggers`/`branch` → 尊重指令（最高优先级）；否则回退到 `timelines[lineId].timetravel_strategy` → 再回退 `time_config.default_timetravel_strategy` → 默认 `"keep"`。在逆跳（日历变小）时套用：reset ⇒ 注入 `reset_triggers:"all"`；branch ⇒ 注入 `branch:true`+自动 label。
- **UI**：时间体系卡加「默认时间穿越策略」单选（保留/重置/分支 + 悬浮说明 S1/S3/S4）；多时间线模式下每线卡片也可覆盖（复用 4.1 卡片布局）。

### 4.3 UI-5 retrigger_policy 编辑器
- **UI**：`src/lore-editors.js` 的事件/截止编辑区加「重触发策略」段：单选「一次性(once)」/「可重复(repeatable)」；选可重复时展开「最大次数(max_repeats，0=无限)」「冷却步数(cooldown_steps)」。写回 `deadline.retrigger_policy`，保存时走 `store.js` 现有归一化。加实时摘要「每 N 步可重复，冷却 M 步」。
- **引擎**：无需改（已消费）。

### 4.4 UI-6 分支回溯/合并面板
- **UI**：游戏界面"时间"区（或世界设置）加「分支管理」面板：列出 `gameState.branches` + 当前线，每条「切换到此分支」按钮（调 `game.js::switchBranch`）；C 档加「合并回主线」按钮（调新增 `mergeBranch(state, branchId)`）。
- **引擎**：`switchBranch` 已存在；C 档在 `triggers.js` 加 `mergeBranch`（并入触发记录后删除分支）。

### 4.5 T-2 玩法说明书（用户向文档）
- 新建 `docs/时间系统玩法说明书.md`（或并入《UI界面参考手册》）：面向非技术作者，含示例——真实起点写法、大跳跃（addYears/addMonths）、逆跳/重置/分支的 LLM 指令写法（`reset_triggers`/`branch`/`sync_rules`），多世界双界写法。纯文档，不碰代码。
