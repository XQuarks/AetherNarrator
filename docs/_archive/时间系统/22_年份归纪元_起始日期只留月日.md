# 方案 22：年份归纪元 + 柔性起始日期 + 日期校验层（架构方案 X · v2）

> ⚠️ 过时说明：本文档「季节冲突、现代措辞检查不变」等涉及季节的描述已失效——季节机制已于 **方案 23（docs/23_彻底移除季节机制.md）** 彻底移除，冲突检测仅保留年份 + 现代措辞维度。

> 状态：待用户最终确认范围（确认后才动代码）
> 前置：时间系统解耦 Phase 0–6 已完成（docs/20、docs/21）。本方案是 Phase 7 的延续，解决克苏鲁等「年代模糊」世界误报「时间可能冲突」，并支持起始日期任意颗粒度 + 真实日历下的日期合法性校验。

## 〇、已确认的设计决策（用户拍板）

| 项 | 决策 |
|---|---|
| 分隔符 | 顶栏用中点 `·`：`1920年代 · 2月2日` |
| 年份容错 | 同 decade 互通（1920 与 1926 不算冲突） |
| AI 引导 | 生成世界时引导 AI：年代写 `era_label`、不写 `calendar_start.year` |
| 起始日期颗粒度 | 年/月/日**各字段独立可选**；缺失部分不显示，内部按默认补齐 |
| 日期校验 | **运行时校验 + 警告 + 明显错误自动纠正** |
| 农历闰月 | 引擎只做**基础范围校验**（月份在表内、日期不超当月天数）；闰月正确性靠 AI 保证 + 提示，不写完整农历算法 |

---

## 一、根因（为什么现在一直冲突）

克苏鲁预设里「年份」被**建模在两处、互相抢**：

- `era_label`（界面「纪元/年份」）= `"1920年代"` —— 天然模糊
- `calendar_start.year`（起始日期的「年」）= `1926` —— 硬年份

S5-4 冲突检查把扫描到的四位数年份和 `calendar_start.year` 做**严格相等**比对，且扫描文本包含 `era_label`。于是「1920**年代**」里的 1920 被当硬年份，发现 ≠1926 → 误报。AI 生成时也会在 system_prompt 写「1920年代」，同样触发。

**结论**：年份不该同时存在于「纪元」和「起始日期」。方案 X = 让 `era_label` 成为唯一「年/纪元」载体，`calendar_start` 退化为纯月日（且各字段可空）。

---

## 二、目标

1. 起始日期的「年」输入框**彻底移除**；年/月/日**各自可空**，支持「年+月+日 / 月+日 / 只月 / 全空」四种粒度。
2. 显示自动拼成 `1920年代 · 2月2日 · 深冬`（纪元来自 `era_label`，日期只显示存在的部分）。
3. 冲突检查改用 `era_label` 作年份/年代锚点（同 decade 容错），不再有两个字段对不上。
4. 新增**日期校验层**：填了非法日期（平年 2月29、月份/日期超范围、农历月份超表）立即红字提示；明显错误自动纠正并提示。
5. AI 生成世界时引导填合法日期；生成后跑一次校验，必要时自动纠正。
6. 克苏鲁误报消除；任何「年代模糊」或「不想写具体年」的世界都能灵活配置。
7. **向后兼容**：仍解析 `calendar_start.year`（双世界「现实线 2003」等继续可用），不破坏旧档与现有预设。

## 三、核心设计

### 3.1 数据形态
- `time_config.calendar_start`（dated 模式）= `{ year?, month?, date? }`，**各字段独立可选**；day/none 仍为 `null`。
- `time_config.era_label` = 唯一「年/纪元」载体：`"1920年代"` / `"1926"` / `"大清乾隆年间"`。
- 内部锚点年（仅机制用，不单独显示）：开局由 `era_label` 解析得到，写入 `current_date.year`，随剧情演进。

### 3.2 锚点年解析（新增 `deriveAnchorYear(era_label)`，`src/utils.js` 或 `src/calendar.js`）
- `"1920年代"` → `1920`；`"1926"` / `"1926年"` → `1926`；无可解析年份 → `null`（机制兜底 `1`）。

### 3.3 冲突检查重构（`src/utils.js` `detectTimeConflict`，L290）
- **锚点来源改为 `era_label`**：解析 `anchorYear`（硬年）或 `anchorDecade`（年代）。
- **扫描范围去掉 `era_label` 本身**（现为锚点来源）；只扫 `opening_narrative` + `system_prompt`。
- **比对（同 decade 容错）**：剧情硬年份与锚点同 decade（`floor(y/10)` 相等）即不冲突；锚点为空则跳过年份比对。
- 季节冲突、现代措辞检查**不变**。
- 效果：克苏鲁 `era_label="1920年代"`（decade 192），system_prompt「1920年代」→1920 通过；不再误报。

### 3.4 显示层（按"存在的字段"拼，不单独露年）
- `src/theme.js` `formatDateOnly`：年无关模式（`calendar_start.year == null`）传 `showYear=false`；且只拼 `calendar_start` 中存在的 month/date。
- `src/calendar.js` `formatCalendarDate`（L126）：支持 `showYear=false` → gregorian `${m}月${d}日`；若仅 `month` 存在则 `${m}月`；若月日皆无则返回空（由 `formatWorldTime` 的 `era_label` 前缀兜底）。
- `formatWorldTime`（L160）已前缀 `era_label`，最终呈现如 `1920年代 · 2月 · 深冬` 或 `1920年代 · 2月2日 · 深冬`。
- `formatDeadlineLabel`（L41）同样按存在字段 + 年无关模式显示。

### 3.5 机制层容错（`src/calendar.js` + `src/time-engine.js`）
- `ensureCurrentDate`（L180）/ `backfillCurrentDate`（L203）：dated 模式若 `calendar_start` 缺字段，用**默认补齐**（缺月→1、缺日→1、缺年→`deriveAnchorYear(era_label) ?? 1`），保证 `current_date` 形状完整、推进不崩。
- `advanceWorldTime`（L106）/ `collectDueDeadlines`（L150）：兼容 `calendar_start` 无 year；截止日期（dated）约定不写 year，仅 `{month, date, period}`，比较时 year 缺省回落锚点年（等价于按年月日、忽略跨年）。

### 3.6 引用点审计
- `src/utils.js` `buildCriticTimeContext`（L360）：纪元读 `era_label`，起始只显存在的月日。
- `src/prompt.js` `buildAuthoritativeTime`（S5-6）：权威锚点改 `era_label`（年代/硬年）+ `calendar_start` 月日，去 `calendar_start.year` 硬依赖。
- `src/llm.js`（L1065 / L1127 用 `tc.calendar_start`）：改 `deriveAnchorYear(era_label)` 取锚点年，避免 `undefined.year`。

### 3.7 预设调整（`src/new-worlds.js`）
- 克苏鲁：`calendar_start` 改为 `{ month: 2, date: 2 }`（去 year）；`era_label` 保留 `"1920年代"`；两目标 `deadline` 去 year（仅 `{month, date, period}`）；`current_date` 去 year。
- 双世界：现实线保留 `year:2003`（硬年仍支持）；异界线可按年代风格去 year。

### 3.8 编辑 UI（`src/lore-ui.js`）
- `renderTimeConfigSection`（L97）：移除「年」输入框，只留 月/日；提示文案「仅 dated 历法生效；各字段可空，缺失部分不显示、按纪元推算年份」。
- `readCalendarStartFromDOM`（L238）：写回 `{ year?, month?, date? }`（只写非空的）；并调用 3.9 的 `validateStartDate` 做即时校验/纠正。
- 新增校验提示位 `#startDateWarn`（红字），input 时实时刷新（仿 `#timeConflictBadge` 的委托，不丢焦点）。

### 3.9 日期校验层（新增 `validateStartDate(cs, mode, era_label)`，建议放 `src/calendar.js`）
返回 `{ valid, warnings[], corrected }`（`corrected` 为可安全纠正后的 `calendar_start`）。
- **公历（gregorian）**：
  - 月份 `1–12`，否则 clamp 到边界并警告。
  - 日期不超当月最大天数；2 月：若 `year` 已知且非闰年且 `date=29` → **自动纠正为 28** 并警告「X年非闰年，已纠正为2月28日」；若 `year` 缺失（年无关）→ **不纠正**，警告「2月29日需闰年，请确认纪元对应年份；当前按2月29保留」。
  - 其他月份越界 → clamp 到当月最大并警告。
- **农历 / 自定义历法（lunar / custom_calendar）**：
  - `month` 须在 `months` 表长度内，否则 clamp + 警告。
  - `date` 不超该月 `days`，否则 clamp + 警告。
  - **闰月正确性（哪年有闰X月、闰月几天）不在此精确计算**——仅做基础范围校验；若 `era_label`/备注提示涉及闰月，交由 AI 保证，并在 UI 提示「农历闰月请确认该农历年确实存在」。
- 仅做**可安全纠正**的自动纠正（clamp、平年2月29→28）；涉及年份语义不确定（年无关下的2月29）只警告不擅自改。

### 3.10 AI 生成引导 + 生成后校验
- **生成 prompt（`src/new-worlds.js` / `src/llm.js` 世界生成段）**加约束：
  - 年代/年份写 `era_label`（如「1920年代」），**不要**写 `calendar_start.year`；
  - 如填具体 `month`/`date`，须符合所选历法：公历注意闰年 2月29、各月天数；农历月份须在表内、日期不超当月天数；涉及闰月需确认该农历年存在。
- **生成后**：对 AI 产出的 `calendar_start` 跑一次 `validateStartDate`；若 `corrected` 与原始不同 → 应用纠正并在进游戏 toast 提示「起始日期已自动纠正：…」。

## 六、风险与兼容

- **旧档**：仍带 `calendar_start.year` 的世界（双世界现实线）继续硬年逻辑；`normalizeTimeConfig` 保留 year 解析，零破坏。
- **AI 生成**：生成器若填了 `calendar_start.year` 仍兼容；已加 prompt 引导优先用 `era_label`。
- **显示回归**：年无关/部分字段世界不再显示具体年，符合「年代模糊」语义；需要硬年的世界继续显示。
- **农历闰月**：明确不做完整算法，靠 AI + 提示，避免高成本与潜在错误。
- **范围可控**：纯时间系统内部重构，不碰知识库/剧情/RAG 引擎。
