## 1. 核心结论（两文合一）

- **文档25 的核心**：把「玩家偏好」从自由文本变成**结构化标签**，让 AI 在创作和运行时都稳定执行（这个我们已经在 `docs/24`/`docs/26` 用 `{STYLE_GUIDE}` 部分落地了）。
- **文档27 的核心**：把「世界」从一段自由文本变成**可配置、可展示、可追溯的叙事容器**（人物卡、变量、时间线、手记），让 AI 在容器里写故事，而不是每轮从零编。
- **合一的结论**：竞品真正的价值 = **「创作阶段的引导」+「游玩阶段的结构」两段式**。AetherNarrator 当前是「即开即玩、自由生成」很强，但要补两层：
  1. **建世界前的结构化引导**（题材/主题/口味/视角/文风/IP检测/完成度清单）；
  2. **游玩中的结构化容器**（人物卡/变量/背包/羁绊/时间线/手记/模块开关）。

## 2. 竞品完整流程还原（建世界前 → 游玩中）

```
【阶段 A：创作前引导】
  选模式（文游/小说）
    → 填世界观 + 选标签：题材 / 主题 / 阅读口味 / 叙事视角 / 叙事风格
    → 打勾「检测到相关作品时增强设定一致性」(IP 检测)

【阶段 B：作者工作台】
  创作完成度清单：标题 / 世界观 / 开场场景 / ≥1角色 / 游玩系统 / 重要事件 / 结局
    → AI 生成：世界观 → 角色 → 时间线 → 升级体系 → 写作约束
    → 玩家逐项编辑（角色卡、世界题库、约束面板、开场）
    → 七项齐了才能「游玩」

【阶段 C：游玩中的结构】
  人物卡 / 属性面板 / 能力目录（带代价）
  背包 / 物品分类（关键物品高亮）
  羁绊 / 好感度（关系标签 + 数值）
  状态面板 / 本回合变化（获得/失去、状态增减）
  日程（玩家自埋伏笔） / 章节化回溯 / 手记（我的故事）
  模块化世界编辑器（模块开关、玩家变量、角色卡字段、物品分类）
  三栏桌面 UI / 单列手机 UI / 玩家备注 + 分支预测
```

**本质差异**：竞品用「强制清单 + 分段编辑 + 字段化容器」保证世界完整、叙事一致；AetherNarrator 用「即时游玩」降低门槛，但牺牲了部分创作时的结构和游玩时的可见性。借鉴时**不要照搬强制阻塞**，而是取「结构化标签 + 字段化容器 + 玩家可见的时间线」这三座桥。

## 3. 统一借鉴清单（去重后，按阶段 + 优先级）

> 去重说明：文档25 的「⑤角色卡」与文档27 的「①人物卡」合并；文档25 的「④时间线预埋」与文档27 的「④日程/回溯/手记」合并；文档25 的「①文风标签」与文档27 的「⑧文风设置」合并；文档25 的「⑥升级体系」与文档27 的「④能力目录」合并为「能力/养成（可选模块）」。

### A. 创作前引导（解决「世界怎么建得完整、文风怎么一致」）

| # | 借鉴点 | 优先级 | 对叙事的帮助 | 和现有系统的结合点 |
|---|---|---|---|---|
| A1 | **结构化偏好标签**：题材 / 主题 / 口味 / 视角 / 文风 | ★★★★★ | 直接解决文风一致性——标签不是自由文本，可一一映射 `{STYLE_GUIDE}`，比 `styleRef/customStyle` 更细、小白更会用 | 复用已落地的 `world.style_profile` + `prompt.js` 注入，**零改动衔接（已于 A1 落地）** |
| A2 | **IP 检测增强一致性** | ★★★★☆ | 提 HP/克苏鲁等关键词自动加载一致性包（禁项/必读设定/文风锚点），对哈利波特模拟器是刚需 | 复用 `DEFAULT_BANNED_CONCEPTS` + 世界知识库；命中加 `is_ip_adaptation` 标志 |
| A3 | **轻量创作完成度清单** | ★★★★☆ | 保证世界「叙事上站得住」（主角有动机、有 NPC、有方向），但不强制阻塞 | 在世界详情页加进度卡，复用已重构的详情页，不新增数据模型 | ✅ **已落地（2026-07-28）**：`src/utils.js::computeWorldCompletion` 纯函数从 `world` 现字段派生 7 维度（标题/世界观/开场/≥1角色/游玩系统=rules/重要事件=lore_kb 带 trigger 片段/主角设定=hero），`render.js::showWorldDetail` 概览顶部注入 `.completion-card`（进度条+评级+✓/○ 维度），不阻塞游玩、不新增数据模型；`test/36-world-completion.test.js`（6 项）全绿 |

### B. 游玩中结构（解决「故事怎么保持一致、选择有后果」）

| # | 借鉴点 | 优先级 | 对叙事的帮助 | 和现有系统的结合点 |
|---|---|---|---|---|
| B1 | **人物卡（主角 + NPC）**：身份/动机/关系/声音标签/不可触碰设定 | ★★★★★ | 让 AI 每轮**强制读取**角色，不再从 lore 文本里「回忆」；关系描述本身就是故事状态 | 写入 `world.characters`；注入 `buildHeroContext` / `buildTurnUserMessage` 的 NPC 关系段 |
| B2 | **玩家变量 + 本回合变化** | ★★★★★ | 选择后果可视化，状态（理智/体力/金钱）成为叙事压力源 | 接 `S.gameState`；变化展示接 `buildAuthorNote`；状态影响选项可用性 |
| B3 | **背包 / 物品**：分类 + 关键物品标签 | ★★★★☆ | 物品成为叙事道具，可反复进选项；关键物品进手记时间线 | `S.gameState.inventory`；选项生成时优先给「使用 X」 |
| B4 | **羁绊 / 好感度**：关系标签 + 数值 + 描述 | ★★★★☆ | 玩家清楚「我和这人什么关系」，AI 有对话锚点；关系驱动选项 | NPC 卡加 `relationship` 字段；跑团自由输入世界里关系是核心驱动力 |
| B5 | **时间线 / 日程 / 章节化回溯 + 手记** | ★★★★☆ | 日程=玩家自埋伏笔；回溯=按章节重来而非按轮；手记=把离散选择串成「我的故事」 | 复用 `calendar.js`（日程）+ `triggers`（必然事件/条件事件）+ `behavior_records`（手记） |（属"时间线/回溯/分支需求族"，与 doc 21 世界内时间机制、doc 20 P1-1 记忆可视化见 docs/38 §六 统一追踪）

### C. 世界规则层（解决「AI 不乱加系统」）

| # | 借鉴点 | 优先级 | 对叙事的帮助 | 和现有系统的结合点 |
|---|---|---|---|---|
| C1 | **模块化世界开关** `modules` | ★★★★☆ | 明确这个世界有没有任务/经济/地图，减少 AI 乱加系统 | 世界配置加 `modules` 开关，进入 system prompt 约束 AI |
| C2 | **能力目录 / 升级体系（带代价，可选）** | ★★★☆☆ | 能力选择本身产生剧情张力（每次使用 +1 疯狂值） | 世界编辑器加 `ability_catalog`；修仙/系统流开启，日常/悬疑关闭 |
| C3 | **响应式 UI（三栏桌面 / 单列手机）** | ★★★☆☆ | 信息密度提升，状态/场景/羁绊做成可切换面板 | 不改引擎，加侧边/底栏面板；选项可带消耗 |
| C4 | **玩家备注 + 分支预测** | ★★★☆☆ | 玩家给存档写私有提示（「希望主角更谨慎」）补进每轮；分支预测降低选择焦虑 | `S.gameState.player_note` 注入 author note；选项 hover 显示后果 |

## 6. 需要谨慎的地方（两文档合并提示）

- **不要照搬所有模块**：AetherNarrator 核心是「低门槛、任意 IP 模拟」。如果创作者必须配 10 个模块才能开始，会劝退。模块应有**默认值**，开箱即用。
- **数值不要喧宾夺主**：克苏鲁世界里「理智」重要，但日常恋爱世界里数值会稀释叙事。变量/模块应**可选启用**。
- **AI 仍要会写故事**：结构是容器，不是替代。人物卡太死会写出「填表式」叙事，要保留「自由文本」字段让 AI 发挥。
- **升级体系 / 双模式影响核心自由叙事**，谨慎上，避免把轻题材世界绑成数值游戏。

---

## 7. 一句话总结

竞品给 AetherNarrator 的最大启发，是**把「玩家偏好」和「世界」都从自由文本，变成结构化、可展示、可追溯的容器**——上半球（文档25）用标签锁死文风与 IP 一致性，下半球（文档27）用人物卡/变量/时间线/手记让故事保持一致、让选择有后果。两者合并后，建议从 **A1 标签 + B1 人物卡 + B2 玩家变量** 这三件套起步，它们复用现有 `style_profile` / `world` / `gameState` 设施，收益最高、风险最低。
