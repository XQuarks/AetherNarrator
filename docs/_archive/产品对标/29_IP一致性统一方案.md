## 0. 背景与问题：为什么用户觉得"重复繁琐"

黎总在原项目里观察到，玩家建一个世界时有**四条看似并行**的能力：

1. **原创生成**：不填任何 IP，纯靠世界描述让 AI 自由发挥。
2. **输作品名做 IP**：建世界卡里选 `type=ip` 并填 `ip_name`（如"哈利波特模拟器"）。
3. **上传文本源文件**：上传 TXT/DOCX/EPUB，文本进知识库当素材。
4. **A2 IP 检测增强一致性**：规划中——自动识别 IP 并加载"一致性包"防止 AI 偏离原著。

四者在 UI 上是分散的入口，在代码里也是各自零散处理"这是不是某个 IP"。
**根因**：缺少一个统一的"这部作品的权威设定到底是什么"模型，导致"原创 / 输 IP 名 / 传源文件"各管各的 IP 属性，A2 若再做成独立"第四条路径"会更乱。

**本方案目标**：不增加第 4 条平行路径，而是把前三条**统一**到一个模型里；A2 降级成这个模型内部的一个"建议器"。

## 1. 代码现状核查（诚实基线，避免空谈）

经核对 `src/` 真实代码：

- **A2 实际未实现**：`docs/25`、`docs/28` 把 A2 列为"待做"，代码里确实没有。
- **真实载体**：IP 身份只靠 `world.type`（`original`/`ip`）+ `world.ip_name` 文本框
  （`index.html` 世界卡；`game.js:92-95,162-165` 读取）。
- **无自动 IP 检测函数**：只有 `isMagicSchool` / `horrorWords` 这类正则，用于推断"文风/题材标签"，**不是 IP 识别**。
- **无 per-IP 一致性包**：克苏鲁的"禁现代科技"是**写死在 `new-worlds.js` 的开场 system_prompt 文案**里的，没走结构化的 `bannedConcepts` 字段（该字段从没被赋值）。
- **上传源不携带元信息**：`S.sourceFileContent` 只是一段纯文本，不记录"这是原创 / 某 IP 改稿 / 某 IP 原文"。
- **全局禁项**：`store.js` 的 `DEFAULT_BANNED_CONCEPTS`（禁手机/电脑等）对所有世界一视同仁，不分 IP。

> 结论：当前"是不是 IP、怎么保持一致"全靠用户手动填 `type`/`ip_name`，没有任何自动识别与结构化约束。

## 2. 关键澄清：系统能做什么、不能做什么（诚实边界，重要）

黎总尖锐提问：**"系统怎么确认上传的是原文还是改过的？AI 数据库里有别人小说原文吗？"**
这直接决定了方案的天花板。诚实回答：

| 问题 | 答案 |
|---|---|
| 本地应用里有"别人小说原文"吗？ | **没有**。知识库（`lore_kb`）只装用户自己上传的内容；`models/` 仅一个约 880KB 的中文向量模型，无任何小说。本地不存在"小说库"。 |
| 云端大模型有逐字版权小说副本吗？ | **没有可靠的**。LLM 对《哈利波特》《克苏鲁》这类超级知名作品"知道"大概世界观/角色（训练语料讨论多），但**没有逐字完整版权副本**，更无法可靠比对"是否原样抄自某章"。它的"记忆"是统计模式，不是字典。 |
| 能自动判定"上传的是原文 vs 改稿"吗？ | **做不到，也不该做**。① 无原文可比对；② 逐字比对版权文本本身是敏感动作，工具不应扮演"版权警察"。 |

**因此方案划清一条红线：**

- ❌ **不**做"自动识别原文 / 改稿 / 同人"的分类（那是过度承诺，不可行）。
- ✅ **只**做"识别**这是哪个 IP**"——用轻量关键词启发式（霍格沃茨→HP、克苏鲁→Cthulhu、巫师/魁地奇→HP）。这是模式匹配，不是比对版权库，诚实可行、不踩红线。
- ✅ **版权边界**：工具不验证、不存储、不比对版权原文；用户对自身上传内容负责；工具只帮 AI 在用户**声明的** IP 框架内保持一致。

## 3. 用户操作全量枚举（12 种组合）

把"建世界时用户所有可能的操作"拆成维度穷举。注意：**冲突的本质是"用户用不同方式（填名 / 上传 / 描述带词）表达了不一致的 IP 身份"**，这正是本方案要协调的。

| # | 用户实际做法 | type / ip_name / 上传 | 当前代码行为 | 问题 |
|---|---|---|---|---|
| 1 | 纯原创，写描述 | original / 空 / 无 | AI 按描述生成，无约束 | ✅ 正常 |
| 2 | 填 IP 名（如"哈利波特"），无原文 | ip / 哈利波特 / 无 | prompt 写"从训练数据找该作品"，**无一致性包** | ⚠️ AI 可能偏离原著 |
| 3 | 上传自己原创稿，不开 IP | original / 空 / 原创稿 | 稿子进知识库当素材 | ✅ 正常 |
| 4 | 上传自己原创稿，**却填了 IP 名** | ip / X / 原创稿 | 既当 IP 改编、又拿原创稿当素材 | ❌ 语义冲突，应提示 |
| 5 | 上传"别的 IP 改稿"+ 填该 IP 名 | ip / X / 改稿 | 当 IP 改编，稿子进知识库 | ⚠️ 应加载 X 包防偏离（当前没加载） |
| 6 | 上传"别的 IP 改稿"，**没填 IP 名** | original / 空 / 改稿 | 当原创自由处理 | ❌ 高风险：改了 IP 却无一致性约束 |
| 7 | 上传某 IP 原文 + 填该 IP 名 | ip / X / 原文 | 当 IP 改编，原文进知识库 | ✅ 干净，但包仍没加载 |
| 8 | 上传某 IP 原文，**没填 IP 名** | original / 空 / 原文 | 当原创处理 | ⚠️ 应靠检测识别并提示（未实现） |
| 9 | 填 IP 名 A + 上传无关文本 B | ip / A / B | A 当 IP，B 当素材 | ❌ 冲突，应提示二选一 |
| 10 | 描述里写了"霍格沃茨"，啥都没填 | original / 空 / 无 | 当原创处理 | ⚠️ A2 应提示"检测到 HP，加载包？"（未实现） |
| 11 | 描述写 HP + 填了**别的** IP 名 | ip / Y / 无 | 用 Y 当 IP | ❌ 检测 X≠Y，冲突，应提示 |
| 12 | 描述写 HP + 上传另一 IP 原文 | original / 空 / Z原文 | 当原创 | ❌ 多重冲突 |

> **修正说明（回应黎总质疑）**：上表早年草案曾把"上传文本性质"写成系统可自动识别的 `original/derivative/canonical`。**已撤销该暗示**——系统识别不了这个。若该信息要保留，只能是**用户自述标签**（上传时手动选），且明确它**不参与一致性逻辑**，仅作个人整理备注；用户不想标时干脆不设这个字段。**一致性真相来源 = 用户上传文本（优先）/ 世界描述**，一致性包由 AI 从源文本**动态生成**；`detectIp()` 仅作辅助（打 IP 标签 + 知名 IP 种子包），不凌驾于源文本（黎总拍板 Q1）。

## 4. 统一设计：`world.canon` 模型

把"IP 身份 + 一致性约束"收敛成一个字段，让"输 IP 名 / 传源文件 / A2 检测"都只是往里**填信息的三种方式**。

```js
world.canon = {
  mode: "original" | "ip_adaptation",   // 是否 IP 改编
  ip_name: string | null,               // 哪个 IP（用户填 或 detectIp 建议）
  source: "none" | "description" | "uploaded_text",
  // 注：上传文本"是原创/改稿/原文"不在模型里做自动判定。
  //     若未来加可选自述标签，仅为用户备注，不参与一致性逻辑：
  upload_kind_self_label: "original" | "ip_derivative" | "ip_canonical" | null,
  key_divergences: string,              // 用户声明的关键性修改（黎总拍板：做）
  consistency_pack: {                    // 一致性包（见第 5、6 节）：动态生成，非静态注册表
    banned: [],          // 禁项（如 HP：不得出现麻瓜科技碾压魔法）
    must_read: [],       // 必读设定（锚定核心世界观）
    style_anchor: ""     // 文风锚点
  } | null,
  pack_source: "generated" | "seed_cache" | null  // 包来源：AI 从源文本生成 / 知名IP种子缓存
}
```

**优先级铁律（注入 system prompt 时务必遵守）**：

```
用户上传文本 + 用户声明的 key_divergences  ＞  consistency_pack（禁项/必读）  ＞  LLM 训练时的原著先验
```

即：**用户说改了什么，比"原著该怎样"算数。** 一致性包只是"兜底风格锚点"，不是高于用户的圣旨。

> **黎总决策（Q1）**：用户上传的原文/改稿是**第一真相来源**——既喂给 AI 当游戏素材，也作为生成一致性包的原料；`detectIp()` 仅作**辅助**（给世界打 IP 标签、对知名 IP 提供种子包），不凌驾于上传文本之上。

## 5. 协调器 `resolveCanonContext()` + `detectIp()` 建议器

建世界时只调一次 `resolveCanonContext({type, ipName, desc, sourceFileContent})`，它负责：

1. **以源文本为真相**：有上传文本用上传文本，无则用世界描述（`world.canon.source`）。它是生成一致性包的原料，也是 AI 每回合读取的素材——二者同源，天然一致。
2. **跑 `detectIp()`**（A2 检测，新增，仅辅助）：从描述/文件名/上传文本里识别 IP 关键词，返回候选 IP 列表，用于给世界打 `ip_name` 标签；对知名 IP 可返回**种子包**作为生成起点。
   - 它是**辅助**，不凌驾于上传文本；仅当用户未声明 IP、或声明有冲突时才给建议。
3. **协调三路信号**：用户显式填的 `ip_name` vs `detectIp()` 检测到的 IP vs 上传文本看起来的 IP。
4. **冲突处理**：发现不一致（如 #4/#6/#9/#11/#12）→ 返回冲突列表，UI 弹**一次**确认框让用户拍板（只在真冲突时打扰用户；日常原创/普通上传完全无感、不弹窗）。
5. **生成一致性包**：无冲突 → 调 `generateConsistencyPack(sourceText, ip_name)`（见第 6 节），从源文本**动态生成** `consistency_pack` 写入 `world.canon`。若 IP 为知名 IP 且有种子缓存，可先用种子包再让 AI 基于用户文本微调（可选优化）。

`detectIp()` 示例（轻量正则，不涉及版权比对）：

```js
// 仅做"识别哪个 IP"的模式匹配，绝不存储/比对原文
const IP_KEYWORDS = {
  "哈利波特": ["霍格沃茨", "哈利", "伏地魔", "魁地奇", "魔法部", "麻瓜"],
  "克苏鲁": ["克苏鲁", "深潜者", "旧日支配者", "拉莱耶", "修格斯", "阿卡姆"],
  // ...可扩展
};
```

## 6. 一致性包：动态生成（非静态注册表）

黎总提问："一致性包能在生成世界观的时候同时生成出来吗？"——**能，而且应该。** 不再手工维护"克苏鲁/HP 包"静态注册表，改为建世界时由 AI **从源文本一次性生成**：

- **`generateConsistencyPack(sourceText, ip_name)`**（新增，走 `llm.js` 现有 JSON 抽取通道）：喂入上传文本/世界描述，让 AI 产出
  `{ banned:[...], must_read:[...], style_anchor:"..." }`，写入 `world.canon.consistency_pack`。
- **为什么更好**：
  - 统一性——原创世界、IP 改编、改稿世界**走同一条路**，无需为每个 IP 手写包；
  - 自动解决 divergence——包是从**用户改后的文本**生成的，自然反映用户的版本，不会和原著打架（呼应第 7 节）；
  - 可扩展——任意冷门/原创 IP 都能生成，不依赖人工录入。
- **代价与对策**：多一次建世界时的 LLM 调用（延迟 + 少量成本）→ 可异步生成、"生成中…"提示、提供"重新生成包"按钮；输出需 JSON 解析 + 字段校验（复用 `llm.js` 既有抽取逻辑）。
- **可选优化（非必需）**：对少数超知名 IP 预置"种子包"作起点，AI 再基于用户文本微调；这是缓存不是必需。
- 运行时注入不变：`prompt.js` 新增 `buildCanonRules(world)` 按第 4 节优先级拼入 system prompt；`getBannedConcepts(world)` = 全局 `DEFAULT_BANNED_CONCEPTS` ∪ `consistency_pack.banned`。

> 注：克苏鲁 `new-worlds.js` 里写死的禁律，改为建世界时由 `generateConsistencyPack` 生成（或首个种子缓存命中），不再硬编码。

## 7. 用户关键性修改（divergence）怎么处理

黎总追问："用户对原文做了关键修改、希望 AI 能看出，需要在填世界观时声明吗？"

**答：不用专门搞"声明开关"，两条现有渠道就够：**

1. **上传改好的文本**（最稳）：AI 每回合通过知识库检索读它，等于"用行动声明"。当前版本（A2 未实现）没有包打架，AI 天然跟用户改后的版本走。
2. **在世界描述 / system_prompt 里写关键改动**：例如"本世界基于 HP，但：时间线移到 2025、伏地魔已败、主角为原创角色 XXX"。

**决定做**：`world.canon.key_divergences` 文本框（黎总拍板"做"）——拼进 system prompt，优先级高于生成的一致性包，作为用户手动兜底。非必填，但建议改过关键设定的用户填写。

> 为什么"声明"只在 A2 实现后才有意义：当前没有一致性包去覆盖你的设定，所以上传改稿 + 描述写清，AI 已经 100% 跟你的走。加包之后，包的旧设定才可能和你的改动冲突——此时 `key_divergences` 和"世界描述里的偏离"就是用来压过包的。

## 9. 落地路线图与范围（已拍板）

- 阶段一（先做）：`world.canon` 模型 + `resolveCanonContext` + `detectIp` 辅助建议器 + `generateConsistencyPack` 动态生成包 + `buildCanonRules` 注入 + `key_divergences` 框 + 克苏鲁写死禁律改走生成包。

**黎总已拍板的三项范围**：
1. ✅ **上传文本优先**：用户上传的原文/改稿是真相来源，识别 IP 仅作辅助（打标签/种子包）。
2. ✅ **`key_divergences` 做**：建世界卡加"关键偏离"文本框，拼入 system prompt、优先级高于生成包。
3. ✅ **一致性包改为动态生成**：建世界时由 AI 从源文本一次性生成（非静态注册表）；知名 IP 可选种子缓存加速。
