# 竞品创作流程拆解 & 可借鉴点分析

> 适用对象：黎总（产品/玩法视角）
> 文档目的：拆解另一款 AI 文游/小说创作工具的产品流程，提炼对 AetherNarrator 叙事系统有价值的借鉴点，并标注**哪些可直接加、哪些需要谨慎**。
> 竞品模式：先让玩家填写/选择世界观、题材、爽点、口味、视角、叙事风格 → AI 生成角色/剧情/事件 → 玩家编辑 → 才能游玩。

---

## 1. 竞品在做什么（7 张图信息还原）

| 图 | 核心界面 | 功能要点 |
|---|---|---|
| 1 | 模式选择 + 世界创建入口 | 两种模式：「我想玩文游」/「我想读小说」。下方是世界描述输入框，外加标签化的**题材、爽点、阅读口味、叙事视角、默认叙事风格**。还有「检测到相关作品时增强设定一致性」开关。 |
| 2 | 创作者工作台（概览/故事/游玩/发布） | 顶部四段式标签。故事页是一张**创作进度清单**：标题、世界观、开场场景、至少一名角色、游玩系统（主题/策略/机制）、重要事件、结局。每完成一项打勾。 |
| 3 | 世界与时间线 | 可设置「事件重要事件」作为伏笔注入；另有「原作时间线（作者参考）」用于锚定后续剧情。 |
| 4 | 世界观 + 世界题库 + 升级体系 | 世界观文本、世界题库（lore）、以及**多分支的升级体系树**（如主世界/异界双轨升级）。 |
| 5 | 写作约束 | 显式的硬规则面板，列出 AI 必须遵守的叙事限制（如主角能力、反派、世界观边界）。 |
| 6 | 角色设定 | 结构化角色卡：每个角色有名、标签、关系、动机、阵营色块。 |
| 7 | 开场 | 独立开场文本编辑区，玩家可继续改写。 |

**一句话定位**：这款竞品更像一个**面向轻度作者/玩家的 AI 世界观编辑器**，把「创作」和「游玩」拆成两段；AetherNarrator 目前更像**即开即玩的 AI 文字模拟器**，创作和游玩边界更模糊。

---

## 2. 竞品流程 vs AetherNarrator 流程

```
竞品：
选模式 → 填世界/选题材爽点口味 → AI 生成世界观 → 玩家编辑世界观 →
AI 生成角色/时间线/升级体系/约束 → 玩家编辑 → AI 生成开场 → 玩家编辑 → 游玩

AetherNarrator（当前）：
选世界 → 填写基础信息 + 文风 → AI 生成世界观 + 知识库 → 直接游玩
（知识库可在游玩中编辑，但缺少"创作阶段"的强制清单）
```

**本质差异**：竞品通过**强制清单**和**分段编辑**确保"世界足够完整才能玩"；AetherNarrator 通过**即时游玩**降低门槛，但牺牲了部分创作时的结构性。

---

## 3. 最值得学的 5 个点（按适配性与收益排序）

### ① 创作前偏好结构化：题材 / 爽点 / 口味 / 视角 / 叙事风格（★★★★★）

**竞品做法**：把「题材、爽点、阅读口味、叙事视角、叙事风格」做成标签，生成前直接喂给 AI。例如：题材=克苏鲁、爽点=复仇、口味=暗黑深沉、视角=第二人称、风格=克制写实。

**对 AetherNarrator 的帮助**：
- 直接解决你刚刚问的「文风怎么保持一致」的问题。这些标签不是自由文本，而是**结构化的约束输入**，可以一一映射到提示词里的 `{STYLE_GUIDE}`。
- 比现有 `styleRef` / `customStyle` 更细：玩家不需要"自己写一段 prompt"，而是勾选/组合，降低了代码小白用户的使用门槛。

**建议增加**：
- 在世界创建卡里增加 **题材（genre）**、**爽点/主题（tropes）**、**阅读口味（tone）**、**叙事视角（POV）**、**叙事风格（style）** 五个维度。
- 每个维度提供预置标签（如题材：都市/仙侠/克苏鲁/赛博朋克；爽点：逆袭/复仇/甜宠/系统；口味：爽快/暗黑/治愈/史诗；POV：第一/第二/第三人称；风格：轻松/克制/华丽/冷峻）。
- 标签映射到 `prompt.js` 里的 `STYLE_GUIDE` 注入——这就是我们在 `docs/24_剧情生成提示词优化与文风一致性.md` 里提出的"运行时注入"的具体落地。

**改动量**：小–中。主要改 UI 创建卡 + 数据 schema + 已有的 `{STYLE_GUIDE}` 注入位。

---

### ② IP 检测增强一致性（★★★★☆）

**竞品做法**：一个复选框「检测到相关作品时增强设定一致性」。玩家写「哈利波特」或「克苏鲁」时，系统会主动做一致性约束。

**对 AetherNarrator 的帮助**：
- 你之前提过想做「哈利波特模拟器」——这个功能正好对口。玩家在描述里提到 HP，系统自动加载一套**IP 一致性包**（禁穿越/禁现代科技/霍格沃茨规则、角色声音锚点等）。
- 可以复用现有的 `DEFAULT_BANNED_CONCEPTS` 和世界知识库机制：检测到 IP 关键词后，自动追加该 IP 的禁止项和必读设定。

**建议增加**：
- 在 `world.type` 或描述中做关键词匹配（哈利波特、HP、霍格沃茨、克苏鲁、Cthulhu、赛博朋克 2077、金庸等）。
- 命中后，给该世界加一个隐藏标志 `is_ip_adaptation`，并自动注入：
  - 该 IP 的硬性规则（如 HP 世界不能乱改魔法体系）；
  - 推荐 lore 条目（如霍格沃茨四学院、主要角色）；
  - 文风提示（如 HP 偏英式奇幻、克苏鲁偏压抑疏离）。
- 同时提示玩家：「检测到 HP 设定，已增强一致性，是否引入原著角色/地点？」

**改动量**：小。纯 prompt 层 + 关键词匹配，不碰核心玩法。

---

### ③ 世界创作完成度清单（★★★★☆）

**竞品做法**：「标题、世界观、开场场景、至少一名角色、游玩系统、重要事件、结局」七项 checklist，全部完成才能进入游玩。

**对 AetherNarrator 的帮助**：
- 现在玩家创建完世界直接开玩，容易出现「主角没动机、NPC 没关系、剧情不知道往哪走」的问题。强制清单可以保证世界在叙事上"能站得住"。
- 但 AetherNarrator 主打**即开即玩的模拟器体验**，完全照搬七项会太繁琐，容易劝退。

**建议增加**：
- **做轻量版 checklist**：保留"可玩"最低标准——世界观、开场、至少一名 NPC、主角目标。未完成时给提示但不强制阻拦（或允许「不完整世界试玩」）。
- 在 UI 上做成进度条/小徽章，而不是弹窗阻塞。比如：世界详情页显示「创作完成度 3/4」，点击展开缺哪项。
- 把清单和已有的「世界详情」页结合（你刚重构了世界详情页，正好可以塞一个进度卡）。

**改动量**：小–中。主要是 UI 和校验逻辑，不增加新数据模型。

---

### ④ 显式时间线 + 事件预埋（★★★☆☆）

**竞品做法**：有「事件重要事件」和「原作时间线」两个面板，允许作者提前埋设未来会发生的大事件。

**对 AetherNarrator 的帮助**：
- AetherNarrator 已有 `triggers.js`（触发事件）和 `events` 系统，但缺少**作者可见的时间线编辑器**。玩家现在只能在 lore 里写事件，不够直观。
- 如果能把事件按时间顺序排列，AI 就能更好地做伏笔、节奏控制和前后呼应。

**建议增加**：
- 在世界规则或知识库里增加一个「故事时间线」页签，允许作者添加未来事件：事件名、触发条件（时间/步数/玩家行为）、事件描述。
- 这些事件直接写入 `triggers.js` 的 `triggered_event_ids` / `retrigger_policy` 体系，和已有的时间系统解耦方案兼容。
- 预埋事件可以分两类：
  - **必然事件**：到某一步一定发生（如"第 7 天满月之夜"）；
  - **条件事件**：玩家达成某条件后发生（如"声望达到 50 触发势力邀约"）。

**改动量**：中–高。需要 UI + 数据 schema + 和现有 triggers 的整合。但这是叙事深度的大杀器，值得做。

---

### ⑤ 角色卡 + 关系网（★★★☆☆）

**竞品做法**：每个角色有名、标签、关系、动机、阵营，甚至可以配头像。

**对 AetherNarrator 的帮助**：
- AetherNarrator 的 NPC 是分散在 lore 里的，没有一个统一视图。结构化角色卡能让 AI 更容易保持一致（如"这个 NPC 永远不会背叛"、"这个 NPC 和主角是宿敌"）。
- 也便于玩家在进入游戏前快速把握"要和谁打交道"。

**建议增加**：
- 在知识库/世界详情里增加「角色」页签，每个角色卡包含：
  - 姓名、身份/角色定位（主角/盟友/反派/中立）
  - 核心动机（想要什么）
  - 与主角关系（好感度初始值、关系标签）
  - 声音标签（口语化/正式/冷峻/谄媚）
  - 不可触碰的设定（如"不会透露组织总部"）
- 这些角色卡自动注入到 `buildHeroContext` / `buildTurnUserMessage` 的 NPC 关系段里，取代现在纯文本的 NPC 描述。

**改动量**：中。需要新 UI + 数据 schema + prompt 注入改造。

## 4. 可借鉴但需谨慎的两点

### ⑥ 升级/养成体系树（★★☆☆☆）

**竞品做法**：多分支升级体系（如修仙境界、技能树）。

**建议**：可以做成**可选世界模板**，而不是强制所有世界都有。修仙/系统/玄幻世界开启，日常/悬疑世界关闭。否则会让轻题材世界被 RPG 数值绑架。

**风险**：AetherNarrator 的核心是自由叙事，如果升级体系太复杂，会变成数值游戏，和跑团式自由输入冲突。

---

### ⑦ 文游 vs 小说双模式（★★☆☆☆）

**竞品做法**：明确区分「玩文游」和「读小说」。

**建议**：可以保留，但优先放在**未来规划**。当前先把「玩文游」的体验做扎实。小说模式本质是减少玩家选择频率、让 AI 自动推进，这需要改交互循环和 AI 调用策略，影响面较大。

---

## 5. 推荐落地顺序（不一次梭哈）

按**改动量小、叙事收益高、不破坏现有体验**排序：

1. **创作前偏好结构化（①）**：直接解决文风一致性问题，可复用我们刚写的 `docs/24` 里的 `{STYLE_GUIDE}` 方案。UI 加标签 + 提示词映射即可。
2. **IP 检测增强一致性（②）**：关键词命中 + 自动追加一致性约束，对哈利波特模拟器是刚需。
3. **轻量创作完成度清单（③）**：在世界详情页加一个进度卡，不阻塞游玩，只提醒/引导。
4. **角色卡（⑤）**：先在世界详情/知识库加一页，逐步替代 lore 里的 NPC 文本。
5. **显式时间线（④）**：最后做，因为需要和 triggers 系统深度整合，但一旦做好，叙事深度会质变。
6. **升级体系树（⑥）/ 双模式（⑦）**：作为后续大版本再考虑。

---

## 6. 一句话总结

竞品最大的启发不是"把功能都抄过来"，而是：**把「玩家偏好」从自由文本变成结构化标签，让 AI 在创作和运行时都能稳定地执行这些偏好**。这和 AetherNarrator 正在做的提示词优化方向完全一致，只是竞品用 UI 把这件事做得更浅白、更产品化。建议优先把「题材/爽点/口味/视角/风格」做成结构化标签，并和 IP 一致性检测结合，这是当前性价比最高的叙事提升。
