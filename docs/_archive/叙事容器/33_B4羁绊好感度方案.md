> 依据：`docs/28` 第 80 行 B4「羁绊 / 好感度：关系标签 + 数值 + 描述」（优先级 ★★★★☆）；路线图 §5 第 5 项「B4 羁绊 / 好感度 —— NPC 卡加关系字段，选择后更新」。
> 状态：方案文档（待黎总确认范围后落代码）。本文档只描述设计与影响范围，**未改动任何代码**。

---

## 1. 目标

给 NPC 关系加上**数值化好感度**与**关系标签**，让玩家清楚「我和这人什么关系」、给 AI 一个稳定的对话锚点，并让关系**驱动选项生成**（高好感可倾诉/委托，宿敌可对峙/回避）。

B4 的产出 = docs/28 定义的「关系标签 + 数值 + 描述」三角，叠加「关系驱动选项」。

---

## 2. 设计原则（沿用 B1/B2/B3 既定范式）

1. **可选默认、零压力**：好感度是人物卡上的**可选字段**，不填 = 不启用数值层（仍走 B1 已有的 `relationship` 自由文本）。不强制任何世界带好感度。
2. **不破坏文字描述层**：docs/05 规定 `attributes/relationships/skills` 用文字描述、不输出数字。B4 在文字层**之上叠加**一个独立数值层，绝不把文字关系覆盖成裸数字（现有 `applyStateChanges` 已对数字做"仅作提示、不覆盖文字"的保护，B4 继承该约束）。
3. **定义静态、值动态**（同 B2）：好感度的**初始锚点 + 关系标签**进 system 静态段（人物卡注入处）；**当前好感度数值**进每轮 user 消息的动态状态（`buildCompactGameState`），不破 DeepSeek 前缀缓存。
4. **复用既有 `state_changes` 通道**：新增 `state_changes.bonds`，由 `applyStateChanges` 累加，与 B2 变量、B3 物品同一管线。

## 4. 数据模型

### 4.1 创作层（人物卡）—— `world.characters[]`
在 B1 的 13 字段基础上新增 2 个**可选**字段：

```js
{
  // ... 既有 13 字段（含 relationship 自由文本）...
  affinity: 0,        // 初始好感度，number，范围 -100~100，默认 0；主角卡(role=protagonist)忽略
  rel_tags: []        // 关系标签数组，如 ["盟友","宿敌","暗恋对象"]，可选
}
```

- `affinity` 缺省 / 非数字 → 视为 0（不启用数值层时也 OK）。
- 主角卡不持有 affinity（好感度是「NPC 对主角的态度」）。

### 4.2 运行时层 —— `S.gameState.bonds`
**用 NPC 名字作 key**（与现有 `relationships` 完全一致，AI 天然给名字、无需 id 映射、零复杂度）：

```js
S.gameState.bonds = {
  "安吉尔教授": { affinity: 0, tags: ["中立学者"], desc: "克苏鲁神话研究者" },
  "邪教徒":     { affinity: -60, tags: ["宿敌"], desc: "试图阻止主角调查" }
}
```

- 结构：`{ [npcName]: { affinity:number, tags:string[], desc:string } }`
- 初始化：`startGame` / `prepareSessionFromSave` 时，由 `world.characters`（role=npc）按 **name** 填充初始 `affinity` / `rel_tags`，`desc` 取人物卡 `relationship` 初始值。
- 旧档兼容策略见第 11 节范围选项。

### 4.3 AI 契约 —— `state_changes.bonds`（新增通道）
```json
{
  "bonds": {
    "安吉尔教授": { "delta": 10, "tags": ["信任"], "desc": "因你交出笔记，他对你多了几分信任" },
    "邪教徒":     { "delta": -15 }
  }
}
```
- `delta`：相对变化（±），`applyStateChanges` 累加并夹取 `[-100, 100]`。
- `tags`：可选，合并进既有标签（去重）。
- `desc`：可选，更新该 NPC 关系文字描述（同时回写 `S.gameState.relationships[npc]`，保持文字层一致）。
- 与现有 `state_changes.relationships`（字符串/数字）**并行不冲突**：AI 可同时返回两者，或只用其一。

## 5. 数据流（文字示意）

```
创作者编辑人物卡(affinity / rel_tags)
        │ 保存 → world.characters[]  （不影响当前存档）
        ▼
开局 / 读档 → 由 characters 按 name 初始化 S.gameState.bonds
        │
        ├─► system 静态段：buildCharactersContext 注入「初始好感锚点 + rel_tags」（定义，静态）
        │                 + buildBondHint（关系驱动选项指令，静态）
        │
        ├─► 每轮 user 消息：buildCompactGameState 注入 bonds 当前值（动态，不破缓存）
        │
        ▼
AI 生成 → state_changes.bonds{delta,tags,desc}
        │
        ▼
applyStateChanges → 累加 affinity(夹取) + 合并 tags + 回写 relationships[desc]
        │
        ├─► 关键羁绊(≥80 或 ≤-80) → addBehaviorRecords(importance 5, type relationship) 进手记
        │
        ▼
展示层：状态面板「羁绊」页签(数值条+标签) + 本回合变化(好感Δ+标签) + 选项(驱动)
```

## 6. AI 注入策略

1. **静态段锚点**：`buildCharactersContext`（B1 已注入 `relationship` 文本处）追加该 NPC 的 `affinity`（初始值）与 `rel_tags`，给 AI 稳定的「这人当前大致态度」锚点。
2. **动态状态**：`buildCompactGameState` 现有已含 `relationships`；B4 追加 `bonds: S.gameState.bonds`，每轮可见当前好感度（与 B2 变量、B3 物品同模式）。
3. **关系驱动选项指令**（新增 `buildBondHint`，常驻 system 静态段，镜像 B3 的 `buildItemUseHint`）：
   > 当某 NPC 好感度较高（≥60）时，可在选项中自然给出「倾诉 / 委托 / 求助」类互动；当好感度较低（≤-40）或带「宿敌」标签时，可给出「对峙 / 回避 / 试探」类互动。选项须贴合当前剧情，不要生硬堆砌。
   > 选项与叙事是**同一次 LLM 调用**，背包/羁绊指令都在静态 system 段，不破前缀缓存。

## 7. 展示层

### 7.1 状态面板「羁绊」页签（升级 `case "relations"`）
- 保留文字关系渲染，叠加数值展示：
  - 好感度数值条（`-100 ~ 100`，负向红、正向绿，中文股市惯例反向不适用此处——好感用「红=敌对/低、绿=友好/高」更直观，待确认配色）。
  - 关系标签 `rel_tags` 小标签（如 `盟友` `宿敌`）。
  - 文字描述 `desc`。
- **关键羁绊高亮**：`affinity ≥ 80` 或 `≤ -80`（或带 `宿敌`/`挚友` 标签）→ 金色高亮 + ★ 前缀 + 置顶（仿 B3 关键物品）。

### 7.2 本回合变化面板（`formatStateChanges` 增强）
- 关系更新行带好感 Δ：`与 安吉尔教授 关系更新（好感 +10）`。
- 标签变化：`+标签[信任]`。

### 7.3 关键羁绊进手记
- 当好感跨入「极高/极低」阈值时，写一条 `type:"relationship"` 手记（`addBehaviorRecords`，importance 5），与 B3 关键物品一致。
