# B2 玩家变量 + 本回合变化 方案

> 衔接文档：docs/27（竞品叙事系统拆解 §5 状态面板/本回合变化、§6 世界编辑器玩家变量）、docs/28（里程碑 B2）、docs/05（状态与数值设计：文字描述优先）。
> 遵循原则：**数值不喧宾夺主、可选启用、结构是容器不是替代**（沿用 B1 已落地的「人物卡」同款范式）。

---

## 1. 为什么做（docs/27 原话）

- "状态"不是背景装饰，而是叙事压力源。理智降低、污染增加，玩家会本能地调整行为。
- "本回合变化"把 AI 的叙事输出**结构化确认**，避免 AI 说"你得到了枪"但系统没记录，或系统有记录但玩家没看见。
- 优先级 ★★★★★（"选择与后果"最直接的视觉反馈）。

## 2. 关键约束（避免踩坑）

1. **保留 docs/05 的"文字描述优先"体系**：`attributes / relationships / skills` 已是文字描述，B2 **不替换**它们，而是新增一类**创作者可配**的变量（数值/文本/开关）。
2. **默认空（开箱即用）**：`world.variable_schema` 默认 `[]`，绝大多数世界无任何数字压力；只有创作者主动添加变量，世界才出现数值。
3. **缓存友好**：
   - 变量**定义**（schema，静态）→ 注入 `buildSystemPrompt` 静态段（像 B1 人物卡），编辑保存时 `invalidateSystemPromptCache()`。
   - 变量**当前值**（每轮变）→ 注入 `buildCompactGameState()` 每轮 user 消息动态段（像 `story_progress`），**不进 system 段**，避免打破前缀缓存。
4. **完全复用现有 `state_changes` 通道**：AI 已在每轮返回 `state_changes` JSON，`applyStateChanges` 统一应用。B2 只是新增 `state_changes.variables` 一个字段，老存档/老世界零破坏。

## 3. 数据模型

### 3.1 世界级定义 `world.variable_schema`（数组）
每个变量定义：
```js
{
  id: "sanity",          // 唯一键（英文/数字，作为 gameState.variables 的 key）
  name: "理智",          // 展示名
  type: "number" | "text" | "toggle",
  default: 80,           // number: 数字；text: 字符串；toggle: boolean
  min: 0, max: 100,      // number 专用，可选
  unit: "%",             // number 专用，可选（如 "点"/"%"）
  desc: "理性与精神稳定度", // 可选说明，注入 AI 提示
  enabled: true          // 是否启用（false 则不注入/不显示/不解析）
}
```

### 3.2 运行时 `S.gameState.variables`（对象）
```js
S.gameState.variables = { sanity: 80, knowledge_pollution: 5 }
```
- 开局/读档时由 `syncVariablesToSchema(world, vars)` 按 schema 初始化并修剪（新增的变量补默认，已删的变量清除）。
- `normalizeSimulationState` 保证 `variables` 为对象（老存档兜底）。

### 3.3 预设示例（克苏鲁世界，new-worlds.js）
```js
variable_schema: [
  { id: "sanity", name: "理智", type: "number", default: 80, min: 0, max: 100, unit: "%", desc: "理性与精神稳定度，归零将陷入疯狂" },
  { id: "knowledge_pollution", name: "知识污染", type: "number", default: 5, min: 0, max: 100, unit: "%", desc: "接触禁忌知识累积的污染" }
]
```
其他预设（后室/双界）默认空数组——不强制数值。

## 4. 运行时数据流

```
创作者定义 world.variable_schema
        │
        ▼
[开局/读档] syncVariablesToSchema → S.gameState.variables
        │
        ├─► buildSystemPrompt 静态段：# 玩家变量（定义+更新指令）  ← 编辑保存时 invalidateSystemPromptCache
        │
        └─► 每轮 buildCompactGameState：variables: {当前值}        ← 动态段，命中每轮 user 消息
                │
                ▼
        AI 在 state_changes.variables 返回「变化后的值」
                │
                ▼
        applyStateChanges → computeVariableUpdates(校验/夹取/类型转换/忽略非法)
                │
                ├─► 写入 S.gameState.variables
                └─► 本回合变化面板：formatStateChanges(展示本回合变量增减 + 地点/关系/物品变化)
```

### 4.1 AI 契约（system 静态段，仅 schema 非空时注入）
```
# 玩家变量（由创作者定义）
本世界含以下玩家可追踪变量。剧情需要时，在 state_changes.variables 中返回变化后的新值（不是增量，是变化后完整值）：
- 理智(sanity)：数值 0–100，单位 %，默认 80。含义：理性与精神稳定度。
- 知识污染(knowledge_pollution)：数值 0–100，单位 %，默认 5。
数值类直接给数字；文本类给字符串；开关类给 true/false。不要编造未列出的变量。
```

## 5. 展示层

### 5.1 本回合变化面板（每条日志叙事下方）
`formatStateChanges(changes, world)` 纯函数，把本回合 `state_changes` 转为人类可读条目：
- 变量增减：`理智 80 → 75（-5）`、`知识污染 5 → 12（+7）`
- 地点：`前往 图书馆`
- 关系：`与 邓布利多 关系更新`
- 物品：`获得 旧式左轮手枪`、`失去 草药`
- 死亡：`角色死亡`
渲染位置：`render.js` 的 `renderLog` 每条 `.log-entry` 叙事+氛围之后（需 `game.js` 把 `resp.state_changes` 存入 `pendingEntry.state_changes`）。

### 5.2 状态面板（游戏内「角色状态」弹窗）
`renderStatusTabs` 增加「变量」页签（仅 schema 非空），`renderStatusPanel` 增加 `case "variables"`：展示每个变量当前值（数值带进度条+单位，文本显示文字，开关显示开/关）。

### 5.3 编辑器（世界详情「变量」页签）
- `render.js showWorldDetail` 增加「变量」页签（列表+编辑按钮）。
- `lore-ui.js`：`openVariableEditor / renderVariableEditorBody / addVariable / deleteVariable / saveVariableReview`。
- `index.html`：新增 `variableEditorModal`（结构镜像 `ruleEditorModal` / `characterEditorModal`）。
- `app.js`：接线 5 个 ACTIONS；保存时 `invalidateSystemPromptCache()`（schema 是静态段）。

## 6. Mock 模式支持
`llm.js mockLLM`：若当前世界有启用的数值变量，在通用分支里对第一个数值变量做小幅变化（演示「本回合变化」面板与状态面板，无需真实 API）。
