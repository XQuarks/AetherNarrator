# #10 错误处理统一方案

> 来源：`docs/34` §3.3 #10（"约 25+ 处 catch 不统一"）。
> 现状：`utils.js::logError(scope,err)` 已于 2026-07-28 落地（静默 `console.warn` + 写入 `S.debugLog.chunkErrors`，**绝不弹 toast**），并替换了 `game.js`/`llm.js` 共 6 处"辅助 LLM 调用失败→静默兜底"。本文档处理**故意留着的剩余部分**。

## 一、实测结论：25+ 处里，真正要改的很少

逐处核对 `src/**/*.js` 的全部 `catch` 后，按"是否影响用户可见结果"分三类：

### Tier 1 — 静默降级（保持静默，仅走 `logError` 记诊断）
这些是有意的非致命兜底，**绝不能改成弹窗**（正是 #10 警告的回归风险）：
- 向量/分词/Worker 不可用 → 降级关键词检索：`rag.js`(96/121/147/161/170/181/200/214/230/257/290/398/402/430/451/574/647)、`game.js:147/156`、`lore-ui.js:919/1048`、`critic.js:65`、`app.js:69`
- JSON 修复降级（核心容错）：`utils.js:525/528/655/661/684/739`、`llm.js:882/885/888`
- 索引持久化/同步失败（内存索引仍可用）：`ann-index.js`(123/137/149/178/193/196/202/204)
- 配置加载/`JSON.parse` fallback：`app.js:26/33`、`idb.js:45(idbGet 返回 null)`
- 图形库 destructor/zoom：`lore-graph-ui.js:60/132/139`
- `migrations.js:11/23`（`parseStored*` 返回 `{ok,value,error}`，调用方决定）

### Tier 2 — 用户提示（showToast，已正确 or 待补）
**已正确做（不动）：**
- 建世界失败 `game.js:252`、回合重试 `game.js:854`、回合失败 `game.js:1093/1104`
- 文件导入失败 `files.js:83/107/113`、记忆包导入 `game.js:1183`、世界导入 `game.js:1226`
- 清除缓存失败 `app.js:335/336`

**待补（唯一真实数据丢失风险）：**
- `idb.js:52/67/84` 的 `idbSet/idbSetMulti/idbDel` 全部 fire-and-forget 静默吞错；`storage.js` 的 `saveWorlds/saveState` 调用它们时不检查成败。**IndexedDB 写盘失败（空间不足/隐私模式/DB 损坏）→ 世界或存档静默丢失、零提示。**

### Tier 3 — 阻塞/严重（showModal + 导出诊断）
当前无专门处理。建议新增两类：
- 启动即 `openDB()` reject（环境不支持 IndexedDB）→ 首屏提示"本地存储不可用，进度无法保存"
- 全局 `unhandledrejection` / `error` 兜底（见下文 Phase 1）

## 二、统一设计：三档入口，一个收口

```
utils.js
  logError(scope, err)               // ★ 现有：静默 console.warn + debugLog，不弹窗
  notifyError(scope, err, userMsg)   // 新增：内部调 logError + showToast(userMsg||友好文案, "error")
  fatalError(scope, err, userMsg)    // 新增：内部调 logError + showModal(专用错误弹窗) + 提供导出诊断
```

判定规则（核心，需用户拍板）：
- **Tier 1 静默**：所有"降级不影响结果"的 catch → `logError`，不弹窗。
- **Tier 2 提示**：用户主动操作失败 / 关键持久化失败 → `notifyError`，弹 toast。
- **Tier 3 阻塞**：应用无法继续（存储不可用、致命初始化）→ `fatalError`，弹 modal。

## 三、分阶段实施（每阶段独立可测，避免回归）

### Phase 1 — 安全网 + 最高危修复（✅ 2026-07-28 已落地，零回归）
1. **全局兜底监听**（✅ 已落地）：`app.js` 的 `init()` 开头挂 `installGlobalErrorGuard()`，监听 `window.addEventListener('unhandledrejection'/'error')`，去抖（同 5s 内只弹一次）`showToast("程序出现异常，部分功能可能受影响（已记录诊断）", "error")` + `logError` 留痕。纯加性，能兜住任何漏网的裸吞。
2. **存档失败透传**（✅ 已落地）：`idbSet/idbSetMulti/idbDel` 改为返回 `boolean`（成功/失败）；`storage.js::saveWorlds/saveSaves/saveState/saveConfig` 在关键写入失败时 `notifyError`（"…保存失败，数据可能未持久化"）。**清缓存等非关键 fire-and-forget（storage.js:183-185）保持静默，不 toast。**

### Phase 2 — 日志统一 + 空 catch 补记录 ✅ 已落地（2026-07-28）
3. 把剩余 `console.error`/`console.warn` 非致命站点收口到 `logError`（均静默留痕，不影响任何用户体验）：
   - `game.js`: 139(分段知识库失败·已有toast)、147/156(向量预计算降级)、219(自动审稿失败)、258(建世界失败·已有toast)、616(AI回退时间被忽略)、1041(过期响应丢弃)、1105(回合失败·已有toast)
   - `lore-ui.js`: 532/549(开场白生成/优化失败·已有toast)、919/1048(向量重算降级)、474(拖拽setData)
   - `llm.js`: 512(流式失败降级非流式)
4. 空 `catch` 补 `logError`：`game.js:942`(裁判异常)、`lore-ui.js:967`(修订应用)、976(修订向量重算)、1025(lore确认持久化)。
   - 注：`lore-ui.js:976` 方案原"建议额外一次性 notifyError"，本次保持 `logError` 静默（非致命降级，用户已在确认弹窗流程中，弹窗会打扰）。
5. **明确排除（方案原文未预见，实测必须排除）**：`ann-index.js` 与 `embedding-worker.js` 两处**不接入 `logError`**——
   - `embedding-worker.js` 是 Web Worker 独立线程，无主线程 `S` 单例/DOM，`logError` 无法安全调用；
   - `ann-index.js` 刻意不 import `utils.js`（避免引入 utils→store 链，store 顶层访问 localStorage 在 node 测试环境会崩）；其空 catch 均为"有意静默降级"且带注释。
   这两处保持原状，非遗漏。

### Phase 3 — 防回归测试 ✅ 已落地（2026-07-28）
5. `test/43-error-handling.test.js` 新增 6 项（全绿，含进 414→420 总量）：
   - `logError` 写入 `S.debugLog.chunkErrors` 且不超过 300 上限 ✅
   - `notifyError` 正确调 `showToast`（mock 验证：className 含 show/error）✅
   - 静默档 `logError` **绝不触发** `showToast`（#10 核心不变量，防回归雷区）✅
   - `idbSet` 失败 → 关键保存路径 `saveWorlds` 触发 `notifyError`（node 无 indexedDB 天然触发失败路径）✅
   - 全局兜底 `installGlobalErrorGuard` 去抖 5s 内只弹一次 ✅
   - 静默路径 `tryRepairJSON`：无法修复时**抛错**（非静默返回）+ 绝不触碰 toast（utils 层无渲染依赖）✅
6. **为可测性做的零行为重构**：`app.js` 的 `installGlobalErrorGuard`（及闭包 `_guardLastShown`）抽到无副作用的 `src/error-guard.js`，`app.js` 改为 `import` 它（运行时 init() 调用点不变）。原因：app.js 顶层直接 `init()` + 大量 `document.addEventListener`，直接 import 测试会触发整条 DOM 链；抽离后测试可干净 import 该函数。

## 四、明确不做（防过度 / 防回归）

- ❌ 不把 Tier 1 静默降级改成 toast（正是 #10 标红的风险：把"有意降级"变烦人弹窗）。
- ❌ 不为每个错误加 modal，仅 Tier 3 致命场景用 modal。
- ❌ 不动 `migrations.js`（已是干净的 `{ok,value,error}` 模式）和 `files.js` 导入 toast（已正确）。

## 五、待用户确认的判断点（见对话提问）

- Q1 存档写盘失败：弹 toast（推荐）/ 仅静默记录 / 弹 modal 强提示
- Q2 向量降级（影响检索质量但不致命）：静默+诊断（推荐）/ 一次性 toast / 每次 toast
- Q3 全局未捕获异常兜底监听：加、去抖弹一次（推荐）/ 不加
