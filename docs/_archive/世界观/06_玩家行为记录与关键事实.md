# 玩家行为记录与关键事实

行为记录确保长对话中 AI 不会遗忘关键剧情。

> 演进说明（C 系列）：`behavior_records` 已升级为结构化记忆——每条含 `importance`(1-5)/`pinned`/`type`/`time`/`location`/`npcs[]`/`embedding`，并有「记忆」面板可查看 / 置顶 / 删除 / 导入导出（C1–C5）；向量语义召回已替代纯关键词。

---

## 1. 工作流程

```
AI 叙事输出 → 提取 key_facts → 加入 behavior_records
     ↓                                      ↓
  触发 applyStateChanges              retrieveBehaviorRecords
     ↓                                      ↓
  更新 gameState                     对比玩家输入 + 中文分词
                                           ↓
                                      匹配关键事实 → 注入 user message
```

---

## 2. 关键事实生成

AI 每轮输出 JSON 时附带 `key_facts` 数组：

```json
{
  "key_facts": [
    "玩家获得了草药",
    "玩家与老道长的关系有所提升"
  ]
}
```

前端自动过滤重复项（`behavior_records` 中已存在的跳过），上限保留 100 条。

---

## 3. 关键事实累积与 B6 记忆晋升（不再无条件注入）

> ⚠️ 本节旧版写"每轮无条件注入最近 5 条关键事实"，**已过时**。当前采用 B6 记忆晋升机制：

每轮的关键事实先累积进 `S.activeBehaviorRecords`（上限 **100 条**），**不再每轮无条件注入 user message**：

- 关键事实以"行为记录"形式持续留存，供 RAG 的**行为记录检索**（`retrieveBehaviorRecords()`）按需召回，而非全量硬塞；
- 仅**高价值记忆**（`importance ≥ 4` 或被 `pinned`）才会被 AI 在合适时机建议，并由玩家在**记忆确认台「应用」**后晋升为 lore 片段，固化进知识库（详见 `B6记忆晋升方案.md`）；
- 普通关键事实随对话推进自然滚动，不会永远占用上下文。

---

## 4. 行为记录检索

当玩家输入涉及过去事件时，通过 `retrieveBehaviorRecords()` 匹配相关行为记录：

- 使用 `Intl.Segmenter` 中文分词（与关键词检索一致）
- 按输入与行为记录文本的匹配度评分
- 得分 > 0 的记录加入融合排序

---

## 5. 对话历史摘要

为减少 API 请求的 token 消耗：

- chatHistory 只保留最近 4 轮完整对话（8 条消息）
- 每轮 AI 回复后自动生成 1-2 句中文摘要（`chatSummary`）
- 摘要取叙事文本前 2 个句子，含地点变更信息
- 摘要上限 20 条，防止无限增长

---

## 6. 玩家输入 → AI 输出全流程

```
玩家输入
  ↓
中文分词 → RAG 并行检索（关键词 + 向量 + 行为记录）
  ↓
触发门控(B1) → 融合排序（老存档降级 Top 8）
  ↓
构建 user message:
  - 对话历史摘要
  - 高价值记忆（经 B6 晋升的 lore）+ 行为记录检索命中项
  - NPC 关系描述
  - RAG 检索片段
  - 紧凑游戏状态
  - 玩家输入
  ↓
构建 messages: [system(缓存) + chatHistory(锚定) + user(动态)]
  ↓
发送 API → SSE 流式响应
  ↓
解析 JSON → 应用状态变更 → 生成摘要 → 归档关键事实 → 保存
```

---

## 7. 后端无状态设计

所有行为记录存入 `currentWorld.behavior_records`，经 **IndexedDB**（`src/idb.js`）持久化，无需服务器；读档时完整恢复。ID 使用 `crypto.randomUUID()` 保证唯一性。
