# 剧情生成提示词优化分析 & 文风一致性方案

> 适用对象：黎总（产品/玩法视角，非工程）
> 文档目的：把"剧情生成提示词哪里能优化"和"剧情风格怎么和玩家需求一致"两个问题讲清楚，并给出**可直接评审的改动前后对照**。
> 配套代码：`src/prompt.js`、`src/llm.js`、`data/system_prompt_template.md`

---

## 0. 一句话结论

当前提示词**结构已经相当完整**（防注入、时间规则、主角锚点都是强项），最大的短板只有一个：**玩家的"文风选择"只在建世界时被喂了一次，之后运行时没有强制约束，还被模板里写死的 emoji/心形/语气词反向覆盖**。修好"文风贯穿运行时"这一条，玩家体验会有质的提升，而且改动很小、可逆、不碰引擎。

---

## 1. 当前提示词是怎么拼出来的（链路）

剧情不是一段写死的提示词，而是在"建世界"和"每轮对话"两个时刻分别拼出来的：

```
建世界时（一次性）
  buildWorldGenerationPrompt
    └─ 把 name / type / desc / hero / 文风 / 自由度 整理成 JSON
       └─ 让 AI 生成 world.system_prompt（一段自由文本）
            ↑ 玩家选的"文风"只在这里出现一次

运行时（每轮都跑）
  buildSystemPrompt（套模板 system_prompt_template.md）
    └─ 角色锁定 / 硬约束 / 叙事基调 / 节奏 / 选项要求 / 防注入 / 输出格式
       + buildToneGuide（用关键词猜"日常/浪漫/悬疑/高张力"）
       + buildHeroContext / buildTimeModeRules / buildAuthorNote
  buildTurnUserMessage（每轮：前情+记忆+关系+lore+状态+玩家输入）
    └─ 组装成发给 AI 的最终请求
```

**关键缺口（看图红框）**：运行时这条链路里，**没有一处把玩家选定的"文风"原文再注入进去**。玩家选的文风只剩"AI 当初写进 `world.system_prompt` 的那段自由文本"在撑，质量随缘——这是后面所有风格漂移的根。

## 3. 核心问题：剧情风格怎么和玩家需求一致

这是你问的重点，也是当前最大短板。

### 3.1 根因（三重稀释）

1. **没强制位**：`styleRef` / `customStyle` 只在建世界时喂一次，运行时 `buildSystemPrompt` 不注入 → 玩家文风只剩"AI 当时写进 `world.system_prompt` 的一段自由文本"，质量随缘。
2. **模板反向覆盖**：固定模板无条件要求 emoji/心形/语气词，对所有世界生效，直接盖过玩家文风。
3. **基调各猜各的**：`buildToneGuide` 关键词推断和玩家 style 脱节，可能得出相反结论（你选"冷峻硬汉"，它推断"日常→温情"）。

### 3.2 修复路径（按性价比排序）

| 优先级 | 做法 | 改动量 | 效果 |
|---|---|---|---|
| ★ 最高 | 模板加 `{STYLE_GUIDE}` 占位符，`buildSystemPrompt` 运行时把 `customStyle` 原文 + 文风标签注进去 | 小 | 玩家文风成为**运行时硬约束**，立刻生效 |
| ★ 高 | 模板第 33–73 行 emoji/心形段改为**按文风开关**：轻松/恋爱类启用，史诗/硬核/恐怖类替换为对应描写指南 | 中 | 消除"硬汉世界冒出 ♡"的违和 |
| ★ 高 | `buildToneGuide` 补恐怖/废土/冷峻/史诗类别；给了自定义文风时**以自定义为准** | 小 | 基调不再和风格打架 |
| 中 | 在 `buildAuthorNote` 中部纠偏位加一句"保持文风 X"；参照世界观裁判 A7，加轻量"文风一致性"审稿 | 小–中 | 双保险，漂移可被拦截 |

### 3.3 你手里已有但没连起来的旋钮：温度

温度是全局一个值（`S.temperatureSetting`，theme.js:258），决定 AI 输出的"随机/发散程度"。**严谨史诗类文风应配低温（0.3–0.5），自由诗意类可高温（0.8+）**。现在所有世界同一温度，也间接导致文风漂移。建议把"文风 → 推荐温度"做成映射，创建世界时自动预填（给玩家可改的默认值即可，不强制）。

## 4. 最该做的 3 件事（含改动前后对照）

> 以下改动**只动 `data/system_prompt_template.md` 和 `src/prompt.js` 的两三个函数**，不碰引擎逻辑，可逆、风险低。

### 4.1 运行时注入 `{STYLE_GUIDE}`（性价比最高）

**问题**：玩家文风只在建世界时被翻译一次，运行时没有强制约束。

**做法**：在 `system_prompt_template.md` 的"叙事基调"段前加一个占位符 `{STYLE_GUIDE}`；在 `buildSystemPrompt` 里，把 `world.styleRef` + `world.customStyle` 拼成一段"本世界强制文风"注进去。

**改前（模板无此段）**
```
（叙事基调一节直接开始，没有任何"玩家选定文风"的痕迹）
```

**改后（模板新增段，运行时填充）**
```
## 本世界强制文风（玩家已选定，每轮必须遵守）
{STYLE_GUIDE}
- 上述文风是本世界的最高优先级叙事约束，任何场景、任何 NPC 都不得偏离。
- 若世界知识库(world.system_prompt)中的文风描述与本条冲突，以本条为准。
```

**`buildSystemPrompt` 注入的 `{STYLE_GUIDE}` 内容示例**
```
文风标签：冷峻硬汉 / 第一人称
玩家自定义要求：少用形容词，多用动作和对话，禁止少女语气词和 emoji。
参考范例：短句为主，对话干脆，心理描写克制。
```

**效果**：玩家文风从"建世界时的一次性翻译"变成"每轮都强制的约束"。

---

### 4.2 模板 emoji/心形段按文风开关（消除违和）

**问题**：第 33–73 行把 emoji + 心形 ♡ + 女性语气词 + 呻吟喘息写死，对所有世界无条件生效——硬核/克苏鲁/赛博朋克世界也被逼写"啊呀~不要嘛♡"。

**做法**：把这段拆成"按文风分类的描写指南"，由 `buildSystemPrompt` 按文风标签选择注入哪一段。

**改前（写死，对所有世界生效）**
```
可以在叙事中适度使用 emoji（如 💡🔥💀⚡🌟）来增强表现力。
使用可爱的心形符号 ♡ 和语气词（如"呀""嘛""呢"）营造亲密感。
适当加入轻声呻吟、喘息等亲密描写……
```

**改后（按文风分支，只注入匹配的一段）**
```
{STYLE_EXPRESSION_GUIDE}   // 由文风标签决定填充下列哪一段

[轻松/日常/恋爱/甜宠 类]
- 可适度使用 emoji（💡🔥🌟）与心形符号 ♡，语气词（呀/嘛/呢）营造亲密感；
  恋爱向可含轻柔的亲密描写，但须保持克制、不越界。

[史诗/硬核/废土/生存 类]
- 禁用 emoji 与心形符号；描写以冷峻的感官细节（气味、触感、声响）为主；
  句子短促有力，避免甜腻语气词。

[克苏鲁/恐怖/悬疑 类]
- 禁用 emoji 与心形符号；用不确定性、留白、不可名状感制造恐惧；
  避免任何轻佻或亲密语气，保持疏离与压抑。

[赛博朋克/黑色 类]
- 禁用 emoji；用冷光、金属、数据意象；对话带犬儒与锋利感。
```

**效果**：硬汉/恐怖世界不再冒出 ♡ 和少女语气词，文风视觉与语气立刻对齐。

---

### 4.3 基调对齐 + 中部纠偏位加文风提醒（双保险）

**做法 A — `buildToneGuide` 补类别 + 自定义优先**
在现有"日常/浪漫/悬疑/高张力"基础上，补：恐怖/克苏鲁、废土/生存、黑色/冷峻、史诗。并加一条规则：**若玩家提供了 `customStyle`，则基调以 `customStyle` 推断为准，不再用关键词瞎猜。**

**做法 B — `buildAuthorNote` 中部纠偏位加文风提醒**
在现有"事件推进 + 玩家持续约束 + 权威时间"之后，追加一句（离生成点近、权重高）：
```
【文风保持】本轮及后续所有输出，必须维持本世界强制文风（见系统提示"本世界强制文风"节）。
如检测到语气/用词偏离，立即回调，不要等玩家纠正。
```

**做法 C — 轻量文风审稿（参照现有世界观裁判 A7）**
在 `callWorldCriticLLM` 的审查维度里加一条"文风一致性"：检查输出是否符合本世界强制文风（emoji/语气词/句式节奏），偏离则标记。这是最后一道闸，成本中等、收益高。

## 5. 建议落地顺序 & 影响范围（给黎总的白话说明）

1. **先做 4.1（注入 `{STYLE_GUIDE}`）** —— 改动最小、收益最大，一针见血解决"文风丢失"。
2. **再做 4.2（emoji 按文风开关）** —— 消除最刺眼的违和感。
3. **最后做 4.3（基调对齐 + 中部提醒 + 文风审稿）** —— 双保险，把漂移彻底拦住。
4. **顺手做 3.3（文风→推荐温度映射）** —— 创建世界时自动预填温度默认值。
