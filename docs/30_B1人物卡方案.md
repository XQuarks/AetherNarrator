# B1 人物卡（主角 + NPC）方案

> 来源：docs/27 竞品叙事系统拆解（人物卡 ★★★★★）、docs/28 合并总览（B1 行）。
> 目标：把「主角 + NPC」从散落在 lore 的自由文本，变成**字段固定、可编辑、每轮强制注入**的结构化容器，让 AI 不再从文本里「回忆」角色，提升叙事一致性。
> 复用现有设施：`world` 对象、`prompt.js` 的 system 注入与缓存、`getWorldLoreKB` 同族的「世界级固定内容」机制。不影响现有 lore / 规则 / 时间系统。

---

## 1. 设计原则（来自 docs/27/28 的谨慎提示）

- **结构是容器，不是替代**：保留「自由文本备注」字段，让 AI 仍有发挥空间，避免「填表式」叙事。
- **开箱即用、不强制**：人物卡是可选的；没有角色卡时世界照常运行（注入段为空则不输出）。
- **主角身份恒定**：与现有 `buildHeroContext` 的「身份锚点」一致——玩家始终扮演主角，不可被替换。
- **注入走 system 静态段**：人物卡是世界级固定内容，放进 `buildSystemPrompt` 的稳定前缀区（与世界观知识库同待遇），命中前缀缓存、token 稳定；编辑保存时 `invalidateSystemPromptCache()` 重建。

---

## 2. 数据模型：`world.characters`

每张卡：
```js
{
  id: "c<timestamp>",
  role: "protagonist" | "npc",   // 主角 / NPC
  name: "",                       // 姓名（主角可留空或填"你"）
  identity: "",                   // 身份（如：霍格沃茨一年级新生 / 克苏鲁调查员）
  gender_age: "",                 // 性别 / 年龄
  appearance: "",                 // 外貌
  personality: "",                // 性格
  motivation: "",                 // 核心目标 / 动机
  relationship: "",               // 【NPC】与主角的关系标签（宿敌/合作者/路人/师徒…）
  attitude: "",                   // 【NPC】对主角态度
  current_state: "",              // 【NPC】当前状态 / 所在
  voice: "",                      // 【NPC】声音标签 / 说话方式
  untouchable: "",                // 不可触碰设定（红线，AI 不得违背，如"永远不会背叛"）
  notes: ""                       // 自由文本备注（给 AI 的额外发挥空间）
}
```

- `ensureWorldCharacters(world)`：保证 `world.characters` 为数组（与 `ensureWorldCanon` 同族）。
- 加载（`storage.js.loadWorlds`）与创建（`game.js.createWorld`）均初始化；预设世界（`new-worlds.js`）补 `characters: []`。
- **不破坏旧世界**：未建人物卡的世界 `characters` 为空数组，注入段自动跳过。

---

## 3. 提示词注入：`buildCharactersContext(world)`

- 纯函数（可在 Node 单测，不触 DOM），参数 `world` 缺省取 `S.currentWorld`。
- 主角卡排在前，NPC 卡在后；只输出非空字段。
- 在 `buildSystemPrompt` 中，于「一致性包」之后、「时间线」之前，注入：
  ```
  # 角色设定（人物卡）

  【角色卡 · 主角】林黛玉
  - 身份：…
  - 性格：…
  - 核心目标：…
  - 不可触碰设定：…（若存在）
  - 备注：…（若存在）

  【角色卡 · NPC】薛蟠
  - 身份：…
  - 与主角关系：表兄
  - 对主角态度：…
  - 当前状态：…
  - 声音标签：…
  ```
- 空世界：`buildCharactersContext` 返回 `""`，调用处不追加该段。

## 4. 编辑器 UI

### 4.1 世界详情页签
`render.js.showWorldDetail` 的 `detail-tabs` 增加「角色」页签：
- 列出所有角色卡（姓名 + `主角`/`NPC` 徽章 + 一句话身份）。
- 底部按钮「编辑角色」→ `data-action="openCharacterEditor"`。

### 4.2 角色编辑弹窗（`characterEditorModal`）
- 列表式：每张卡为一个可折叠编辑块，含全部字段输入框 + 角色切换（主角/NPC）+ 删除按钮。
- 顶部「＋ 添加角色」；右上「🤖 AI 生成」（见 §5）。
- 底部「取消 / 保存角色」：`saveCharacterReview` 从 DOM 读回 → 写入 `world.characters` → `saveWorlds()` → `invalidateSystemPromptCache()` → 关闭。

### 4.3 接线
- `lore-ui.js` 实现 `openCharacterEditor / renderCharacterEditorBody / addCharacter / deleteCharacter / saveCharacterReview / generateCharactersAI / syncCharacterForm`。
- `index.html` 增加 `characterEditorModal`（结构镜像 `ruleEditorModal`）。
- `app.js` 从 `lore-ui.js` 导入并接入 `ACTIONS`。

---

## 5. AI 生成角色卡（可选增强）

- `llm.js`：`generateCharacters(world)` 用 `callLLMJson` 依据 `world.desc + world.hero` 产出 3–6 张角色卡 JSON（含主角 + 若干 NPC），`parseCharacters(text)` 做容错解析（复用 `tryRepairJSON`）。
- `lore-ui.js`：`generateCharactersAI()` 调用并合并进 `S._charEdit`，重新渲染；无 API / mock / 失败均安全跳过，不阻断。

---

## 6. 测试

`test/30-characters.test.js`（纯函数，Node 环境）：
- `ensureWorldCharacters`：缺字段补数组、已有保留、非法值兜底。
- `buildCharactersContext`：主角+多 NPC 正确格式化、空世界返回空、只输出非空字段、untouchable/notes 条件输出。
- `parseCharacters`：标准 JSON / 含噪声 / 损坏 三种解析。
- 注入集成：带角色卡的世界 `buildSystemPrompt` 含「角色设定（人物卡）」段；空角色卡不含。
