> 目标：世界可以有"只有引擎知道"的真相（谜底、幕后设定、NPC 真实身份）——**叙事 AI 绝不知晓、绝不剧透**；剧情推进到相应阶段时，由引擎从"受控通道"揭示给 AI 作为叙事依据。补强 docs/56 防剧透门禁（那是"知识库条目按阶段解锁进检索池"，本方案是"真相不进检索池、只由引擎显式揭示"，两者互补）。

---

## 一、与 docs/56 门禁的关系（先讲清，避免重复造轮子）

| | docs/56 防剧透门禁 | 本方案 GM 真相层 |
|---|---|---|
| 数据 | lore_kb.snippets 每条带 `unlock_stage` | 独立顶层字段 `world.gm_truth.entries[]`（不进 lore_kb） |
| 解锁方式 | 达到阶段后**进入 RAG 检索池**，玩家问起/关键词命中即可注入 | 达到阶段后由引擎**显式揭示**（独立 system 消息），不依赖检索 |
| 可发现性 | 玩家可通过对话/检索"挖出"设定 | 玩家只能通过剧情推进让引擎揭示，挖不到 |
| 用途 | 世界设定分级放送 | 幕后真相/谜底（GM 视角铁律、结局级秘密） |

→ 二者互补：普通后期设定走 docs/56，**只有"整个故事的核心谜底"才进 GM 真相层**（数量少、价值高、绝不能提前泄）。

## 二、数据模型

```jsonc
// world.gm_truth（独立顶层字段，绝不放进 lore_kb.snippets）
{
  "entries": [
    {
      "id": "gt1",
      "title": "勾玉的真相",               // ≤200 字，作者端展示
      "content": "神社家子女出生获赠透明勾玉；被 Yith 寄宿时变黑。黑勾玉 + 离岛机器 = 回到佩戴者来时的时间线。",
      "unlock_stage": 3                   // 剧情推进到 stage>=3 时引擎揭示；缺省 1
    }
  ]
}
```

**铁律（硬隔离）**：gm_truth 是 world 顶层字段，与 lore_kb 完全隔离——
- 不参与 RAG 检索（rag.js 只读 lore_kb，碰不到 gm_truth）；
- 不进入 `buildSystemPrompt` / `buildTurnUserMessage` / 知识库硬约束段 / 图谱；
- **唯一出口**：`buildGmTruthReveals()` 受控揭示函数（见下）。

---

## 三、受控揭示机制（引擎唯一出口）

`prompt.js` 新增纯函数：

```js
// 返回「已到揭示阶段的 GM 真相」文本块；无到期条目返回 ""。
// 规则：story_progress >= entry.unlock_stage 的条目视为已到期；
//      无 gm_truth / 无到期条目 → 不输出（即叙事 AI 永远看不到未揭示的真相）。
export function buildGmTruthReveals(state, world) { ... }
```

- 读取 `world.gm_truth.entries`（world 可为 `S.currentWorld`），用 `S.gameState.story_progress` 过滤；
- 到期条目拼为：
  ```
  # GM 揭示（幕后真相）
  以下为本局已推进到的幕后真相，请按此叙事：本局玩家已触及……
  - 勾玉的真相：……
  - …
  注意：未在此列出的真相，你依旧不得知晓、不得暗示。
  ```

`llm.js::callLLM` 在作者注（authorNote）之后、user 之前，插入独立 system 消息：

```js
...(gmReveal ? [{ role: "system", content: gmReveal }] : []),
```

- 位置与 authorNote 同级（贴近生成点、system 级权威），不动 system 前缀缓存；
- **无到期条目时不产生该消息**（默认情况下系统里根本不存在真相文本）。

## 五、兼容与安全

- 旧档/旧世界无 `gm_truth` → `buildGmTruthReveals` 空值兜底返回 ""，行为与现在完全一致；
- AI 生成世界不产 gm_truth → 正常（可选字段）；
- 硬隔离由"字段位置"保证（独立顶层字段不进 lore_kb），再加测试断言兜底：构建出的 user/system 文本不含未到期真相文本。
