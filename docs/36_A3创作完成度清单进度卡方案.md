## 一、目标

在「世界详情页（作者工作台）」的概览页顶部，加一张**创作完成度清单 / 进度卡**，让创作者在进游戏前一眼看到：这个世界「叙事上站得住吗」——有没有标题、世界观、开场、角色、机制、事件、主角动机。

- **轻量**：全部指标从 `world` 现有字段实时派生，**不写任何新字段、不改存档结构、不改 schema、不改引擎**。
- **不阻塞**：仅展示，缺项**不阻止「开始游玩 / 继续游戏」**（区别于竞品的强制七项齐了才能玩）。
- **引导而非警告**：缺失项用柔和样式（灰/次级色），不红字告警；可选附「去补」快捷入口。

## 三、设计

### 3.1 完成度维度（默认 7 项，全部可静态派生）

| # | 维度 | 派生逻辑（现有字段） | 缺失时提示 |
|---|---|---|---|
| 1 | 标题 | `world.name` 非空 | （已保存世界恒满足） |
| 2 | 世界观 | `world.desc` 非空（建议 ≥ 10 字，避免空壳） | 去编辑世界观描述 |
| 3 | 开场场景 | `world.opening_narrative` 非空 | 去补开场白 |
| 4 | ≥1 角色 | `world.characters.length ≥ 1` | 去添加角色卡 |
| 5 | 游玩系统 | `world.rules.length ≥ 1`（机制/规则） | 去添加规则 |
| 6 | 重要事件 | `world.lore_kb.snippets` 中至少 1 条带 `trigger` | 去知识库给片段挂触发 |
| 7 | 主角设定 | `world.hero` 非空 | 去补主角动机/身份 |

> 说明：第 1 项对已保存世界恒为真，保留它是为了让进度条从「1/7」起跳、视觉上不空；若你觉得它没信息量，可在范围选项里去掉。

### 3.2 进度卡视觉（概览页顶部内嵌）

```
┌─ 创作完成度  5 / 7  ·  基本可用 ───────────┐
│  ▓▓▓▓▓▓▓▓▓▓▓░░░░░   71%                    │
│  ✓ 标题      ✓ 世界观     ✓ 开场场景        │
│  ✓ ≥1 角色   ○ 游玩系统   ○ 重要事件        │
│  ✓ 主角设定                                   │
│  小字：不完整的项不影响开始游玩，补全可让世界更扎实 │
└────────────────────────────────────────────┘
```

- 顶部一行：完成数 / 总数 + 一句话评级（如 7/7 圆满 · 4–6/7 基本可用 · <4/7 待充实）。
- 进度条（复用现有配色变量，不引入新色）。
- 维度以「✓ 已完成 / ○ 待补」两态展示；缺失项用次级色，不告警红字。
- 可选：缺失项旁带「去补 →」文字链（点击跳到对应 tab/编辑器），见范围选项。

### 3.3 代码落点（影响文件）

| 文件 | 改动 |
