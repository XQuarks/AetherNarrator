# docs/73 — 随机事件条件系统方案

> 配套 docs/70（状态栏与变动日志）、docs/71（情境人格与 OOC 守门）、docs/72（AI 生成角色切面）。
> 本文档只定方案，**代码改动需黎总确认范围后再进行**。

## 1. 目标

让「随机事件池」里**每条事件**可以挂条件。引擎在「每 N 回合」这个全局节奏之上，再按**单条事件的条件**做筛选，只有命中的事件才进入抽取池。

- 条件**全部确定性判定**（引擎读状态，不劳 AI 猜）。
- 支持「多条件全满足（AND）」与「满足任意一个（OR）」两种组合。
- 条件依赖的进阶功能（好感/知识库/支线事件等）未开启时，UI 置灰提示，不让保存无意义条件。

## 2. 已拍板的决策（本次确认）

| 决策点 | 结论 |
|---|---|
| 前置事件支持来源 | **三层全要**：①本随机事件发生过 ②支线 events 发生过 ③lore 知识卡已解锁 |
| 依赖功能未开启时 | **UI 动态禁用 + 灰字提示**，不允许保存该条件 |
| 配置入口 | **仅生成后的「随机事件」tab**（世界详情弹窗），**不进**初始 6 步创作向导 |

## 3. 数据模型

`world.random_events` 的每一项扩展为：

```js
{
  title: "走廊遇巨怪",
  hint: "巨怪摇摇晃晃堵在走廊尽头，魔杖发光的水渍一路拖过来。",
  weight: 1,                          // 软性权重（非硬条件），越高越易被抽中；默认 1
  condition_mode: "all",             // ★ "all"=多条件全满足 | "any"=满足任意一个；默认 "all"
  conditions: [                      // 条件数组，空数组 = 无条件（任何节奏回合都可抽）
    { type: "location",      value: "霍格沃茨大厅" },
    { type: "story_progress", op: ">=", value: 3 },
    { type: "bond",          npc: "哈利", op: ">=", value: 40 },
    { type: "fired",         value: "分院仪式" },        // 前置：本随机事件发生过
    { type: "events",        value: "密室开启" },        // 前置：支线事件发生过
    { type: "lore",          value: "秘典·第一章" },     // 前置：知识卡已解锁
    { type: "season",        value: "冬季" }             // 时间系统条件
  ]
}
```

> `conditions` 留空 = 无条件事件（保持现有行为，向后兼容旧数据）。
> `op` 仅数值类条件使用，取值 `>=` / `<=` / `==`，默认 `>=`。

## 4. 六类条件判定（全部确定性，零 AI）

| type | 含义 | 判定状态来源（已核实字段） | 判定式 | 依赖模块 |
|---|---|---|---|---|
| `location` | 当前位置命中 | `S.gameState.current_location`（字符串，任何世界都有） | `current_location === value`（或包含） | 无（核心） |
| `story_progress` | 章节进度 | `S.gameState.story_progress`（整数，引擎自维护，game.js:896） | `story_progress op value` | 无（核心） |
| `bond` | 角色好感 | `S.gameState.bonds[npc].affinity`（数值，B4/affinity 模块） | `bonds[npc].affinity op value` | `affinity` |
| `fired` | 本随机事件已发生 | `S.gameState.random_event_state.firedTitles`（本次**新增**数组） | `firedTitles.includes(value)` | `random_event`（自身） |
| `events` | 支线事件已发生 | `S.gameState.completed_events`（数组，支线触发后写入，game.js:761） | `completed_events.includes(value)` | `events`（支线事件模块） |
| `lore` | 知识卡已解锁 | `world.lore_kb[].unlock_stage`（1–50，docs/56） | 该卡 `unlock_stage <= story_progress`（即已达解锁阶段） | `lore`（知识库） |
| `season` / `era` | 时间条件 | `current_date` / `era`（时间系统，docs/20/21） | 命中指定季节/纪元 | 时间系统（核心） |

**关键点：前置事件（fired / events / lore）不需要 AI 判定**——它们都来自引擎已维护的确定性状态：
- `fired`：每次 `getRandomEventHint` 成功注入一条事件，引擎把它的 `title` 推进 `firedTitles`。
- `events`：`completed_events` 是支线事件触发后由 `applyStateChanges` 写入的既有数组。
- `lore`：`unlock_stage <= story_progress` 是 docs/56 防剧透门禁的同款判定逻辑。

## 5. 组合逻辑（AND / OR）

```js
export function evalEventConditions(event, S) {
  const conds = (event && Array.isArray(event.conditions)) ? event.conditions : [];
  if (!conds.length) return true;                 // 无条件 = 始终满足
  const mode = (event.condition_mode === "any") ? "any" : "all";
  const results = conds.map(c => evalCondition(c, S));
  return mode === "any" ? results.some(Boolean) : results.every(Boolean);
}
```

- `condition_mode: "all"` → `every`（默认，最常用语义：全部满足才出现）
- `condition_mode: "any"` → `some`（满足一个即可）

## 6. 引擎抽取改造（src/prompt.js）

`pickRandomEvent` 改为**先过滤再抽**：

```js
export function pickRandomEvent(pool, excludeTitle, rng, S) {
  let cand = (Array.isArray(pool) ? pool : []).filter(e => evalEventConditions(e, S)); // ★ 先按条件筛
  if (!cand.length) return null;                  // 全不满足 → 本轮不注入（不硬塞，避免空转）
  if (excludeTitle && cand.length > 1) {
    const f = cand.filter(e => e.title !== excludeTitle);
    if (f.length) cand = f;
  }
  const r = (typeof rng === "function") ? rng() : Math.random();
  return cand[Math.min(cand.length - 1, Math.max(0, Math.floor(r * cand.length)))] || null;
}
```

`getRandomEventHint` 注入成功后，把标题记入 `firedTitles`：

```js
if (ev && S.gameState) {
  if (!S.gameState.random_event_state) S.gameState.random_event_state = {};
  if (!Array.isArray(S.gameState.random_event_state.firedTitles)) S.gameState.random_event_state.firedTitles = [];
  S.gameState.random_event_state.firedTitles.push(ev.title);   // ★ 记录已发生
  S.gameState.random_event_state.lastTitle = ev.title;
}
```

`evalCondition` / `evalEventConditions` 为**纯函数**，便于单测，不碰 DOM、不调 AI。

## 7. 依赖功能未开启的 UI 处理（src/render.js）

在「随机事件」tab 里编辑条件时：

- 条件**类型下拉**列出全部 7 类；若某类依赖的功能未开启（`isModuleEnabled(world, 模块)` 为 false），该选项**置灰（disabled）+ 标注「需先开启 X 模块」**。
- 已保存但依赖后来被关闭的条件：在列表里**灰显 + 提示「依赖的 X 模块已关闭，本条件暂不生效」**，不让其静默失效导致误判。
- 条件参数输入（如 `bond` 的 npc、`lore` 的卡名）按类型动态显隐对应输入框。

> 这样既不劝退新手（不强求先开功能才能看到这一栏），也保证不会保存出无意义的条件。

## 8. 配置 UI 改造（src/render.js · 随机事件 tab）

每条事件卡内新增两块：

1. **组合方式**：下拉 `condition_mode`（全满足 / 任一满足），默认「全满足」。
2. **条件列表**：可「+ 添加条件」增行，每行 = 类型下拉 + 参数输入（按类型动态）+ 删除 ✕。
   - `location` → 文本输入（地点名）
   - `story_progress` / `bond` → 数值输入 + （bond 额外）角色名输入 + 比较符下拉
   - `fired` / `events` / `lore` → 文本输入（事件/卡片标题）
   - `season` / `era` → 文本/下拉

保存走现有 `saveWorldRandomEvents`（game.js），解析条件写回 `world.random_events`。

## 11. 风险与回滚

- **条件全不满足 → 池空**：已设计为 `return null`（本轮不注入），不会硬塞破坏主线；但作者需注意「高门槛条件 + 小池子」可能长期不触发，属预期。
- **依赖关闭后已存条件**：灰显提示，不静默失效。
- **回滚**：所有改动未提交，整体 `git checkout` 即可回退；Phase 间可独立验证。
