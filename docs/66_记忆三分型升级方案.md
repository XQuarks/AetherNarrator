# 66_记忆三分型升级方案（借鉴点 1 · WorldLines）

> 日期：2026-08-07
> 来源：docs/65_WorldLines竞品研究.md 借鉴点 1（soul 长期记忆分 emotional / important_events / learned_facts 三类）
> 状态：**✅ 已实施（黎总 2026-08-07 拍板），688 测试全绿（674 旧 + 14 新增）**
> 目标：升级 B6 记忆为三分型，让角色记忆不只"事实列表"，而分**情感记忆 / 重要事件 / 学到的知识**三类，叙事更有"人味"；旧档零迁移。

---

## 一、现状（探索结论）

现有 B6 记忆链路：

- **数据**：`S.activeBehaviorRecords`（数组，≤100 条），每条 `{id, text, importance(1-5), pinned, type, time, location, npcs[], embedding, embedDim, embedModel, createdAt}`；`type` 走 `MEMORY_TYPES = [event, relationship, item, discovery, other]`（store.js:110）。
- **写入**：`rag.js::addBehaviorRecords(facts)`——AI 回合返回 `key_facts`（llm.js 工具 schema 里是 `string`，parseResponse 兜底成数组，元素可为 string/object）；fallback `summarizeFactsFromChanges`。
- **注入**：`prompt.js::buildTurnUserMessage`——"# 已发生的关键事件（务必记住）"单列表，`ragFacts(检索命中) + getRecentKeyFacts(5)` 去重取 6 条，无分类。
- **检索**：`rag.js::retrieveBehaviorRecords`——向量语义 + 关键词，importance 加权，pinned+2。
- **UI**：`render.js` 记忆面板（renderStatusPanel "memory"）单列表，type 徽标 + ★ 星标。
- **记忆包**：`memory-transfer.js`（导出/导入），sanitize 白名单不含 bucket 类字段。
- **存档**：`save.js` 直接 deepClone `behavior_records`，无字段清洗 → **新增字段天然兼容旧档**；旧档缺新字段运行时兜底即可，无需迁移。

**痛点**：AI 产出的记忆混在一起——"玩家获得符文钥匙"（事实）和"女巫背叛让玩家心碎"（情感）和"第一夜钟楼巨响"（事件）在同一列表里，注入叙事时没有类型区分，AI 难以按"情感连续性/事件因果/事实锚点"分别取用。

---

## 二、方案：给每条记忆加 `bucket` 分型字段

借鉴 WorldLines `long-term-memo/` 三文件分型，引入**新的分型维度 `bucket`**（与现有 `type` 并存，`type` 语义不变）：

| bucket | 中文标签 | 语义 | 示例 |
|---|---|---|---|
| `emotional` | 情感记忆 | 玩家/角色对某人某事的情绪印记，带 `target`（对象）+ `intensity`（0~1） | "林晚照说出身世时，玩家感到被信任（intensity 0.8，target 林晚照）" |
| `important_event` | 重要事件 | 剧情里程碑/转折 | "世界时限『血月之夜』已到""目标『找回遗物』失败" |
| `learned_fact` | 学到的知识 | 客观事实/知识/设定锚点 | "玩家获得符文钥匙""雾港的电力靠潮汐电塔" |

**兜底规则 `inferBucket`（纯函数，旧数据/无标注时用）**：
1. 显式 `fact.bucket` ∈ 白名单 → 用之；
2. `type === "event"` → `important_event`；
3. `importance >= 4` → `important_event`；
4. 否则 → `learned_fact`。

→ `emotional` 只能显式标注（AI 判断"值得记住的情绪"时才产），避免误判泛滥。

**不变项**：记录字段全部保留（text/importance/pinned/type/time/location/npcs/embedding…）；容量 100 不变；检索逻辑不变（bucket 不参与打分，只参与展示与注入分组）。

## 三、改动面（6 个文件 + 测试）

### 1. `src/store.js` — 新增常量

```js
export const MEMORY_BUCKETS = ["emotional", "important_event", "learned_fact"];
export const MEMORY_BUCKET_LABELS = {
    emotional: "情感记忆", important_event: "重要事件", learned_fact: "学到的知识"
};
```

### 2. `src/rag.js` — 写入分型

- 新增导出纯函数 `inferBucket(fact, imp)`（按上表规则）；
- `addBehaviorRecords`：每条记录加 `bucket`（显式合法 → 用之；否则 inferBucket）；emotional 记录额外保留 `target`（string 截断 80）与 `intensity`（0~1 钳制）。

### 3. `src/llm.js` — 让 AI 学会标注

`TOOLS.apply_turn_state.parameters.key_facts` 由 `{ type: "string" }` 改为：

```js
key_facts: {
    type: "array",
    description: "本回合值得记住的关键事实（0~3 条）。每条：text 为事实文本；bucket 分类——emotional 情感印记(对某人某事的感觉)、important_event 重要事件/转折、learned_fact 学到的事实与知识(默认)；importance 1~5。",
    items: { type: "object", additionalProperties: true,
        properties: { text: { type: "string" }, bucket: { type: "string", enum: ["emotional","important_event","learned_fact"] }, importance: { type: "number" } } }
}
```

兼容：parseResponse 已把 key_facts 兜底为数组；字符串元素仍可进（inferBucket 兜底）。

### 4. `src/prompt.js` — 注入三分段

`buildTurnUserMessage` 记忆段重构：检索命中的 behavior_ + 各 bucket 最近记录，**按 bucket 分组**输出三段（每段 ≤3 条，总 ≤9，量级与现 6 条相当）：

```
# 角色的记忆（务必保持一致性）

【情感记忆】1. … 2. …
【重要事件】1. … 2. …
【学到的知识】1. … 2. …
```

- `getRecentKeyFacts(count)` 保留（兼容）；新增内部辅助按 bucket 分组取最近。
- 无内容的分段不输出。

### 5. `src/render.js` — 记忆面板分组

`renderStatusPanel("memory")`：先按 bucket 分三小节（每节标题带计数，如"情感记忆 · 2"），节内保持 pinned + importance 排序；卡片保留 type 徽标与星标；顶部统计 `共 N/100`。空列表文案不变。

### 6. `src/memory-transfer.js` — 记忆包兼容

`sanitizeMemory` 增加 `bucket`（白名单校验，缺省 infer）；`merge` 时 bucket 随条保留（同文本合并时不降级：existing 无 bucket 才用 incoming 的）。

### 7. 测试 `test/66-memory-buckets.test.js`

- inferBucket：显式/type=event/importance≥4/默认/非法值；
- addBehaviorRecords：bucket 落槽、emotional 的 target/intensity 保留与钳制、字符串元素兜底、去重不破；
- prompt 注入：三分段出现、空段不输出、总量上限；
- memory-transfer：sanitize 保留 bucket、导入合并 bucket 不丢；
- 回归：现有 674 测试全绿（type/importance 断言不受影响）。
