# B3 背包 / 物品方案（分类 + 关键物品标签 + 影响选项生成）

> 衔接文档：docs/28（里程碑 B3：背包/物品，优先级 ★★★★☆）、docs/31（B2 玩家变量，已落地，本方案沿用其"可选默认 / AI 优先 / 复用 state_changes"原则）、docs/05（文字描述优先）。
> 路线图原文：*背包/物品：分类 + 关键物品标签；物品成为叙事道具，可反复进选项；关键物品进手记时间线。* `S.gameState.inventory`；选项生成时优先给「使用 X」。

---

## 1. 背景与动机

竞品把"背包"做成叙事道具系统：物品有分类（武器/线索/货币），关键物品高亮并进入手记时间线，且玩家能反复"使用 X"推动剧情。

AetherNarrator 当前的背包其实**已经能跑**（详见第 2 节），但缺三件事：
- 物品没有**分类**与**关键标记**，状态面板里所有东西平铺、无法区分轻重；
- 关键物品不会**高亮**、也不会在**手记**里被强调；
- AI 虽然每轮都能"看见"背包（已在 `buildCompactGameState` 注入），但**没有指令**让它针对可用物品主动给出"使用 X"选项，物品更多是"背景摆设"而非"可反复触发的剧情开关"。

B3 要补的就是这三件事，并把"初始物品"开放给创作者在编辑器里配置（分类 + 关键标记），与 B2 变量编辑体验一致。

## 3. 数据模型

### 3.1 运行时物品（`S.gameState.inventory[]` 元素）
在现有 `{ item_id, name, count, world, tags }` 基础上新增两字段：
```js
{
  item_id: "notebook",      // 稳定 id（同 id 合并数量）
  name: "调查笔记",          // 展示名
  count: 1,                 // 数量
  world: null,              // 所属界（multiverse 用，clear_world 时按此过滤）
  category: "线索",          // ★ 新增：分类（见 3.3 枚举）
  is_key: false,            // ★ 新增：关键物品（高亮 + 手记强调）
  tags: ["has_firearm"]      // 已有：持有期激活的解锁标签
}
```

### 3.2 创作者定义的初始物品（`world.initial_state.inventory[]`）
与运行时同形状，由编辑器配置；**默认 `[]`（不强制任何初始物品，沿用 B2 可选默认原则）**。
> 设计取舍：B3 不做独立的"世界物品图鉴/目录"。物品主要是 AI 在剧情中动态授予的（符合本项目的 AI 优先叙事），创作者只配置"开局带什么"。若未来需要图鉴，可作为独立增强，不在本次范围。

### 3.3 `category` 枚举（固定下拉，简单可控）
`["武器","装备","消耗品","线索","书籍","货币","其他"]`
- `is_key` 是**独立布尔**，与分类解耦：例如"神秘钥匙"可标 `category:线索, is_key:true`；"左轮手枪"可标 `category:武器, is_key:false`（或 true，看叙事权重）。

## 4. 运行时数据流

```
创作者保存初始物品 (world.initial_state.inventory)
        │  startGame: S.gameState = normalizeSimulationState(deepClone(world.initial_state))
        ▼
S.gameState.inventory（开局即含分类/关键标记）
        │  每轮 buildCompactGameState → 注入用户消息（AI 可见背包）
        ▼
AI 返回 state_changes.inventory = [{op:"add", item_id, name, count, category, is_key, tags}, ...]
        │  applyStateChanges（game.js）
        │   - add：found 则合并数量并保留原 category/is_key；否则 push 含 category/is_key 的新条目
        │   - remove：扣减，归零移除
        │   - 关键物品获得 → addBehaviorRecords（importance 高 + type:"item"）
        ▼
S.gameState.inventory 更新 → 状态面板「物品」页签渲染（分类 + 关键高亮）
                           → 本回合变化面板（获得/失去 + [关键]）
                           → 手记（关键物品强调）
                           → AI 下轮可见（闭环，物品持续作为剧情道具）
```

**旧档兼容**：`simulation.js normalizeSimulationState` 对缺 `category`/`is_key` 的旧物品回填 `category:""`、`is_key:false`，绝不破坏老存档。

## 5. AI 契约

### 5.1 `state_changes.inventory` 元素（扩展）
在现有 `op/item_id/name/count/world/tags` 基础上，AI 授予物品时**鼓励**同时返回 `category` 与 `is_key`：
```json
{ "op": "add", "item_id": "key_rune", "name": "符文钥匙", "count": 1,
  "category": "线索", "is_key": true, "tags": [] }
```
- `category`/`is_key` 缺失时由 `applyStateChanges` 兜底为 `""`/`false`，不强制 AI 每次都给。
- 删除/合并逻辑不变。

### 5.2 选项生成指令（B3 核心能力）
在 `buildSystemPrompt` 静态段追加一条**轻量、世界无关**的规则（常驻、不破前缀缓存）：
```
【物品与选项】玩家背包已有物品，是可直接使用的叙事道具。
若背包中存在可用物品（尤其标记为关键、武器、消耗品者），你应在给出的选项中优先包含
「使用 X」「检查 X」「交给 X」等围绕该物品的动作，让物品能反复触发剧情，而非仅作背景。
仅当剧情确实不适合使用时，才可不列。
```
> 说明：选项与叙事同一次 LLM 调用返回（`resp.choices`），背包已在每轮动态状态里可见，故只需在 system 静态段加这句"行为指令"即可，无需额外调用。

## 6. 展示层

### 6.1 状态面板「物品」页签（render.js ~842）
- 每件物品展示：名称 + 数量 + **分类标签**（小灰标，如 `武器`）。
- `is_key:true` 的物品：**金色边框 + ★ 前缀**高亮，置顶排列（关键物品一眼可见）。
- 空背包仍显示"背包空空如也"。

### 6.2 本回合变化面板（prompt.js formatStateChanges ~566）
- 获得/失去文案附加标记：`获得 [关键] 符文钥匙`、`失去 干粮`。
- 非关键物品保持原样，零噪音。

### 6.3 手记（game.js + rag.js）
- 关键物品**获得**时，除常规事实外，额外 `addBehaviorRecords([{ text:"获得关键物品：X（可能影响后续剧情）", importance:6, type:"item" }])`，让关键物品在手记/时间线里被强调。
- 普通物品维持现有自动手记（"玩家获得了 X xN"），不变。

### 6.4 正文高亮（render.js highlightItems，已有）
- 维持现有物品名高亮；`is_key` 物品可在高亮上加金色样式（轻量增强，可选）。

## 7. 编辑器（世界详情「物品」页签 + 弹窗）

镜像 B2 变量编辑器体验：
- **世界详情**：加「物品」详情页签，列出该世界初始物品卡片（名称/数量/分类/关键标记 + 编辑/删除按钮）。
- **弹窗 `itemEditorModal`**（index.html，镜像 `variableEditorModal`）：字段
  - `item_id`（稳定 id，唯一）、`name`（展示名）
  - `count`（数量，默认 1）
  - `category`（下拉枚举，默认 其他）
  - `is_key`（复选框，默认关）
  - `tags`（可选，逗号分隔的解锁标签，如 `has_firearm`）
- **函数**：`lore-ui.js` 新增 `openItemEditor / syncItemForm / renderItemEditorBody / addItem / deleteItem / saveItemReview`（校验唯一 id、清理类型），保存时 `saveWorlds()`（初始物品改的是 `world.initial_state.inventory`，**不影响运行中的 `S.gameState`**，符合"编辑世界定义≠改动当前存档"）。
- **接线**：`app.js` ACTIONS 增加 `openItemEditor / addItem / deleteItem / saveItemReview`。

> 与 B2 差异：变量是世界级"定义"（schema），物品是世界级"初始实例"（initial_state.inventory）。变量有运行时值表，物品本就是实例集合，故编辑器直接编辑初始实例，概念更直接。

## 8. 预设适配（new-worlds.js）

为现有预设的初始物品补 `category`/`is_key`（**只补元数据，不新增任何强制物品**）：
- 克苏鲁：调查笔记→线索；左轮手枪→武器（可 `is_key:false`，保留 `has_firearm` tag）；柯达相机→装备；安吉尔教授的笔记盒→线索/`is_key:true`；旅费→货币。
- 后室/都市怪谈/双界：按各自初始物品语义补分类即可（其余保持 `[]` 的不动）。
