## 3. 推荐架构（玩家配置 = 权威源）

**核心原则**：玩家在向导里配的时间系统，就是世界最终的时间系统。AI 不重新设计一套，只基于它写剧情。

改造步骤：
1. **创建向导时间模块**提供完整编辑器（与详情页功能对齐，但精简为"创建期"形态）。
2. 玩家配置收集为 `wizardTimeConfig`，统一用 `store.js::normalizeTimeConfig()` 归一化（字段形状与详情页一致）。
3. 生成时（★ 实施采用 `worldPrefix` 通道，不改 `llm`/`prompt` 签名以降低回归）：
   - `game.js::generateWorld` 收集 `getWizardTimeConfig()`，经 `buildTimeConfigPrompt()` 序列化为**结构化硬约束文本**，拼入 `worldPrefix`（沿用既有「世界观生成前缀」通道，与原来 `timeHint` 同一注入点）。
   - 文本明确告诉 AI：「时间体系已固定为如下配置，请勿重新设计，请基于此推进剧情节奏」。
   - 生成后：**仅用 `wizardTimeConfig` 覆盖 AI 返回的 `schema.time_config` 子对象**（AI 设计的时间部分丢弃，玩家配置优先；**不碰** `schema` 其它字段如 genre/tropes，也不碰 `world.initial_state`，避免误伤 AI 生成的其它内容）。
4. 详情页编辑器保持不变（作为生成后的微调入口）。

## 5. 已确认决策点（2026-08-04 用户拍板）

- **A. 范围**：✅ 一次性全做（12 项全前置），分 4 阶段交付。
- **B. AI 与玩家配置关系**：✅ 玩家配置是权威。AI 不重新设计时间体系，只基于玩家配置写剧情；生成后 `wizardTimeConfig` **仅覆盖** `schema.time_config` 子对象（不动其它 schema 字段）。

## 7. 默认值与校验规则

- time 模块未开（61 门禁）→ `getWizardTimeConfig()` 返回 `normalizeTimeConfig(null)`（即 `none` 默认），不注入时间提示。
- 选 `custom_calendar` 但 `months` 为空 / 无 `label` → **warning**（不阻断），生成时 `normalizeTimeConfig` 回落默认。
- 选 `multiverse` 但 `timelines` 为空 → **error 拦截**（至少一条线）。
- 起始日期 `calendar_start`：`month` 1–12、`date` 1–31（按历法夹紧），沿用 `lore-ui.js::validateStartDate`。
- `clock_mode`：仅 `period` / `none`（无 12h/24h）。
- `temperature_preset`：0–1 钳制，缺省 0.5。
- `default_timetravel_strategy`：keep / reset / branch，缺省 keep。
- 时间相关的 error 并入 docs/61 的 `computeWizardValidation` → 向导底部校验面板（红色 error 拦截生成，黄色 warning 放行）。

## 14. 实现要点与简化说明（实施复盘）

- **未改 `llm`/`prompt` 签名**：原计划拟新增 `timeConfig` 参数，实施时改为沿用 `worldPrefix` 通道注入 `buildTimeConfigPrompt` 结构化文本——功能等价且零回归（`mockGenerateWorld` 的 schema 本不含 `time_config`，更凸显玩家覆盖必要）。
- **独立命名空间（关键）**：详情页时间编辑器强耦合 `S.currentWorld` + 全局 `data-action` 委托，直接复用会污染当前世界。向导编辑器用 `wz_` 前缀 id + `data-wtime` 独立委托（参照 `wizard-containers.js` 隔离先例），状态存本地缓冲 `WT`，**绝不写 `S.currentWorld`**。
- **多线共享顶层自定义历法**：多时间线里某线选 `custom_calendar` 时，复用顶层 `WT.custom_calendar`（线级 `custom_calendar` 由切换时复制），不重复编辑，简化实现且归一化正确。
- **温度不重复**：温度已由创建向导既有 `#worldTemp`（→ `world.temperature_preset`）覆盖，时间编辑器不再包含温度字段。
- **门禁联动**：`refreshTimeGate`（docs/61）在 time 模块开关变化时同步 `renderWizardTimeEditor()`，确保开启模块后编辑器即时出现。
