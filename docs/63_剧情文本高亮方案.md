# docs/63 · 剧情文本高亮方案（A+B+C，设置面板统一管理）

> 状态：✅ 已落地（2026-08-06）
> 范围：渲染层 + 设置面板 + 生成提示词，**不改存档结构**，旧档/历史回合即时生效。

## 一、目标

剧情文本中出现以下内容时自动增强显示：

| 类型 | 视觉 | 方案 | 开关 |
|---|---|---|---|
| 人物名字 | 加粗 + 主题色 | A 本地词典（B1 人物卡） | 人物名字高亮 |
| 背包物品 | 主题色浅底胶囊（已有） | A 本地词典（inventory，已有实现） | 背包物品高亮 |
| 人物对白 | 斜体 + 主题色（引号内容） | C 引号识别 | 人物对白高亮 |
| 重要文本 | **加粗** / ==高亮== 浅底 | B AI 标记（进阶） | AI 重点标记 |

四个开关全部放在**选项页（设置面板）**新增「高 亮」分区，localStorage 持久化（键 `aigame_hl_*`），默认全部开启。

## 二、实现要点

### 1. 渲染管道（src/render.js）

`renderNarrative` 现在是：按空行拆段 → 逐段 `<p>` 包裹。新管道（**先无条件转义，再叠加高亮**，保持安全不变量）：

```
escapeHtml(b)                    ← 安全基座（无条件，防 XSS）
→ highlightTerms(物品名)         ← A：item-highlight（开关）
→ highlightTerms(角色名)         ← A：name-highlight（开关；≥2 字才参与）
→ dialogueOnEscaped(引号)        ← C：dialogue-highlight（开关）
→ aiMarksOnEscaped(**/==)        ← B：ai-emphasis / ai-mark（开关）
→ highlightBanned(违禁词)        ← IP#6 标黄（既有，保持最后叠加）
→ \n → <br>，包 <p>
```

### 2. 防嵌套设计（highlightTerms）

- 多词**交替正则 + 单次 replace**（长词优先），同一词表内天然不嵌套（替代旧 highlightItems 的循环 replace 嵌套 bug）。
- 按 `<...>` 标签切分，跟踪 span 深度，**已包裹在 span 内的文本不再参与后续词表匹配** → 跨词表也不嵌套（物品名与角色名相同也不会叠两层）。

### 3. AI 标记约定（src/prompt.js，方案 B 唯一动 AI 的地方）

`buildSystemPrompt()` 末尾注入（仅当 `S.highlightAiMarks !== false`）：

- 关键人名/物品/线索可用 `**加粗**`；极重要悬念用 `==高亮==`；对白用 “…” 或 「…」。
- 克制：每段 1~3 处；仅限叙事文本内使用。
- 运行时注入 → **新世界旧世界都生效**；关闭开关则不注入，AI 无感。

### 4. 设置面板（index.html · 选项页「高 亮」分区）

4 行 switch（`hlNames` / `hlItems` / `hlDialogue` / `hlAiMarks`），data-action 委托，持久化同 `aigame_lore_confirm` 模式（store.js `_lsGet` 默认 true + theme.js toggle + localStorage.setItem）。

## 三、影响范围

| 项 | 结论 |
|---|---|
| 存档/历史 | ✅ 零迁移。conversationHistory 存纯文本，渲染时现算，改完旧回合立即带高亮 |
| 安全 | ✅ 管道先无条件 escapeHtml，所有高亮在其上做白名单 span/strong 替换；AI 标记只解析 `**`/`==`，解析产物仍是转义文本，无注入面 |
| 打字机 | ✅ 不变——打字中 textContent 纯文本，打完后一次性 renderNarrative |
| 性能 | ✅ 每段一次多词正则替换，词表几十项量级，可忽略 |
| AI 稳定性 | 仅 B 开关开启时 prompt 多一段约定；AI 偶尔漏标/滥用，开关可关 |
| 误伤 | 角色名单字（<2 字）不参与匹配；引号识别对强调引号可能误判（样式克制，可接受） |
| 旧功能 | highlightItems 重构内部用 highlightTerms，对外行为与测试兼容；highlightBanned 保持原样 |
