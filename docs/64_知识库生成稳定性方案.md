# 64_知识库生成稳定性方案

> 日期：2026-08-06
> 状态：**✅ 已实施（A+B+C 全范围，黎总 2026-08-06 拍板）**，674 测试全绿

## 问题

真实 API 走查（3 轮 13 次生成）发现：**生成世界的知识库（`world.lore_kb.snippets`）数量极不稳定**，个别世界知识库 0 条，导致：
- 游戏内知识库 tab 显示「暂无分类数据」
- RAG 检索无命中 → AI 回合回复失去世界观锚点（凭 AI 自身记忆/常识瞎编，偏离设定）
- 玩家游玩时无关键词高亮、无知识库跳转等增强体验

### 数据（3 轮真实生成）

| 轮次 | lore_snippets | 备注 |
|---|---|---|
| 第 1 轮 | 16 条 | 正常 |
| 第 2 轮 | 12 条 | 正常 |
| 第 3 轮 | **0 条** ❌ | world.lore_kb 存在但 snippets 空数组 |

## 根因分析

1. **Prompt 约束不够硬**（`prompt.js:65-68`）：当前约束是"至少生成 N 条"（小书 8 / 大书 12），AI 遇到长描述/复杂 schema 输出压力时会**牺牲 lore 数组保 schema/initial_state**。措辞为"建议"，未强调必须产出。
2. **JSON 输出截断风险**：完整 schema+initial_state+lore_kb+system_prompt+opening_narrative+initial_choices 一次输出，token 压力大；AI 倾向于先输出结构化字段，最后 lore 数组被截断或偷空。
3. **Sanitize 无兜底**：`utils.js::sanitizeWorldConfig` 对 lore_kb 仅做白名单清洗与字段截断，**0 条直接通过**。
4. **缺可观测 + 缺补救**：生成完成无 lore 数量校验，无 UI 提示，用户/创作者无感。

## 方案（分范围，按黎总选择执行）

### 范围 A：Prompt 强化（最小改动，预计 0.5h）

`src/prompt.js::buildWorldGenerationPrompt` 改造 `lengthLimitSection`（line 65-68）：

- 把"至少生成 N 条"改成 **"必须生成 8~15 条 lore_snippets"** 硬区间（不再是 ≥）
- 新增"每条 lore 必须含字段"清单：`id / title / category / content(100-300字) / activation_keys`
- 新增"分类覆盖"硬要求：**至少覆盖 `地点/人物/事件/物品` 四类**（缺少视作生成失败风险点）
- 新增"分类平衡"建议：四类各 2~4 条，剩余按 IP 倾向在 `势力/冲突/规则` 中选 1~2 类
- 在 prompt 末尾追加"输出自检清单"：让 AI 产出 `_meta: { lore_count, categories, has_name, has_opening }`，前端可读用于调试/告警

**优点**：零额外 API 调用，零前端改动
**风险**：可能仍被 AI 偷空（概率降低但不归零）

### 范围 B：Sanitize 兜底 + 自动补抽（中等，预计 2h）

新增 `src/lore-bootstrap.js`：

```js
// 当 sanitize 后 lore 不足 loreCountMin 时触发；复用 llm.js 的 lore 抽取能力
export async function backfillLoreIfShort(world, minCount) {
    if (world.lore_kb?.snippets?.length >= minCount) return world;
    // 基于 desc + ipName + system_prompt 单独调一次 lore 抽取
    const extra = await extractLoreFromDescription(world);
    world.lore_kb = mergeLore(world.lore_kb || { ip: world.name, snippets: [] }, extra);
    return world;
}
```

集成点：`src/game.js::generateWorld` 在 `world = {...}` 构建后、写盘前调用一次。

**优点**：保证 lore 数量下限，AI 偷空也能补救
**代价**：每个 lore 不足的世界额外 1 次 LLM 调用（约 1~3 秒 + token）

### 范围 C：UI 兜底提示（最小，预计 0.5h）

`src/render.js::renderWorldList` 或 `showWorldDetail` 的「知识库」tab：

- lore 为 0 时，世界列表卡片显示「⚠ 知识库为空」徽标
- 世界详情「知识库」tab 显示醒目空状态 CTA：「点击编辑知识库补充 →」
- 世界详情「概览」顶部的 `completion-card`（已有 A3）增加"知识库 ≥5 条"校验位（红色未达标）

**优点**：让创作者/玩家立刻感知问题，可手动补
**风险**：无（纯提示）

## 推荐组合

**A + C**（推荐）：既加强生成，又对极少数失败给出可见提示；成本最低（≈1h），零额外 LLM 调用。

**A + B + C**（最稳）：加补抽兜底，彻底消灭 0 条世界；代价是每世界可能多 1 次 API。
