# 世界观 · 知识库 · 提示词手册

> 本手册是 AetherNarrator「**世界观生成 / 知识库 / RAG 检索 / System Prompt / 状态数值 / 行为记忆 / 文风一致性**」的唯一年威参考，整合自：`01_世界观生成指南`、`02_知识库设计`、`03_System_Prompt工程`、`04_RAG方案`、`05_状态与数值设计`、`06_玩家行为记录与关键事实`、`24_剧情生成提示词优化与文风一致性`。原始方案已移入 `docs/_archive/世界观/` 留底。
>
> **适用读者**：创作文字游戏的作者。本手册讲清「世界怎么生成、知识怎么管、AI 怎么被约束、文风怎么贯穿」。

---

## 1. 世界观怎么生成（作者视角）

创建世界时你提供：名称、类型（`ip` 已有作品 / `original` 原创）、世界观描述、主角设定（可选）、文风选择、剧情自由度（1 严格遵循原著 → 5 完全自由）、源文件上传（EPUB/TXT/DOCX 可选，从原文提取设定）。

AI 据此产出世界 `schema`（属性模板、时段名、进度标签如「境界/年级」）、`initial_state`（玩家初始状态）、`lore_kb`（知识库）、`system_prompt`（AI 主指令）、`opening_narrative`（开场白）、`initial_choices`（初始选项）。

**关键规则**：`attributes` / `relationships` / `skills` 用**文字描述**而非数字（详见 §5）；`goals` 含阶段目标+最终目标，可设 deadline；NPC 要有初始态度、行事理由、**日常行程**（`npc_activity`）；死亡条件合理。

> 双世界穿梭（multiverse）是一种特殊**世界结构**（`time_config.mode:"multiverse"`，每界独立时间线），详见《时间系统完全手册》。

## 2. 知识库（lore_kb）设计

知识库是 RAG 检索核心，约束 AI 不编造、不跨界。每条 100–300 字，带 `keywords`（3–8 个）。

**分类体系**（冲突/事件为关键新增类）：

| category | 用途 | 最少条目 |
|---|---|---|
| 规则 | 世界硬规则 | 1 |
| 地点 | 场景设定 | 1 |
| 人物 | NPC 性格/态度/**日常行程** | 1 |
| 冲突 | 核心矛盾（必填） | 2 |
| 事件 | 可触发事件+触发条件 | 2 |
| 势力/物品/世界观 | 组织/道具/氛围 | 按需 |

**向量嵌入**：模型 `Xenova/bge-small-zh-v1.5`（512 维，中文语义，权重随项目内置 `models/`，无需联网）。拼接格式 `[category] title\ncontent`。构建期 `tools/compute-embeddings.mjs` 预计算；浏览器端 `src/embedding-worker.js`（Web Worker，本地权重，不走 CDN）。

**生命周期**：创建时 AI 自动生成约 12 条；每轮关键事实累积进 `activeBehaviorRecords`（≤100），**不自动写回**；仅高价值记忆经 B6 晋升为 lore（详见《叙事结构化容器手册》§6）。

## 3. RAG 检索（混合，触发式优先）

每次玩家输入触发，三路**并行**（`Promise.all`）：
1. **关键词检索**：`Intl.Segmenter` 中文分词，加权评分。
2. **向量语义检索**：bge-small-zh 余弦相似度，权重更高（2×）。
3. **行为记录检索**：从 `activeBehaviorRecords` 中文分词匹配关键事实（1.5×）。

融合排序后注入 user message。

> **当前默认世界（带触发元数据）走「触发式注入」**：每条片段带 `activation_keys` / `trigger_mode`(keyword/regex/always) / `scan_depth`，**仅命中才进候选**，再融合排序 + token 预算裁剪 + 递归触发。无触发元数据的**老存档降级为全量 Top 8 注入**。向量相似度阈值 ≥0.30 算命中。

**全量注入策略**：知识库总长 < 12000 字符时全量注入 system 静态段（命中缓存）；超阈值才用检索 Top 片段。

## 4. System Prompt 工程（控制 AI 叙事行为）

结构：固定前缀（角色设定/世界观硬约束/叙事风格/节奏/选项要求/NPC 自主/事件触发/数值约束/目标系统/世界属性/职责/输出格式/状态变更规则/禁止事项）+ 动态后缀（当前状态/相关片段/行为记录/玩家输入）。

**缓存优化**：system 硬化缓存，同世界永远返回相同字符串；聊天历史前 2 轮作稳定锚点 + 最近 2 轮灵活；动态内容全放 user 消息；不嵌时间戳/随机 ID。

**叙事节奏三模式**：展开（场景切换/重要 NPC/关键事件，2–3 段）→ 推进（日常，1–2 段）→ 加速（重复动作/时间跳跃，1 段概括）。

**选项设计五规则**：① 至少一带代价/风险 ② 至少一引导表达态度 ③ 至少一与场景/角色独特相关 ④ 禁空泛（"继续前进"）⑤ 暗示结果不剧透。

**事件触发复合条件**：时间 + 地点 + 数值阈值 + 前置事件。
**目标系统**：目标链 / 隐藏目标 / 失败分支（deadline 后标记 failed）。
**时间推进**：基于行动实际耗时，优先保持时间不变（详见《时间系统完全手册》）。
**剧情自由度**：1 严格遵循 → 5 完全自由，控制 NPC 自主程度。

## 5. 状态与数值（文字描述优先）

**五维属性**（文字描述，不整数）：胆识 courage / 洞察 perception / 专注 patience / 幸运 luck / 意志 will。只在**质变**时更新描述。

**关系系统**：NPC 关系用文字描述（`"林黛玉":"你们一见如故…"`），每轮完整注入 user message 维持一致性。

**NPC 活动状态** `npc_activity`：记录每位 NPC 当前位置/状态，AI 每轮更新，玩家进地点自然知道谁在。

**技能/物品/目标**：技能文字描述（按世界观自定义）；物品支持 add/remove；目标含可见/隐藏/链/失败分支。

**持久化**：世界/存档/状态/配置经 **IndexedDB**（`src/idb.js`+`storage.js`，异步大容量）持久化，每次 AI 响应后保存；仅主题/字号/温度等 UI 偏好用 localStorage。

> 注：结构化的数值类玩家变量另有 B2 容器（见《叙事结构化容器手册》§3），与本节「文字描述优先」互补、不冲突。

## 6. 玩家行为记录与关键事实（长对话不遗忘）

每轮 AI 输出 JSON 附 `key_facts` → 前端去重后累积进 `S.activeBehaviorRecords`（上限 **100 条**）。

> **演进（B6 记忆晋升）**：关键事实**不再每轮无条件注入最近 5 条**，而是持续留存供 RAG 行为记录检索按需召回；仅**高价值记忆**（`importance≥4` 或 `pinned`）由 AI 建议、玩家在确认台「应用」后晋升为 lore 固化（详见《叙事结构化容器手册》§6）。

**对话历史摘要**：`chatHistory` 只留最近 4 轮完整，每轮生成 1–2 句中文摘要（`chatSummary`，上限 20 条）省 token。

**后端无状态**：行为记录存 IndexedDB，读档完整恢复；ID 用 `crypto.randomUUID()`。

**全流程**：玩家输入 → 分词 + RAG 并行检索 → 触发门控(B1) → 融合排序 → 组装 user message（摘要+记忆+关系+lore+状态+输入）→ messages[system(缓存)+chatHistory(锚定)+user(动态)] → API → 解析 JSON → 应用状态变更 → 摘要 → 归档关键事实 → 保存。

## 7. 文风一致性（运行时硬约束，方案 24）

**根因**：玩家「文风选择」只在建世界时喂一次，运行时没强制约束，还被模板写死的 emoji/心形/语气词反向覆盖 → 风格漂移。

**修复（已落地的方向，代码层）**：
- **运行时注入 `{STYLE_GUIDE}`**：`buildSystemPrompt` 把 `world.styleRef` + `world.customStyle` 拼成「本世界强制文风」注进 system 静态段，每轮生效、最高优先级。
- **emoji/心形按文风开关**：模板第 33–73 行拆成按文风分支（轻松/恋爱类启用，史诗/硬核/克苏鲁/赛博朋克类禁用）。
- **基调对齐**：`buildToneGuide` 补恐怖/废土/冷峻/史诗类别；给了自定义文风则以自定义为准，不瞎猜。
- **中部纠偏位加文风提醒**：`buildAuthorNote` 追加「保持文风 X」；可加轻量文风一致性审稿。
- **文风→推荐温度映射**：创建世界自动预填温度（严谨史诗低温 0.3–0.5，自由诗意高温 0.8+）。

> 这套改动只动 `data/system_prompt_template.md` 与 `src/prompt.js` 少数函数，不碰引擎，全可逆。
